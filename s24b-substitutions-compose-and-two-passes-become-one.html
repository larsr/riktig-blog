Substitutions compose, and two passes over a term become one

Applying a substitution to a term walks the whole term. Applying two substitutions walks it twice — yet substitutions compose, so one walk with the composed substitution computes the same result. This post proves that fusion law twice over: once as a theorem about substitutions as functions, and once as a program, over a datatype of substitutions on which composition genuinely computes — including the cancellations, so that composing “shift everything up” with “put a term at position zero” costs nothing at all. Two ideas share the post because the second is stated over the first: a term representation in which scope errors are type errors, and an algebra of substitutions over it.

Terms that carry their scope

The setting, from Impl/Lambda/Scoped.v, is the lambda calculus in de Bruijn index style — variables are numbers counting binders outward, as in the de Bruijn post — but with the scope in the type: Exp n is the type of terms with at most n free variables, a dependent type indexed by the count.

Inductive Exp : nat -> Type :=
  | EVar : forall {n : nat}, Fin.t n -> Exp n
  | EApp : forall {n : nat}, Exp n -> Exp n -> Exp n
  | ELam : forall {n : nat}, Exp (S n) -> Exp n.

A variable is a Fin.t n — a number below n, so an out-of-scope index is unwritable — and a lambda’s body lives one scope higher. A substitution from scope m into scope n assigns a term to each of the m variables, and applying one is the structural walk, with up pushing the substitution under a binder:

Definition Sub (m n : nat) : Type := Fin.t m -> Exp n.
Fixpoint subst {m n : nat} (s : Sub m n) (e : Exp m) {struct e} : Exp n :=
  match e in Exp m0 return Sub m0 n -> Exp n with
  | EVar x => fun s0 => s0 x
  | EApp f a => fun s0 => EApp (subst s0 f) (subst s0 a)
  | ELam b => fun s0 => ELam (subst (up s0) b)
  end s.

Composition substitutes through the first substitution’s output:

Definition comp_sub {m n p : nat} (r : Sub m n) (s : Sub n p) : Sub m p :=
  fun x : Fin.t m => subst s (r x).

And the fusion law is the file’s closing theorem: substituting twice is substituting once with the composition,

e[r][s]=e[s∘r],e[r][s] \;=\; e[s \circ r],

Theorem subst_subst : forall (m n p : nat) (r : Sub m n) (s : Sub n p)
    (e : Exp m),
  subst s (subst r e) = subst (comp_sub r s) e.

by induction on the term; the only case with content is the binder, where the composition must be shown to commute with up, which is the file’s ladder of renaming/substitution interchange lemmas. Note the equality is Coq’s plain =: terms here are first-order data with decidable equality, so no setoid is needed.

A substitution language on which composition computes

comp_sub composes functions, so nothing about it simplifies: the composed substitution is a closure, and asking what it does at a variable re-runs both parts. The move that changes this is defunctionalization — replace the function space by a first-order datatype of the substitutions actually used, exactly the technique of the defunctionalization post, applied this time to the substitutions themselves. From Impl/Lambda/EnvAlgebra.v — the shape is the explicit substitution calculus, with scopes indexed:

Inductive DEnv : nat -> nat -> Type :=
  | DShift : forall (k n : nat), DEnv n (k + n)
  | DCons  : forall (m n : nat), Exp n -> DEnv m n -> DEnv (S m) n
  | DComp  : forall (m n p : nat), DEnv m n -> DEnv n p -> DEnv m p.

DShift k renumbers every variable up by k, DCons t r puts t at position zero and r everywhere above, DComp records a composition. denote reads a code back as a real substitution — DShift as the variable-shifting function, DCons as cons_sub, DComp as comp_sub:

Fixpoint denote {m n : nat} (e : DEnv m n) {struct e} : Sub m n :=
  match e in DEnv m0 n0 return Sub m0 n0 with
  | DShift k n0 => fun x => EVar (fin_add k x)
  | DCons t r => cons_sub t (denote r)
  | DComp r s => comp_sub (denote r) (denote s)
  end.

Now composition can be a program. dcomp pushes a composition into the structure instead of recording it:

Fixpoint dcomp {m n p : nat} (r : DEnv m n) (s : DEnv n p) {struct r}
    : DEnv m p :=
  match r in DEnv m0 n0 return DEnv n0 p -> DEnv m0 p with
  | DShift k n0 => fun s0 => shift_comp k s0
  | @DCons m0 n0 t r0 => fun s0 => DCons (subst (denote s0) t) (dcomp r0 s0)
  | @DComp m0 n0 p0 r1 r2 => fun s0 => dcomp r1 (dcomp r2 s0)
  end s.

The DCons case substitutes into the stored term and recurses; the DComp case reassociates. The content hides in shift_comp: composing DShift k with s consumes the first k entries of s — a shift followed by a cons cancels, entry by entry, the shift_cons law of the substitution calculus running as code. The result of dcomp carries no DComp node on its spine, so looking a variable up through it is a single pass.

Soundness says the program computes what the semantics says — denotation turns dcomp into comp_sub, pointwise on variables (sub_eq is pointwise equality):

Theorem dcomp_sound : forall (m n p : nat) (r : DEnv m n) (s : DEnv n p),
  sub_eq (denote (dcomp r s)) (comp_sub (denote r) (denote s)).

by induction on r, the shift case being the cancellation argument. And the two fusion laws snap together. On the blackboard: two passes are one pass with the function composition, by subst_subst; and the function composition is the computed code’s denotation, by soundness —

e[denoter][denotes]=e[denotes∘denoter]=e[denote(dcomprs)].e[\mathrm{denote}\,r][\mathrm{denote}\,s] \;=\; e[\mathrm{denote}\,s \circ \mathrm{denote}\,r] \;=\; e[\mathrm{denote}\,(\mathrm{dcomp}\,r\,s)].

In Coq, as a calc chain (the calc post explains the notation):

Theorem dfuse : forall (m n p : nat) (r : DEnv m n) (s : DEnv n p) (e : Exp m),
  subst (denote s) (subst (denote r) e) = subst (denote (dcomp r s)) e.
Proof.
  intros m n p r s e.
  calc (subst (denote s) (subst (denote r) e))
    == (subst (comp_sub (denote r) (denote s)) e)
         { (subst_subst m n p (denote r) (denote s) e) }
    == (subst (denote (dcomp r s)) e)
         { (subst_ext m p (comp_sub (denote r) (denote s)) (denote (dcomp r s))
              (fun x => eq_sym (dcomp_sound m n p r s x)) e) }.
Qed.

Two steps, one per fusion law, with subst_ext transporting the pointwise soundness fact under subst.

Running it

Everything is first-order, so vm_compute decides concrete cases. The cancellation happens: shifting into scope 2 and then composing with a substitution that conses a term back on reduces to the identity shift —

Example dcomp_cancellation :
  dcomp ex_env1 (dcomp ex_env2 ex_env3) = DShift 0 1.
Proof. vm_compute. reflexivity. Qed.

fusion holds on a concrete term,

Example dfuse_ex :
  subst (denote ex_s2) (subst (denote ex_r2) ex_e2)
  = subst (denote (dcomp ex_r2 ex_s2)) ex_e2.
Proof. vm_compute. reflexivity. Qed.

and the composed code itself normalizes to a DComp-free spine (dcomp_ex2_normal_form). The file ends with Print Assumptions on dcomp_sound and dfuse: both closed under the global context — the scope-index transports the DShift arithmetic needs are all destructed against universally quantified indices, so no equality axiom sneaks in.
