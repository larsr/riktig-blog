The untyped lambda calculus is an algebraic structure: fifteen laws, beta under guard

A group is a carrier with operations and equations, and every group fact is derived from the equations by calculation — no group proof ever inspects how a particular group’s elements are built. Proofs about programs are usually the opposite: induction over the syntax tree, case analysis on the evaluator, one bespoke lemma per construct. The question of this post: can the untyped lambda calculus be presented the way a group is — a carrier, operations, a fixed list of equations — so that program facts like “the Church conditional selects its branch” follow by chains of rewriting, with no induction over any syntax? It can, and the interesting part is what the equation list must contain, what it must not contain, and what happened when a smaller candidate list was measured against it.

The operations

Terms live in a carrier T; the equality == on T is conversion — programs are equal when reduction can identify them, the relation the program-equality post built for concrete terms. Variables are de Bruijn indices: var 0 is the nearest enclosing binder’s variable, var 1 the next one out, as in the de Bruijn post. The one design decision that shapes everything: substitutions get their own carrier Sb, with operations to build them, and applying a substitution is itself an operation t.[s]. From Structure/Lambda.v, one class per symbol:

Class HasVar T := var : nat -> T.
Class HasLam T := lam : T -> T.
Class HasApp T := app : BinOp T.
Class HasSub T S := substitute : T -> S -> T.
Class HasSubId S := sub_id : S.
Class HasSubShift S := sub_shift : S.
Class HasSubCons T S := sub_cons : T -> S -> S.
Class HasSubUp S := sub_up : S -> S.
Class HasVal T := val : Pred T.

Notation "t .[ s ]" := (substitute t s)
  (at level 2, s at level 200, left associativity, format "t .[ s ]").
Infix ".:" := sub_cons (at level 55, right associativity).

Five substitution builders: sub_id changes nothing; sub_shift (written ↑\uparrow below) renumbers every variable up by one; u .: s (written u⋅su \cdot s) sends variable 00 to uu and variable n+1n+1 wherever ss sends nn; and sub_up s (written ⇑s\Uparrow s) is ss pushed under one binder — variable 00 stays put, everything else does ss and then shifts past the new binder. val marks the values, the terms an argument must reduce to before a call-by-value function call consumes it.

The fifteen laws

  Class LambdaModel (T Sb : Type) {Te : EqRel T} {var : HasVar T}
      {lam : HasLam T} {app : HasApp T} {substitute : HasSub T Sb}
      {sub_id : HasSubId Sb} {sub_shift : HasSubShift Sb}
      {sub_cons : HasSubCons T Sb} {sub_up : HasSubUp Sb}
      {val : HasVal T} := {
    equivalence    :: Equivalence Te;
    lam_proper     :: Proper (equ ==> equ) lam;
    app_proper     :: Proper (equ ==> equ ==> equ) app;
    shift_respects : forall t t' : T, t == t' -> t.[sub_shift] == t'.[sub_shift];
    substitute_id  : forall t : T, t.[sub_id] == t;
    var_zero_cons  : forall (u : T) (s : Sb), (var O).[u .: s] == u;
    app_substitute : forall (f a : T) (s : Sb),
        (app f a).[s] == app (f.[s]) (a.[s]);
    lam_substitute : forall (b : T) (s : Sb), (lam b).[s] == lam (b.[sub_up s]);
    var_zero_up    : forall s : Sb, (var O).[sub_up s] == var O;
    var_succ_up    : forall (n : nat) (s : Sb),
        (var (S n)).[sub_up s] == ((var n).[s]).[sub_shift];
    var_shift      : forall n : nat, (var n).[sub_shift] == var (S n);
    shift_cons     : forall (t u : T) (s : Sb), (t.[sub_shift]).[u .: s] == t.[s];
    shift_up       : forall (t : T) (s : Sb),
        (t.[sub_shift]).[sub_up s] == (t.[s]).[sub_shift];
    beta           : forall b u : T, val u -> app (lam b) u == b.[u .: sub_id];
    val_lam        : forall b : T, val (lam b);
  }.

Three groups. The first three fields make == an equivalence and the term formers respect it, plus one congruence for substitution: conversion may be pushed below the single substitution sub_shift. The middle nine are the computation laws of substitution — how sub_id, u .: s, ⇑s\Uparrow s and ↑\uparrow act on variables and distribute over app and lam, and the two cancellations shift_cons (t[↑][u⋅s]=t[s]t[\uparrow][u \cdot s] = t[s]: shift, then substitute at 00, is a no-op on tt) and shift_up. The last two are the only laws that mention computation of programs: beta reduction,

(λb)u==b[u⋅id]when u is a value,(\lambda b)\,u \;==\; b[u \cdot \mathrm{id}] \qquad \text{when } u \text{ is a value},

and the fact that every abstraction is a value.

The guard on beta is not a stylistic choice. The intended carrier compares terms by call-by-value conversion, and there the unguarded law is false: with K=λλ.𝗏𝖺𝗋1K = \lambda\lambda.\,\mathsf{var}\,1 and Ω\Omega the standard non-terminating term, unguarded beta would prove KxΩ==xK\,x\,\Omega == x, but no call-by-value computation ever identifies them, because the argument Ω\Omega never becomes a value. An algebraic presentation of a programming language must build the evaluation strategy into its equations or prove things that are not true of it.

Why SKI lost

There is a famous smaller candidate. Combinatory logic presents computation with application and three constants SS, KK, II and their contraction laws — no binders, no substitution carrier, nothing but six operations and eight laws. The SKI post builds it and its translation from lambda terms. Before Structure/Lambda.v was committed to, both presentations were written out over an abstract carrier and measured on the same four benchmarks — the two Church-boolean selections and the two Church-pair projections — and the design note at the top of that file records the outcome.

The combinator presentation wins the booleans: one and two rewrite steps against six. Then it stops. Both presentations need the value guard (the same KxΩK\,x\,\Omega counterexample forces it), and the guard rejects every compound of combinators in argument position — which is exactly the shape bracket abstraction produces. The pairing term is such a compound, so the pair projections are simply not derivable from SS, KK, II under the guard: benchmark three costs a new primitive with its own law, benchmark four another, and the SS law goes entirely unused. Each further construct that is not already a primitive costs again. The substitution algebra pays fifteen laws once, and its marginal cost per further construct is zero. (The categorical route — a cartesian closed category with a reflexive object — was not measured separately: it is the substitution algebra’s operations in categorical clothing, plus retraction equations.)

A program fact, derived like a group fact

The Church encoding of the booleans, over any carrier with the term formers — from Structure/Lambda.v:

Definition church_true {T : Type} {var : HasVar T} {lam : HasLam T} : T :=
  lam (lam (var (S O))).

Definition church_false {T : Type} {var : HasVar T} {lam : HasLam T} : T :=
  lam (lam (var O)).

Definition church_if {T : Type} {app : HasApp T} (b g h : T) : T :=
  app (app b g) h.

𝖳𝖱𝖴𝖤=λλ.1\mathsf{TRUE} = \lambda\lambda.\,1 returns its first argument, 𝖥𝖠𝖫𝖲𝖤=λλ.0\mathsf{FALSE} = \lambda\lambda.\,0 its second, and the conditional is just application. The theorem: for values gg and hh, 𝖳𝖱𝖴𝖤gh==g\mathsf{TRUE}\,g\,h == g. On the blackboard, writing [][\,] for substitution:

𝖳𝖱𝖴𝖤gh=((λλ.1)g)h==(λ.1[⇑(g⋅id)])h==(λ.g[↑])h==g[↑][h⋅id]==g[id]==g,\mathsf{TRUE}\,g\,h \;=\; ((\lambda\lambda.1)\,g)\,h \;==\; (\lambda.\,1[\Uparrow(g \cdot \mathrm{id})])\,h \;==\; (\lambda.\,g[\uparrow])\,h \;==\; g[\uparrow][h \cdot \mathrm{id}] \;==\; g[\mathrm{id}] \;==\; g,

by: beta at the value gg together with the lam distribution law; the variable computation 1[⇑(g⋅s)]==g[↑]1[\Uparrow(g \cdot s)] == g[\uparrow]; beta at the value hh; the cancellation shift_cons; and substitute_id. In Theory/Lambda.v the middle cancellation is its own two-step lemma —

  Lemma substitute_cancel : forall t u : T, (t.[sub_shift]).[u .: sub_id] == t.
  Proof.
    intros t u.
    calc ((t.[sub_shift]).[u .: sub_id])
      == (t.[sub_id]) { shift_cons }
      == t            { substitute_id }.
  Qed.

— the first beta-and-distribute is the helper app_church_true, and the theorem is the remaining three blackboard steps, as a calc chain (the calc post explains the notation):

  Lemma app_church_true : forall g : T, val g ->
    app church_true g == lam (g.[sub_shift]).
  Proof.
    intros g Hg. unfold church_true.
    calc (app (lam (lam (var 1))) g)
      == ((lam (var 1)).[g .: sub_id] : T)
           { (beta _ _ Hg) }
      == (lam ((var 1).[sub_up (g .: sub_id)]) : T)
           { lam_substitute }
      == (lam (g.[sub_shift]))
           { (var_one_up_cons g sub_id) }.
  Qed.

  Theorem church_if_true : forall g h : T, val g -> val h ->
    church_if church_true g h == g.
  Proof.
    intros g h Hg Hh.
    calc (church_if church_true g h)
      == (app (lam (g.[sub_shift])) h)   { (app_church_true g Hg) }
      == ((g.[sub_shift]).[h .: sub_id]) { (beta _ _ Hh) }
      == g                               { substitute_cancel }.
  Qed.

Every step is one of the fifteen laws or a lemma already derived from them. No induction, no evaluator, no constructor of any datatype. The same file derives church_if_false, and the two Church-pair projections church_fst_pair and church_snd_pair — the benchmarks the combinator basis could not reach — from the same laws.

The instance, and what this is for

The laws earn their keep only if something real satisfies them. Lambda/Conv.v proves that the concrete de Bruijn terms tm of the evaluator post, with call-by-value conversion conv as ==, functions nat -> tm as the substitution carrier, and the evaluator’s value predicate as val, are a model:

Instance Tm_LambdaModel : LambdaModel tm tmsub.

The instance proof is where the presentation’s cost is paid, once: nine of the fifteen obligations are plain structural identities of the parallel-substitution function psub (several hold by reflexivity), and only three — beta, shift_respects, val_lam — touch conversion at all, with shift_respects needing only that conversion survives renaming, not full substitution. Every abstract theorem then specializes for free:

Example tm_church_if_true : forall g h : tm, value g -> value h ->
  church_if church_true g h == g.
Proof.
  intros g h Hg Hh. exact (church_if_true g h Hg Hh).
Qed.

This post is the point where two halves of this library meet. The tools built so far are for algebraic reasoning about mathematical structures; the aim they serve is to reason the same way about program code — what a program does, its specification, and how it behaves, its semantics. LambdaModel is a programming language’s semantics presented as an algebraic structure, and church_if_true is a specification fact proved from laws alone — the same calculation discipline, applied to a program.
