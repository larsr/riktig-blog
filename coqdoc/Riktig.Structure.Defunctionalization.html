Library Riktig.Structure.Defunctionalization

From Riktig.Structure Require Export CPSLambda.

Defunctionalization of the continuations of a CPS-translated program (Reynolds, "Definitional interpreters for higher-order programming languages", 1972; Danvy and Nielsen, "Defunctionalization at work", 2001). The continuations such a program builds are not arbitrary terms but a stack K of frames: halt is the empty stack, karg a k holds an argument a still to run, kfun f k a function value f already obtained. reify reads a stack back as a term, and each law says the read-back of one constructor behaves under application as the continuation it stands for -- one transition of the abstract machine, decoded (Gibbons, "Continuation-passing style, defunctionalization, accumulations, and associativity", 2022, arXiv:2111.10413). druns is a run of the first-order machine, sound for the CPS semantics and complete for evaluation (Wand, "Deriving target code as a representation of continuation semantics", 1982).
Module Defunctionalization.
  Class Defunctionalization (N T Sb K : Type) `{CPSLambda N T Sb}
      (is_value : Pred T)
      (halt : K) (karg : T → K → K) (kfun : T → K → K)
      (reify : K → T) (druns : T → K → T → Prop) := {
    
    value_lam : ∀ b : T, is_value (lam b);
    value_evaluates : ∀ v : T, is_value v → evaluates v v;
    
    reify_halt : ∀ t : T, app (reify halt) t == t;
    
    reify_karg : ∀ (f a : T) (k : K),
      app (cps (app f a)) (reify k) == app (cps f) (reify (karg a k));
    
    reify_kfun : ∀ (a f : T) (k : K), is_value f →
      app (reify (karg a k)) (psi f) == app (cps a) (reify (kfun f k));
    
    reify_call : ∀ (b v : T) (k : K), is_value v →
      app (reify (kfun (lam b) k)) (psi v) == app (cps (b.[v .: sub_id])) (reify k);
    
    druns_sound : ∀ (t v : T) (k : K), druns t k v → app (cps t) (reify k) == psi v;
    druns_complete : ∀ l v : T, evaluates l v → druns l halt v;
  }.
End Defunctionalization.
