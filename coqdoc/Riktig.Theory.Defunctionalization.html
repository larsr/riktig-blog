What holds in any defunctionalized CPS calculus, from the laws alone. The mechanical part of Reynolds' recipe -- translate to continuation-passing style, then represent the continuations first-order (Reynolds, "Definitional interpreters for higher-order programming languages", 1972) -- is packaged in the laws; what each derivation below adds is a short calculation whose every step is a single rewrite. This is the division Gibbons draws (arXiv:2111.10413): some steps of such developments are turn-the-handle, and the rest need one local insight -- an associativity, an evaluation -- which here is exactly one justified step of a calc chain, with no claim to a procedure that finds it.
Section DefunctionalizationTheory.
  Context {N T Sb K : Type} `{Defunctionalization N T Sb K}.

Running a program against the empty stack yields the value's translation: the interpreter and its defunctionalized Compiler.machine agree on answers (Reynolds 1972).
  Theorem defun_runs : ∀ l v : T,
    evaluates l v → app (cps l) (reify halt) == psi v.
  Proof.
    intros l v Hl.
    calc (app (cps l) (reify halt))
      == (app (reify halt) (psi v)) { (CPSLambda.cps_runs l v (reify halt) Hl) }
      == (psi v) { (Defunctionalization.reify_halt (psi v)) }.
  Qed.

Once the function part has run to a value the Compiler.machine turns to the argument: two decoded transitions in sequence (Danvy and Nielsen, "Defunctionalization at work", 2001).
  Theorem defun_app : ∀ (f fv a : T) (k : K),
    evaluates f fv → is_value fv →
    app (cps (app f a)) (reify k) == app (cps a) (reify (kfun fv k)).
  Proof.
    intros f fv a k Hf Hv.
    calc (app (cps (app f a)) (reify k))
      == (app (cps f) (reify (karg a k))) { (Defunctionalization.reify_karg f a k) }
      == (app (reify (karg a k)) (psi fv)) { (CPSLambda.cps_runs f fv (reify (karg a k)) Hf) }
      == (app (cps a) (reify (kfun fv k))) { (Defunctionalization.reify_kfun a fv k Hv) }.
  Qed.

The Compiler.machine's route through an application -- function, then argument, then the call -- decodes to the direct contraction: the stack the Compiler.machine keeps is a faithful representation of the continuation semantics (Wand, "Deriving target code as a representation of continuation semantics", 1982).
  Theorem defun_call : ∀ (f a b av : T) (k : K),
    evaluates f (lam b) → evaluates a av → is_value av →
    app (cps (app f a)) (reify k) == app (cps (b.[av .: sub_id])) (reify k).
  Proof.
    intros f a b av k Hf Ha Hv.
    calc (app (cps (app f a)) (reify k))
      == (app (cps a) (reify (kfun (lam b) k))) { (defun_app f (lam b) a k Hf (Defunctionalization.value_lam b)) }
      == (app (reify (kfun (lam b) k)) (psi av)) { (CPSLambda.cps_runs a av (reify (kfun (lam b) k)) Ha) }
      == (app (cps (b.[av .: sub_id])) (reify k)) { (Defunctionalization.reify_call b av k Hv) }.
  Qed.

The first-order Compiler.machine and the evaluator agree on answers, up to translation.
  Theorem druns_agree : ∀ l v w : T,
    druns l halt w → evaluates l v → psi w == psi v.
  Proof.
    intros l v w Hw Hv.
    calc (psi w)
      == (app (cps l) (reify halt)) { (Defunctionalization.druns_sound l w halt Hw) }
      == (psi v) { (defun_runs l v Hv) }.
  Qed.
