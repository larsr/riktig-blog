What holds of any compiler to a stack Compiler.machine, from the laws alone.
Reynolds' recipe -- translate to continuation-passing style, then represent the continuations first-order -- is mechanical, and carried out on an evaluator for this language it yields an abstract Compiler.machine, but not a compiler: the Compiler.machine still carries unevaluated source expressions on its stack. What turns the Compiler.machine into a compiler is one further step, and that step is an appeal to associativity. Wand made it as the associativity of a generalized composition, which rotates tree-shaped code until no composition has another on its left, leaving a linear instruction sequence ("Deriving target code as a representation of continuation semantics", 1982); Gibbons draws out that this is the part of the development no handle-turning supplies (arXiv:2111.10413, section 5).
Here that step is compile_rotate, a single rewrite by the associativity of the code monoid. The insight is not automated away -- there is no procedure that finds it, and for a source operator like subtraction none could, since subtraction is not associative. What the equational setting buys is that once the insight is named, the rest is calculation: the associativity used is that of code concatenation, and the source operator binop is never assumed to have any property at all.

  Context {V E C S : Type} `{Compiler V E C S}.

Running a concatenation runs one program after the other: the antiadditivity of exec, read at a stack.
  Lemma exec_cat : ∀ (c d : C) (s : S), exec (c + d) s == exec d (exec c s).
  Proof. intros c d s. exact (antiadditive[exec] c d s). Qed.

The rotation: the code of a node, bracketed as the tree is, is the code of a node bracketed as a linear sequence. This is the whole of the associativity in the development, and it is the associativity of concatenation, not of binop.
  Theorem compile_rotate : ∀ e f : E,
    compile (node e f) == (compile e + compile f) + op_instr.
  Proof.
    intros e f.
    calc (compile (node e f))
      == (compile e + (compile f + op_instr)) { (Compiler.compile_node e f) }
      == ((compile e + compile f) + op_instr) { (associative (compile e) (compile f) op_instr) }.
  Qed.

Running a compiled expression on any stack pushes its value: the stack below is never inspected, which is what carries the induction through (McCarthy and Painter, "Correctness of a compiler for arithmetic expressions", 1967).
  Theorem compile_correct : ∀ (e : E) (s : S),
    exec (compile e) s == push (evaluate e) s.
  Proof.
    intros e.
    apply (Tree.tree_induction (fun t : E ⇒ ∀ s : S, exec (compile t) s == push (evaluate t) s)).
    - intros t t' Ht. split; intros Hp s; [ rewrite <- Ht | rewrite Ht ]; apply Hp.
    - intros v s.
      calc (exec (compile (lit v)) s)
        == (exec (push_instr v) s) { (Compiler.compile_lit v) }
        == (push v s) { (StackMachine.exec_push v s) }
        == (push (evaluate (lit v)) s) { (Compiler.evaluate_lit v) }.
    - intros t u IHt IHu s.
      calc (exec (compile (node t u)) s)
        == (exec (compile t + (compile u + op_instr)) s) { (Compiler.compile_node t u) }
        == (exec (compile u + op_instr) (exec (compile t) s)) { (exec_cat (compile t) (compile u + op_instr) s) }
        == (exec (compile u + op_instr) (push (evaluate t) s)) { (IHt s) }
        == (exec op_instr (exec (compile u) (push (evaluate t) s))) { (exec_cat (compile u) op_instr (push (evaluate t) s)) }
        == (exec op_instr (push (evaluate u) (push (evaluate t) s))) { (IHu (push (evaluate t) s)) }
        == (push (binop (evaluate t) (evaluate u)) s) { (StackMachine.exec_op (evaluate t) (evaluate u) s) }
        == (push (evaluate (node t u)) s) { (Compiler.evaluate_node t u) }.
  Qed.

The compiler is therefore determined up to what the Compiler.machine does: two expressions with the same value compile to code with the same effect.
  Corollary compile_agrees : ∀ (e f : E) (s : S),
    evaluate e == evaluate f → exec (compile e) s == exec (compile f) s.
  Proof.
    intros e f s Hv.
    calc (exec (compile e) s)
      == (push (evaluate e) s) { (compile_correct e s) }
      == (push (evaluate f) s) { Hv }
      == (exec (compile f) s) { (compile_correct f s) }.
  Qed.
