From Riktig.Impl Require Export SignaturePoly CategoryFun.

EXCEPTION TO THE LAYER RULES -- deliberate, and meant to stay singular. A Structure file must not import from Impl; this file does, and is the only one that may.
Why it is justified here: the signature machinery is meta-programming. The derivation of shapes from signatures is written against the abstract Signature structure, in the ordinary way; this file merely EXECUTES that derivation, once, at the Coq implementation of signatures, so that every shape a datatype declares computes -- in any target category -- and case analysis on one level typechecks in the arrow programs. What the layer rules protect, the implementation-genericity of object-level programs, is untouched: a datatype declared through this file is still abstract in its carrier, its category, and every operation; only the finite SYNTAX describing its shape is fixed, and that syntax is what varies for no one.
Do not imitate this crossing. A new Impl import into Structure or Programs needs the same argument to hold: the imported thing must be meta-level, executed at declaration time, and invisible to what programs are generic over. Every datatype structure imports this file and never the implementation itself.
A signature over constant names in K, concretely.
Notation sig K := (poly K).

One level of the datatype a signature describes, in the category with objects O, the constants named through den.
Notation shape_of den q := (lobj (layer den q)).
