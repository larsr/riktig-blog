Vector spaces without coordinates

Everything so far had one carrier: a set combining with itself. A vector space has two. The vectors form an abelian group, the scalars form a field, and the field acts on the group — you can stretch a vector by a number. Nothing in that description mentions coordinates, arrows, or ℝ3\mathbb{R}^3, and nothing below will either.

Two carriers, and an action between them

Fix a field FF. A vector space over FF is an abelian group VV together with an operation F×V→VF \times V \to V, written a*:va *: v, satisfying

a*:(u+v)=a*:u+a*:v,(a+b)*:u=a*:u+b*:u,a *: (u + v) = a *: u + a *: v, \qquad (a + b) *: u = a *: u + b *: u,

(ab)*:u=a*:(b*:u),1*:u=u.(ab) *: u = a *: (b *: u), \qquad 1 *: u = u.

The first two are distributivity on each side, the third says scaling by a product is scaling twice, and the fourth pins the unit down — without it, the operation sending every vector to 00 would satisfy everything else.

The transcription splits into two pieces, and the split matters later:

  Class ScaleLaws (F V : Type) `{Field F}
      {Ve : EqRel V} {Va : HasAdd V} {Vs : HasScale F V} := {
    scale_proper          :: Proper (equ ==> equ ==> equ) Vs;
    is_left_distributive  :: LeftDistributive F V V Vs;
    is_right_distributive :: RightDistributive F V V Vs;
    is_associative        :: Associative F V Vs mult;
    is_left_identity      :: LeftIdentity F V Vs 1;
  }.
  Class VectorSpace (F V : Type) `{Field F}
      {Ve : EqRel V} {Vz : Zero V} {Va : HasAdd V} {Vn : HasNeg V}
      {Vs : HasScale F V} := {
    vectors :: AbGroup V;
    scaling :: ScaleLaws F V;
  }.

ScaleLaws holds the four laws about the action; VectorSpace is that together with the additive group. Every law is filled in from the same catalogue the earlier posts used, and two of them are worth looking at twice. Associative F V Vs mult is the mixed reading of the associativity entry — the one where the two operations differ and the carriers differ — giving (ab)*:u=a*:(b*:u)(ab) *: u = a *: (b *: u) rather than anything about a single operation. LeftIdentity F V Vs 1 reads the identity entry the same way, with the scalar 11 acting on a vector. No new law had to be written for either.

Why the two-part split rather than one class with six fields? Because some carriers have the scaling laws without being a vector space in their own right. A geometric algebra’s elements are one: they get their addition from the ring they already form, not from a separate group, and yet scalars act on them exactly as above. Keeping ScaleLaws separate lets that case reuse the laws — and the theorems below — without a second, competing additive structure on the same carrier.

Scaling and zero

The first facts are the ones that make signs behave: a*:0=0a *: 0 = 0, 0*:u=00 *: u = 0, (−a)*:u=−(a*:u)(-a) *: u = -(a *: u), a*:(−u)=−(a*:u)a *: (-u) = -(a *: u). None of them is an axiom, and none needs a new argument, because they are all instances of something the group post proved.

Fix a scalar aa and look at the map u↦a*:uu \mapsto a *: u. Left distributivity says exactly that this map sends sums to sums — it preserves addition. And a map between groups that preserves addition sends 00 to 00 and negatives to negatives, whatever else it is. So:

  Theorem scale_zero : forall a : F, a *: (0 : V) == 0.
  Proof.
    intros a.
    exact (additive_zero (scale a)).
  Qed.

The proof names the map and stops. Its additivity is registered as scale_l_additive, whose proof is left_distributive a — the distributive law is the additivity of scaling, once the scalar is fixed — and the licence to rewrite under it is scale_l_proper. Fixing the vector instead gives the map a↦a*:ua \mapsto a *: u, additive by the other distributive law, and that is zero_scale and neg_scale. Four theorems, no new reasoning.

Rearranging scalars

The remaining facts move scalars around, and each is a short chain. Scaling twice can be done in either order,

a*:(b*:u)=(ab)*:u=(ba)*:u=b*:(a*:u)a *: (b *: u) = (ab) *: u = (ba) *: u = b *: (a *: u)

  Theorem scale_swap : forall (a b : F) (u : V),
    a *: (b *: u) == b *: (a *: u).
  Proof.
    intros a b u.
    calc (a *: (b *: u))
      == ((a * b) *: u)  { (associative a b u) }
      == ((b * a) *: u)  { (commutative a b) }
      == (b *: (a *: u)) { (associative b a u) }.
  Qed.

which needs the field’s commutativity in the middle step and nothing else. And scaling by −1-1 is negation:

(−1)*:u=−(1*:u)=−u(-1) *: u = -(1 *: u) = -u

  Theorem neg1_scale : forall u : V, (- (1 : F)) *: u == - u.
  Proof.
    intros u.
    calc ((- (1 : F)) *: u)
      == (- (1 *: u)) { (neg_scale 1 u) }
      == (- u)        { (left_identity u) }.
  Qed.

That one is worth noticing because on the blackboard it is usually assumed rather than proved. Here it follows from the previous section’s neg_scale and the unit law, in two steps.

Where the instances come from

The definition mentions no coordinates, so the examples need not have any. Three constructions supply most of what the rest of the series uses, and each is proved once, generically:

  • A field over itself. Any field is a vector space over itself, with multiplication as the scaling. Interface/VectorSpace.v says so in four lines, of which the interesting one is Instance Field_Scale {F}{Field F} : HasScale F F := mult.`
  • Functions into a vector space. If V is a vector space then so is X -> V for any X, adding and scaling at each argument — Theory/Pointwise.v. This is the construction the Clifford algebras are built on later, where X is the set of blades.
  • Pairs. If A and B are vector spaces over the same field, so is A * B — Theory/ProdVS.v.

Each is stated for arbitrary carriers, so they compose: nat -> bool -> V is a vector space by applying the second twice, and Theory/Pointwise.v ends with exactly that as a check:

Example pw_vs_nested (F V : Type) `{HF : Field F} `{HV : VectorSpace F V} :
  VectorSpace F (nat -> bool -> V) := _.

The _ is the whole proof: instance search assembles it.
