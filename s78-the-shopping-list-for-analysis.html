The shopping list for analysis

Limits, derivatives and integrals all need vocabulary that pure algebra does not supply: a way to say one element is smaller than another, a size for an element, a size for a vector, coordinates to compute in, and a specification of what the real numbers are. This post assembles that list — order, absolute value, norms, bases, the real numbers as a specification — stating each as an interface with laws rather than a construction, and then spends the second half on one substantial theorem: complex numbers over any field where −1-1 is not a square field form a field.

The list, item by item

Order, and an absolute value stated by its laws (Structure/Order.v / Theory/Order.v). Analysis begins with “smaller than”: <= arrives as opt-in vocabulary, and OrderedField states a field whose order is reflexive, transitive, antisymmetric up to ==, total, respects +, and keeps products of nonnegatives nonnegative. The design choice worth pausing on is abs: defining |a||a| as “if a≥0a \ge 0 then aa else −a-a” needs to decide the order — something real-number programs cannot generally do — so abs is an operation with laws, not a construction. The headline three:

0≤|a|,|ab|=|a||b|,|a+b|≤|a|+|b|0 \le |a|, \qquad |ab| = |a|\,|b|, \qquad |a+b| \le |a| + |b|

(an abridged list — the interface states seven abs laws in all, the others being properness, abs a == 0 <-> a == 0, abs (- a) == abs a, and 0 <= a -> abs a == a). Proved from the laws alone, in Theory/Order.v: |1|=1|1| = 1, and from that a small gem — 0≤10 \le 1 is a theorem, because one is an absolute value and absolute values are nonnegative.

Norms: length, axiomatically (Structure/Norm.v / Theory/Norm.v). A norm is a ruler for a vector space: ‖u‖ in the ordered scalar field, with the four classical laws — nonnegative, definite, homogeneous (∥a⋅u∥=|a|∥u∥\|a \cdot u\| = |a|\,\|u\| — this is why we needed abs), and the triangle inequality. Proved: ∥0∥=0\|0\| = 0 and ∥−u∥=∥u∥\|-u\| = \|u\|, each a one-line rewrite chain. When limits arrive, “within ε\varepsilon of” will be measured by exactly this ‖·‖.

A basis is a coordinate isomorphism (Structure/Basis.v). The post on representations as isomorphisms sold that idea; a basis is the same idea wearing a math hat — a way of assigning coordinates: basis vectors Basis.vec : Fin.t n -> V plus a coordinate map Basis.coords, itself a LinearMap into Fin.t n -> F, with two round-trip laws,

∑i(coordsv)i⋅bi==vandcoords(∑ici⋅bi)==c.\textstyle\sum_i (\mathrm{coords}\,v)_i \cdot b_i == v \qquad\text{and}\qquad \mathrm{coords}\left(\textstyle\sum_i c_i \cdot b_i\right) == c.

Spanning and linear independence, packed into round trips — “V has a basis” literally is “V ≅ Fin n -> F”. Proved: the standard basis eie_i really is a basis of Fin n -> F, via the delta-collapse ∑ici⋅ei(j)==cj\sum_i c_i \cdot e_i(j) == c_j, by induction. (Infinite bases wait for the analysis track; ListVS from the post on representations as isomorphisms is the warm-up.)

The reals: a specification, not a construction (Structure/Reals.v). The stance that shapes everything downstream: we do not build ℝ out of Cauchy sequences or cuts. We state what any implementation must provide — ordered-field laws plus completeness: every nonempty, bounded-above predicate has a least upper bound. Programs get written against this interface and then refined to things a computer can hold: rationals for approximation, intervals guaranteed to contain the true value. Classical mechanics is written this way too: a Lagrangian L=T−VL = T - V and its equations of motion, stated against the real-number interface, so the same statements can later be run by refining ℝ to computable approximations with the proofs carried along. (Q famously fails completeness — the supremum of “squares to less than 2” is missing — which is exactly the gap the interface names. Nothing is proved here on purpose; a specification’s theorems belong to its implementations.)

The centerpiece: complex numbers, and the law that makes division work

Now the construction the list was leading to (Impl/Complex.v): a genuinely new field from an old one. The carrier is a record of two components, (a,b)(a, b) read as a+bia + bi; equality and addition are componentwise (the product pattern from the post on representations as isomorphisms, again), and multiplication is the Gaussian product, exactly as written in the file:

#[export] Instance C_Mult : HasMult (C F) :=
  fun z w => mkC (re z * re w + - (im z * im w))
                 (re z * im w + im z * re w).

The ring is routine, by design. Every ring law on C F reduces to two component equations over F, and each component equation is a polynomial identity — commutativity, associativity and distributivity rearranged, nothing more. Coq’s ring tactic decides exactly that class of goal, so each law is one line:

  #[export] Instance C_left_distributive : LeftDistributive (C F) (C F) (C F) mult.
  Proof. intros z w v. split; simpl; ring. Qed.

split turns the C F equation into its real and imaginary halves, simpl unfolds the component definitions, and ring closes both. Setting that up costs one declaration at the top of the section,

  Add Ring F_ring : (ring_theory_of_Ring (R := F) commutative).

which hands ring a proof that F’s own laws form a ring theory in the shape the tactic expects. Twelve laws, twelve one-line proofs. So far, any field F would do.

Division is where the construction must pay. The candidate inverse is z−1=z‾/(a2+b2)z^{-1} = \bar z / (a^2 + b^2):

#[export] Instance C_Inv : HasInv (C F) :=
  fun z => mkC (re z * inv (norm2 z)) (- im z * inv (norm2 z)).

and the field law inv z * z == 1 needs norm2 z =a2+b2= a^2 + b^2 to be invertible whenever z≠0z \neq 0. Over which fields is that true? Not all of them — over ℂ itself, 12+i2=01^2 + i^2 = 0 with neither summand zero. The exact assumption needed has a classical name (Structure/MinusOneNotASquare.v):

Module MinusOneNotASquare.
  Class MinusOneNotASquare (F : Type) `{Field F} :=
    two_squares_vanish : forall a b : F, a * a + b * b == 0 -> a == 0.
  Hint Mode MinusOneNotASquare ! - - - - - - - - : typeclass_instances.
End MinusOneNotASquare.
Export MinusOneNotASquare.

A sum of two squares vanishes only if each summand does (the symmetric half, two_squares_vanish_r, is derived in Theory/Field.v). The class states one summand; the other follows by symmetry, so norm2_nonzero can use both halves at once:

Lemma norm2_nonzero : forall z : C F, z =/= 0 -> norm2 z =/= 0.
Proof.
  intros z Hz Hn. apply Hz. split.
  - exact (two_squares_vanish (re z) (im z) Hn).
  - exact (two_squares_vanish_r (re z) (im z) Hn).
Qed.

Read it backwards: to show norm2 z is nonzero, assume it is zero (Hn) and derive that z itself is zero, contradicting Hz. Equality on C F is the conjunction of the two component equalities, so split asks for re z == 0 and im z == 0 separately, and formal reality delivers each. With that lemma, inv z * z == 1 goes through, and C_Field — the full field instance, every law and every Proper discharged by a component lemma over F — assembles.

Over any field F in which −1-1 is not a square, the complex numbers C F form a field.

Two design notes. First, the hypothesis is exactly the debt: not “F is ordered”, not “equality is decidable” — one implication about sums of squares, the single fact complex inversion needs. The imaginary unit exists because we paid for it with an axiom about the scalars; nothing is free, but everything is itemized. Second, the file deliberately does not prove MinusOneNotASquare Q: that fact belongs to the order machinery (a sum of squares is nonnegative, and zero only at zero), so it lives with Q’s order instance: Impl/Qof.v proves Q_MinusOneNotASquare, and Field (C Q) then assembles by instance resolution with no new proofs in Complex.v. The file ends with two resolution checks pinning both halves — the ring needs only Field F, the field needs (and only needs) MinusOneNotASquare F:

Example c_ring_check (F : Type) `{HF : Field F} : Ring (C F) := _.

Example c_field_check (F : Type) `{HF : Field F} (FR : MinusOneNotASquare F) :
  Field (C F) := _.

The _ is the whole test: Coq must find the instance from the stated hypotheses alone, and the second one fails to elaborate if MinusOneNotASquare F is dropped.

The shopping list is bought. Next: sequences, limits, and the first ε\varepsilon-δ\delta proofs — with ‖·‖ as the ruler and Reals as the specification they are stated against.
