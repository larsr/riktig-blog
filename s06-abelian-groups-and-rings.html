Commutative structure: abelian groups and rings

The group post got a long way on three laws — associativity, identity, inverse — without ever assuming that a+ba + b equals b+ab + a. Order genuinely matters for some groups: composing two rotations of a cube in the other order lands somewhere else. But for the groups this series needs next, order does not matter, and assuming it changes what can be proved.

This post adds commutativity, then a second operation alongside the first, arriving at the structure that describes the integers: a ring.

Commutativity, and what it makes possible

A group whose operation satisfies

a+b=b+aa + b = b + a

is an abelian group. The transcription adds one field to Group:

  Class AbGroup (A : Type) {eq : EqRel A} {zero : Zero A} {add : HasAdd A}
                {neg : HasNeg A} := {
    group    :: Group A;
    is_commutative :: Commutative A A add;
  }.

What commutativity buys is the freedom to move a summand anywhere in a sum. Theory/AbGroup.v records that freedom as a handful of named rearrangements, each proved by the same three-step pattern: associativity out, commutativity in the middle, associativity back.

(a+b)+c=a+(b+c)=a+(c+b)=(a+c)+b(a + b) + c = a + (b + c) = a + (c + b) = (a + c) + b

  Theorem add_swap_r : forall a b c : G, (a + b) + c == (a + c) + b.
  Proof.
    intros a b c.
    calc ((a + b) + c)
      == (a + (b + c))  { associative }
      == (a + (c + b))  { (commutative b) }
      == ((a + c) + b)  { associative }.
  Qed.

The most useful of the family swaps the two middle terms of a sum of four — the interchange law, which is what turns up whenever two sums have to be recombined:

(a+b)+(c+d)=(a+c)+(b+d)(a + b) + (c + d) = (a + c) + (b + d)

  Theorem add_interchange : forall a b c d : G,
    (a + b) + (c + d) == (a + c) + (b + d).

Its proof uses add_swap_l in the middle rather than commutativity directly, which is the general habit: each lemma is proved from the one below it, so no chain is longer than it has to be.

One more consequence, and it is the reason the group post was careful about the order in −(a+b)=(−b)+(−a)-(a+b) = (-b) + (-a): when addition commutes, the reversal stops mattering, and Theory/AbGroup.v can state the friendly form −(a+b)=(−a)+(−b)-(a + b) = (-a) + (-b) as neg_add.

A second operation

A ring is an abelian group under ++ that also carries a multiplication which is associative with a unit, and which distributes over addition:

a(b+c)=ab+ac(a+b)c=ac+bc.a(b + c) = ab + ac \qquad (a + b)c = ac + bc.

Distributivity is the only law connecting the two operations, and everything below comes from it.

  Class Ring (R : Type) {eq : EqRel R} {zero : Zero R} {add : HasAdd R}
             {neg : HasNeg R} {one : One R} {mult : HasMult R} := {
    abgroup               :: AbGroup R;
    mul_monoid            :: @Monoid R eq one mult;
    is_left_distributive  :: LeftDistributive R R R mult;
    is_right_distributive :: RightDistributive R R R mult;
  }.

Look at the second field. Multiplication is not given fresh laws of its own: it reuses Monoid, the same class the additive side used, with one where zero went and mult where add went. That is what the explicit @Monoid R eq one mult is doing — naming the arguments positionally because this time they are not the ones search would pick by default. Associativity of multiplication and the laws 1a=a=a11a = a = a1 are exactly the monoid’s laws, so they are not restated.

Note also what is absent: no commutativity for multiplication, and no multiplicative inverses. Square matrices are a ring and AB≠BAAB \neq BA in general; the integers are a ring and 22 has no reciprocal. Both are added later, and each addition has a name of its own.

Multiplying by zero

Nothing in the ring axioms says a⋅0=0a \cdot 0 = 0. It has to be proved, and the proof is short once you notice what distributivity says about a fixed factor. Multiplying by aa turns sums into sums,

a(x+y)=ax+ay,a(x + y) = ax + ay,

which is precisely the statement that the map x↦axx \mapsto ax preserves addition. The group post proved that any such map sends 00 to 00. So there is nothing left to do but name the map:

  Theorem mul_0_r : forall a : R, a * 0 == 0.
  Proof.
    intros a.
    exact (additive_zero (mult a)).
  Qed.

The three siblings — mul_0_l, mul_neg_l, mul_neg_r — are the same line with the other side or the other theorem. And the sign rule that schoolchildren memorise is two of them and a double negation:

(−a)(−b)=−(a(−b))=−(−(ab))=ab(-a)(-b) = -\big(a(-b)\big) = -\big(-(ab)\big) = ab

  Theorem mul_neg_neg : forall a b : R, (- a) * (- b) == a * b.
  Proof.
    intros a b.
    calc ((- a) * (- b))
      == (- (a * (- b)))  { mul_neg_l }
      == (- - (a * b))    { mul_neg_r }

The chain ends by citing neg_involutive from the group post. Minus times minus is plus because negation is an involution — not because anyone declared it so.

The integers

Impl/Zr.v supplies Z with the vocabulary and then discharges each law by naming the standard library’s fact for it:

Instance Z_add_commutative : Commutative Z Z add := Z.add_comm.
Instance Z_left_distributive : LeftDistributive Z Z Z mult :=

and the three structures cost one line each:

Instance Z_Group : Group Z := {}.
Instance Z_AbGroup : AbGroup Z := {}.
Instance Z_Ring : Ring Z := {}.

From there, every theorem in this post and the two before it holds for Z, and the equality they hold up to is Coq’s own — Z_EqRel chooses eq, because two integers that are equal are the same integer. The next post’s carrier will not be so lucky.
