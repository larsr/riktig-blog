The monoid, and its unique identity

A semigroup is a set with an associative operation. Add one element that does nothing — an identity element — and you have the structure that turns up in programming more than any other: a monoid. Lists with concatenation and the empty list. Integers with addition and zero. Functions from a type to itself with composition and the identity function. Strings, matrices, steps run in sequence — all monoids.

This post gives the structure, then proves the fact that makes the phrase “the element that does nothing” well defined: there cannot be two of them.

The structure

A monoid is a set MM with an associative operation ++ and an element 00 such that, for every aa,

0+a=aanda+0=a.0 + a = a \qquad\text{and}\qquad a + 0 = a.

The whole of Interface/Monoid.v:

  Class Monoid (M : Type) {eq : EqRel M} {zero : Zero M} {add : HasAdd M} := {
    semigroup         :: Semigroup M add;
    is_left_identity  :: LeftIdentity M M add 0;
    is_right_identity :: RightIdentity M M add 0;
  }.

Associativity is not restated — it lives in the semigroup, which the first field holds whole. The two new laws come from the catalogue in Props.v,

  Class LeftIdentity := left_identity : forall x : B, unit · x == x.

filled in as LeftIdentity M M add 0. Their projections, left_identity and right_identity, are the names the proofs below cite.

The two sides are demanded separately, and that is not pedantry: there are structures with a left identity and no right one. Requiring both is what makes the next theorem true.

There is only one identity

Suppose ee works as a left identity and ff works as a right identity — possibly two unrelated elements, arrived at by different routes. Then they are equal:

e=e+f=f,e = e + f = f,

the first step because ff is a right identity, the second because ee is a left identity. The middle term e+fe + f is the whole idea: each hypothesis applies to it from its own side.

  Theorem id_unique : forall e f : M,
    (forall a, e + a == a) -> (forall a, a + f == a) -> e == f.
  Proof.
    intros e f He Hf.
    calc e
      == (e + f) { (Hf e) }
      == f       { (He f) }.
  Qed.

He and Hf are the two hypotheses, and each step names the one it uses at the point it uses it: Hf e is “f is a right identity, applied to ee”, and He f is “e is a left identity, applied to ff”. Notice what the statement does not say: neither ee nor ff is assumed to be the structure’s own 0. It is about any two elements that behave like identities, which is why it rules out a second one.

Specialising one side to the structure’s own 0 gives the form later proofs actually reach for — anything acting as a left identity is 0:

e=e+0=0e = e + 0 = 0

  Theorem zero_unique_l : forall e : M, (forall a, e + a == a) -> e == 0.
  Proof.
    intros e He.
    calc e
      == (e + 0) { right_identity    }
      == (0 : M) { (He 0) }.
  Qed.

The first step is the structure’s own right-identity law, the second the hypothesis at 0. zero_unique_r is the mirror image. The ascription in (0 : M) is there because a bare 0 does not say which carrier is meant — one of the small habits collected in the Coq underneath.

Uniqueness as something search can find

Theory/Monoid.v ends by recording the result as an instance of a general notion: a property that at most one element can have.

Instance Monoid_LeftIdUnique M `{HM : Monoid M} :
  Unique M (fun e : M => forall a, e + a == a).
Proof.
  intros e f He Hf.
  calc e
    == (0 : M) { (zero_unique_l e He) }
    == f       { (zero_unique_l f Hf) }.
Qed.

Both elements are shown equal to 0 by the theorem just proved, and == is transitive. Stating it as Unique rather than as one more named lemma means a later proof that needs “there is at most one such thing” can find it without knowing this file exists.

Seen from below

Nothing above mentions lists, integers or matrices. Concretely, Impl/ListMonoid.v supplies the vocabulary and the three laws for lists, and then

Instance List_Monoid A : Monoid (list A) := {}.

is the entire declaration — the empty braces ask instance search to supply every field. From that line onward id_unique, zero_unique_l and everything else proved about monoids applies to list A, with concatenation for + and the empty list for 0. The proofs were written once, and were never about lists.
