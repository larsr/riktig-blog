Merge sort, correct

A definition that will not unfold

Most recursive programs terminate for a reason a compiler can check by itself: each recursive call is made on a piece of the argument it was given. Merge sort is not one of them. It splits its input into two halves, sorts each, and merges the results — and the two halves are things computed from the input, not parts of it. A checker that only knows “recurse on a sub-term” has no way to see that fst (split l) is shorter than l.

The standard remedy is to give the reason explicitly: pick a measure that drops at every call — here the length of the list — and define the function by recursion on the proof that the measure cannot drop forever. In Coq that is the Fix combinator, and it works. But it buys termination at a price. The resulting definition carries a proof of well-foundedness inside it, and on a list built from variables that proof is stuck, so the recursion cannot take a step. Calling simpl on a goal about msort (x :: y :: rest) leaves the term where it was: the equations you had in mind when you wrote the program — “the empty list sorts to itself; a list of two or more sorts to the merge of its sorted halves” — are nowhere in the goal.

So the question this post is about is not really “does merge sort sort?” It is: what do you prove about a function you cannot unfold? The answer is to recover the equations once, as a lemma, and then never mention the definition again. Every theorem below rewrites with that lemma and nothing else.

The program, and the equation it deserves

split alternates the elements of a list between two outputs, and recurses on a literal sub-list, so it is an ordinary Fixpoint. merge walks two already-sorted lists and repeatedly emits the smaller head. Neither is the problem. msort is:

Definition msort : list nat -> list nat.
apply (Fix (well_founded_ltof (list nat) (@length nat)) (fun _ => list nat)).
intros l rec.
(* Term-mode `match l with ...` (as used by `qsort` in
   Quicksort.v) does not propagate the pattern `x :: y :: rest` back
   into `rec`'s type, since the Fix body here doesn't depend on `l`
   pointwise; `destruct` (tactic-mode) does perform that
   substitution, so the two termination holes below see the goal in
   exactly `split_length_lt`'s shape. *)
destruct l as [|x [|y rest]].
- exact [].
- exact [x].
- refine (merge (rec (fst (split (x :: y :: rest))) _)
                (rec (snd (split (x :: y :: rest))) _));
  abstract (unfold ltof; apply (split_length_lt x y rest)).
Defined.

well_founded_ltof (list nat) length is “shorter-than on lists is well-founded”; rec is the recursive call, and it demands, as an extra argument, a proof that what it is being applied to is strictly shorter. Those are the two holes left by refine, and abstract closes them with a proof stored outside the definition’s own body, so what the definition shows is the program and not its termination argument. The case split is written as a destruct rather than a term-level match for the reason the comment gives: only the tactic substitutes the pattern back into the type of rec, which is what leaves the two holes in exactly the shape of the lemma that discharges them:

Lemma split_length_lt {A} (x y : A) (rest : list A) :
  length (fst (split (x :: y :: rest))) < length (x :: y :: rest) /\
  length (snd (split (x :: y :: rest))) < length (x :: y :: rest).

On a closed list the definition does compute — the well-foundedness proof reduces once the list is a literal — so the program runs:

Check Logic.eq_refl : msort [5;3;8;1;9;2;7] = [1;2;3;5;7;8;9].
Check Logic.eq_refl : msort [2;1] = [1;2].

What it does not do is take a step on x :: y :: rest. The lemma that fixes this is msort_step, and it is proved with the standard library’s Fix_eq: a Fix equals its own body applied to itself, provided the body cannot tell two extensionally equal recursive calls apart.

Lemma msort_step l :
  msort l =
    match l with
    | [] => l
    | [_] => l
    | x :: y :: rest =>
        merge (msort (fst (split (x :: y :: rest))))
              (msort (snd (split (x :: y :: rest))))
    end.
Proof.
  unfold msort at 1. rewrite Fix_eq.
  - destruct l as [|x [|y rest]]; reflexivity.
  - intros u f g Hfg.
    destruct u as [|x [|y rest]]; try reflexivity.
    rewrite !Hfg. reflexivity.
Qed.

The first bullet is the equation itself: once Fix_eq has replaced the Fix by its own body, each of the three branches holds by reflexivity. The second bullet is Fix_eq’s side condition: given Hfg : forall y p, f y p = g y p, the body built from f must equal the body built from g — which here is rewrite !Hfg, because the body uses its recursive call twice and does nothing else with it. This is the last time Fix is mentioned in any proof about msort.

One more step makes the equation comfortable to use. Rewriting with msort_step leaves a match in the goal, which then has to be destructed by hand at every use. Three corollaries, one per branch, remove it once and for all:

Lemma msort_nil : msort [] = [].
Proof. rewrite msort_step. reflexivity. Qed.

Lemma msort_single (x : nat) : msort [x] = [x].
Proof. rewrite msort_step. reflexivity. Qed.

Lemma msort_cons2 (x y : nat) (rest : list nat) :
  msort (x :: y :: rest) =
    merge (msort (fst (split (x :: y :: rest))))
          (msort (snd (split (x :: y :: rest)))).
Proof. rewrite msort_step. reflexivity. Qed.

From here on msort behaves in proofs exactly like a Fixpoint: three equations, each rewritable in one direction, and no residual match.

Nothing is lost

Sorting is two claims, and this is the first: the output of msort is a rearrangement of its input. Writing ∼\sim for “is a permutation of” and (l1,l2)(l_1, l_2) for split(l)\mathrm{split}(l), the interesting case is a chain of three rearrangements:

x::y::r∼l1++l2{splitting loses nothing}∼msort(l1)++msort(l2){induction hypothesis, on each half}∼merge(msort(l1),msort(l2)){merging loses nothing}=msort(x::y::r){the branch equation 𝚖𝚜𝚘𝚛𝚝_𝚌𝚘𝚗𝚜𝟸.} \begin{aligned} x :: y :: r &\sim l_1 \mathbin{+\!\!+} l_2 && \{\text{splitting loses nothing}\}\\ &\sim \mathrm{msort}(l_1) \mathbin{+\!\!+} \mathrm{msort}(l_2) && \{\text{induction hypothesis, on each half}\}\\ &\sim \mathrm{merge}(\mathrm{msort}(l_1),\ \mathrm{msort}(l_2)) && \{\text{merging loses nothing}\}\\ &= \mathrm{msort}(x :: y :: r) && \{\text{the branch equation } \mathtt{msort\_cons2}.\} \end{aligned}

The two “loses nothing” facts are separate lemmas about the two helper programs. split_perm : Permutation l (fst (split l) ++ snd (split l)) is an induction on the measure length (split consumes two elements at a time, so structural induction does not fit its shape), and merge_perm : Permutation (l1 ++ l2) (merge l1 l2) needs no induction at all here: this file’s merge is the generic merge with its two arguments swapped, so the generic permutation lemma applies directly and Permutation_app_comm puts the two arguments back in the written order. The Coq proof of the theorem is the chain above, read downwards:

Theorem msort_perm : forall l : list nat, Permutation l (msort l).
Proof.
  apply (measure_ind (@length nat)).
  intros l IH.
  destruct l as [|x [|y rest]].
  - rewrite msort_nil. constructor.
  - rewrite msort_single. apply Permutation_refl.
  - pose proof (split_length_lt x y rest) as [H1 H2].
    rewrite msort_cons2.
    calc (x :: y :: rest)
      == (fst (split (x :: y :: rest)) ++ snd (split (x :: y :: rest)))
      == (msort (fst (split (x :: y :: rest))) ++
          msort (snd (split (x :: y :: rest))))
      == (merge (msort (fst (split (x :: y :: rest))))
                (msort (snd (split (x :: y :: rest))))).
    + apply split_perm.
    + apply Permutation_app; apply IH; [exact H1 | exact H2].
    + apply merge_perm.
Qed.

Walking it:

  • The induction is well-founded on length, the same measure msort itself recurses on, so the hypothesis IH is available at any strictly shorter list. destruct l splits into exactly the three shapes the three branch corollaries cover.
  • Empty and singleton: rewrite the corollary, then the output is the input, so constructor (a permutation of [] with itself) and Permutation_refl close them.
  • The main case first names the two “strictly shorter” facts H1 and H2 from split_length_lt, then rewrites msort_cons2 — the only contact with the definition — and states the chain. Its three steps are the three annotations on the blackboard version: split_perm, then Permutation_app (concatenating respects permutation) fed the induction hypothesis at each half, then merge_perm.

The == in the chain is not equality: calc reads the relation off the goal, which here is Permutation, and glues the steps with its transitivity.

Nothing is out of order

The second claim is that the output is sorted, and it is shorter, because the substance lives in merge_sorted — merging two sorted lists yields a sorted list — which is proved once about merge and reused here:

Theorem msort_sorted : forall l : list nat, Sorted le (msort l).
Proof.
  apply (measure_ind (@length nat)).
  intros l IH.
  destruct l as [|x [|y rest]].
  - rewrite msort_nil. constructor.
  - rewrite msort_single. constructor; constructor.
  - pose proof (split_length_lt x y rest) as [H1 H2].
    rewrite msort_cons2.
    apply merge_sorted; apply IH; [exact H1 | exact H2].
Qed.

Same skeleton, same three branches. The empty list is sorted by constructor; a singleton needs two, one for “the tail is sorted” and one for “the head bounds the empty tail”. The main case rewrites msort_cons2, exposing the merge of the two recursively sorted halves; apply merge_sorted then reduces “the merge is sorted” to “each half is sorted”, and apply IH closes both at the strictly shorter arguments.

Together the two theorems pin sorting down completely — a rearrangement of the input that is in order is the sorted rearrangement, since sortedness and element content determine a list:

Corollary msort_correct : forall l : list nat,
  Permutation l (msort l) /\ Sorted le (msort l).
Proof. intros l. split; [apply msort_perm | apply msort_sorted]. Qed.

Permutation and Sorted are the standard library’s own predicates, so the statement means what any Coq user would take it to mean: no element gained or lost, and every adjacent pair of the output in order.

Nothing in this proof was specific to sorting. A function defined by well-founded recursion gets one unfolding lemma through Fix_eq, one match-free corollary per branch, and then induction on the very measure the function recurses on — after which Fix never has to be mentioned again.
