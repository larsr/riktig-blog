Multiplication is differentiable

A first course in calculus differentiates x↦xcx \mapsto x\,c for a fixed cc and gets cc, which is no work at all: the function is linear, and a linear function is its own best linear approximation everywhere. The product rule is about the harder question — what happens when both factors move. For ordinary numbers the answer is familiar,

d(xy)=ydx+xdy,d(xy) \;=\; y\,dx + x\,dy,

and the reason it is not trivial is visible in the algebra. Expand (x0+dx)(y0+dy)(x_0 + dx)(y_0 + dy) and four terms appear: the value x0y0x_0 y_0, the two terms of the rule, and a fourth, dxdydx\,dy, that belongs to none of them. The rule is correct only because that fourth term is negligible compared to the size of the step — and “negligible” is an analytic claim, not an algebraic one.

Multiplication of numbers is one instance of a much wider pattern. Matrix multiplication, the scaling of a vector by a scalar, an inner product, the application of a linear map to a vector: each takes two arguments, is linear in each one separately when the other is held fixed, and is not linear in the pair — doubling both arguments quadruples the result. A map like that is called bilinear. The question this post answers is whether the product rule above holds for every bilinear map, into any space, and what exactly has to be proved to get it: how much is algebra, and how much is genuine analysis.

The setting: a map of two arguments, and the size of a pair

Write BB for a bilinear map taking a uu from one space and a vv from another and producing a value in a third. Viewing BB as a function of both arguments at once means viewing it as a function on the product space of pairs (u,v)(u,v). The claimed derivative at a point (u0,v0)(u_0,v_0) is the map sending a pair of steps to the sum of the two rule terms:

DB(u0,v0)(du,dv)=B(du,v0)+B(u0,dv).D B(u_0,v_0)\,(du,dv) \;=\; B(du,\,v_0) \;+\; B(u_0,\,dv).

That candidate is itself a function on pairs, and it is linear in the pair — additivity and homogeneity each follow from one law of BB in each slot — so it can be packaged as an actual linear map, bilinear_deriv_lm, built from the function

  Definition bilinear_deriv_fun (p : U * V) : W :=
    B (fst p) v0 + B u0 (snd p).

“Derivative” is meaningless without a way to measure the size of a step, and a step here is a pair. The measurement chosen is the sum norm — the size of a pair is the sum of the sizes of its parts (Theory/ProdVS.v):

  Definition prod_norm (p : A * B) : F := ‖ fst p ‖ + ‖ snd p ‖.

Taking the sum rather than the larger of the two is a deliberate choice: every estimate below then rearranges by ordinary addition, where the maximum would force a comparison of the two components at every step.

The definition of derivative being met is the coordinate-free one: a bounded linear map L whose error against f shrinks faster than the step (Theory/Derivative.v):

  Definition is_deriv (f : U -> V) (a : U) (L : LinearMap F U V) : Prop :=
    linear_map_bounded L /\
    forall eps : F, 0 < eps ->
      exists delta : F, 0 < delta /\
        forall h : U, ‖ h ‖ < delta ->
          ‖ f (a + h) + - (f a + L h) ‖ <= eps * ‖ h ‖.

Finally, the estimate needs a hypothesis about BB itself: that it does not magnify its arguments without bound. For a linear map that condition is linear_map_bounded; the bilinear analogue asks for a single constant that works for both slots at once:

  Definition bm_bounded (B : BilinearMap F U V W) : Prop :=
    exists C : F, 0 <= C /\ forall (u : U) (v : V), ‖ B u v ‖ <= C * ‖ u ‖ * ‖ v ‖.

It is stated as a hypothesis the theorem takes, not as a further field of the bilinear-map record, for the same reason linear_map_bounded is not a field of LinearMap: bilinearity is an algebraic notion that makes sense with no norm in sight, and only the theorems that estimate things should have to mention one.

Algebra gets three terms; the fourth is the work

Statement. The remainder of BB against the candidate derivative is exactly the cross term.

Expanding by bilinearity in the first slot and then the second,

B(u0+du,v0+dv)=B(u0,v0)+B(du,v0)+B(u0,dv)+B(du,dv),B(u_0{+}du,\,v_0{+}dv) = B(u_0,v_0) + B(du,v_0) + B(u_0,dv) + B(du,dv),

so subtracting the value and the candidate’s contribution leaves B(du,dv)B(du,dv) and nothing else. There is no approximation in this step: it is an identity.

  Lemma bilinear_remainder_eq : forall (du : U) (dv : V),
    B (u0 + du) (v0 + dv) + - (B u0 v0 + (B du v0 + B u0 dv)) == B du dv.

Now the analysis. The chain rule for ordinary linear maps never has to work this hard, because there the remainder of a composite is a sum of two small quantities, and a sum of small things is small with no argument at all. Here the leftover is a product of two small quantities. Bounding it with bm_bounded and then bounding each factor by the whole step size ‖h‖=‖du‖+‖dv‖\lVert h \rVert = \lVert du\rVert + \lVert dv\rVert gives

‖B(du,dv)‖≤C‖du‖‖dv‖≤C‖h‖‖h‖,\lVert B(du,dv)\rVert \;\le\; C\,\lVert du\rVert\,\lVert dv\rVert \;\le\; C\,\lVert h\rVert\,\lVert h\rVert,

which is quadratic in the step. A quadratic bound is not automatically small compared to the step — being smaller than C‖h‖2C\lVert h\rVert^2 says nothing until C‖h‖C\lVert h\rVert itself is known to be small. So the tolerance has to be turned into a radius: given ε\varepsilon, take δ=ε/(1+C)\delta = \varepsilon / (1 + C), and for every step shorter than δ\delta the factor C‖h‖C\lVert h\rVert drops below ε\varepsilon, collapsing the quadratic bound to ε‖h‖\varepsilon\lVert h\rVert exactly. The padding by 11 in the divisor is what keeps δ\delta positive even when CC is zero, with no test of whether it is.

  Lemma bilinear_remainder_bound : forall C : F, 0 <= C ->
    (forall (u : U) (v : V), ‖ B u v ‖ <= C * ‖ u ‖ * ‖ v ‖) ->
    forall eps : F, 0 < eps ->
    forall (du : U) (dv : V),
      ‖ du ‖ + ‖ dv ‖ < eps * inv (1 + C) ->
      ‖ B du dv ‖ <= eps * (‖ du ‖ + ‖ dv ‖).

With the identity and the estimate in hand, the theorem is their assembly:

  Theorem bilinear_is_deriv : bm_bounded B ->
    is_deriv (fun p : U * V => B (fst p) (snd p)) (u0, v0) bilinear_deriv_lm.
  Proof.
    intros Hbb.
    split.
    - exact (bilinear_deriv_bounded Hbb).
    - destruct Hbb as [C [HC HCb]].
      intros eps Heps.
      exists (eps * inv (1 + C)).
      split.
      + apply mul_pos.
        * exact Heps.
        * apply pos_inv. apply one_plus_nonneg_pos. exact HC.
      + intros [du dv] Hh.
        simpl.
        unfold LinearMap.map, bilinear_deriv_lm, bilinear_deriv_fun; simpl.
        calc (‖ B (u0 + du) (v0 + dv) + - (B u0 v0 + (B du v0 + B u0 dv)) ‖)
          == (‖ B du dv ‖)
          == (eps * ‖ (du, dv) ‖).
        * apply eq_le. apply vnorm_proper. exact (bilinear_remainder_eq du dv).
        * unfold vnorm, Prod_HasNorm, prod_norm; simpl.
          exact (bilinear_remainder_bound C HC HCb eps Heps du dv Hh).
  Qed.

Walking it: split produces the two halves of is_deriv. The first is that the candidate is a bounded linear map, which bilinear_deriv_bounded gets from bm_bounded with the constant C‖v0‖+C‖u0‖C\lVert v_0\rVert + C\lVert u_0\rVert — one term per slot. For the second half, destruct names the bound C and intros eps Heps fixes a tolerance; exists (eps * inv (1 + C)) offers the padded radius, and the apply mul_pos branch checks it is positive without any test on C. Then intros [du dv] Hh takes an arbitrary short step, split into its two components. The calc chain has exactly two steps, one per half of the argument: bilinear_remainder_eq rewrites the remainder to the cross term (under the norm, via NormedSpace.vnorm_proper), and bilinear_remainder_bound bounds the cross term by eps * ‖ (du, dv) ‖ once the sum norm is unfolded.

Nothing in the statement mentions a dimension, a basis, or a particular kind of product. It holds for every bounded bilinear map into every normed space.

Using it: the product of two matrices

The instance that motivates the whole thing is matrix multiplication, which is bilinear — linear in the left factor for a fixed right one and conversely — and, with matrices measured by the sum of the absolute values of their entries, bounded with the sharp constant C=1C = 1, since ‖AB‖≤‖A‖‖B‖\lVert A B\rVert \le \lVert A\rVert\,\lVert B\rVert. Theory/MatMulBilinear.v packages mat_mul as a bilinear map (mat_mul_bilinear), proves that bound (mat_mul_bm_bounded), and hands both to the theorem above:

  Theorem mat_mul_is_deriv : forall (A0 : Matrix m n F) (B0 : Matrix n p F),
    is_deriv (fun AB : Matrix m n F * Matrix n p F => mat_mul (fst AB) (snd AB))
      (A0, B0) (mat_mul_deriv_lm A0 B0).
  Proof.
    intros A0 B0.
    exact (bilinear_is_deriv mat_mul_bilinear A0 B0 mat_mul_bm_bounded).
  Qed.

A single exact: the general theorem, applied to the witness and its boundedness proof. That is the payment the abstraction returns — differentiating a matrix product in both arguments at once, which is what training a layer that multiplies data by weights requires, needs no analysis of its own.
