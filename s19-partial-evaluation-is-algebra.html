Partial evaluation is algebra

Every compiler you have ever used performs equational reasoning it never writes down: this call can be inlined; this branch is dead; this expression is that constant. Each of those is a claim that two programs are interchangeable. This post gives that claim a symbol, laws, and machine-checked proofs, for the untyped lambda calculus — three kinds of term, a variable Var n, a function Abs b and an application App f a, with a call-by-value reduction relation step saying how one term becomes the next.

An algebraic structure is set up the same way every time: a carrier, an equality == chosen for the job, laws stated as equations in that equality. A group’s carrier is its elements; here the carrier is the type tm of programs, and the equality has to be built.

Making == mean “behaves alike”

step is a poor candidate: it runs forward, and only where call-by-value permits. Close it under congruence and under equivalence and you get conversion (theories/Lambda/Conv.v):

Inductive conv : tm -> tm -> Prop :=
  | conv_step : forall t t', step t t' -> conv t t'
  | conv_abs : forall b b', conv b b' -> conv (Abs b) (Abs b')
  | conv_appl : forall f f' a, conv f f' -> conv (App f a) (App f' a)
  | conv_appr : forall f a a', conv a a' -> conv (App f a) (App f a')
  | conv_refl : forall t, conv t t
  | conv_sym : forall t u, conv t u -> conv u t
  | conv_trans : forall t u v, conv t u -> conv u v -> conv t v.

Instance Tm_EqRel : EqRel tm := conv.

That last line is the whole point: tm now has a ==, the same == as monoids and vector spaces, with the same consequences — the Proper instances for Abs and App mean rewrite descends into programs like it descends into sums. Program syntax is now a setoid, and program transformation is setoid rewriting.

Two design notes. First, conv deliberately contains more than execution: step only reduces in call-by-value positions, but conv_abs lets us rewrite under a binder — an optimizer transforms function bodies without calling the function. Second, equality by running comes with a bridge that turns the evaluator into a proof engine:

Lemma conv_by_eval : forall n m s t, eval n s = eval m t -> s == t.

If two terms compute to the same normal form, they are convertible. Proofs of program equations become apply (conv_by_eval 10 10). reflexivity. — the kernel runs both programs and compares. We prove by executing.

Booleans without booleans

The lambda calculus has no if, no true, no false — and needs none. Church’s encoding: a boolean is the choice it would make.

TRUE=λt.λe.tFALSE=λt.λe.e\mathrm{TRUE} = \lambda t.\lambda e.\, t \qquad \mathrm{FALSE} = \lambda t.\lambda e.\, e

TRUE applied to two arguments keeps the first; FALSE keeps the second — your if is just application, bghb\,g\,h, written IFB b g h. In theories/Lambda/Church.v the branch-simplification laws every compiler applies are theorems:

Lemma IF_TRUE : forall g h, value g -> value h -> IFB TRUE g h == g.
Lemma IF_FALSE : forall g h, value g -> value h -> IFB FALSE g h == h.

(The value hypotheses are what call-by-value demands: you may only discard a branch that call-by-value was never going to evaluate.) Pairs come from the same trick — a pair is a function awaiting a selector, and the projection laws FST_PAIR, SND_PAIR end their proofs with exact (IF_TRUE v w Hv Hw) and exact (IF_FALSE v w Hv Hw), because a projection is an applied boolean. The encoding’s elegance shows up as proof reuse.

Dead-branch elimination is a two-line proof

Here is the theorem this post exists for, exactly as it appears in the source:

Lemma if_of_true : forall b g h,
  value g -> value h -> b == TRUE -> IFB b g h == g.
Proof.
  intros b g h Hg Hh Hb. rewrite Hb. apply IF_TRUE; assumption.
Qed.

Read it slowly: we know the condition is (equivalent to) TRUE — perhaps an analysis proved it, perhaps it came from a constant — so we rewrite the condition inside the program (rewrite Hb, which works because IFB respects ==), and then the branch law finishes. The group proof cancel_l has the same two moves in the other order: rewrite with the hypothesis a + b == a + c in the middle of a chain of named laws, and let the laws close it. Group elements, vectors, programs — one discipline.

That is what a rewrite pipeline needs. A program refined step by step — inline this, specialize that, lower arithmetic, introduce a stack — is only a compilation if every step preserves meaning, and this is what a meaning-preserving step is, formally: an == on programs whose operations carry Proper instances, so that steps compose and apply locally. Unfold, inline, partially evaluate — each is a named lemma, each application is one rewrite, and the chain of them is a verified compilation.
