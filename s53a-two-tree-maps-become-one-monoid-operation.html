Two tree maps become one monoid operation: fusion by delayed actions

Applying an operation to every element of a tree costs a full traversal. Applying two operations costs two traversals — unless the program is rewritten to apply their composition in a single pass, the optimization compilers know as fusion. There is a stronger move available when the operations compose by a monoid rule: traverse zero times, by storing the pending operation at the root and combining newly arriving operations into it — one monoid multiplication each, touching no element. The data-structures literature knows this as lazy propagation in a segment tree; this post proves the algebra that makes it sound, and gets the classic fusion law back as a corollary, without its induction.

Trees, actions, and the delayed tree

Two datatypes, from Impl/DelayedTree.v — the plain binary tree with values at the leaves, and the same tree with one extra constructor holding a pending operation:

Inductive Tree (A : Type) : Type :=
| Leaf (a : A)
| Node (l r : Tree A).
Inductive DTree (M A : Type) : Type :=
| DLeaf (a : A)
| DNode (l r : DTree M A)
| DDelay (m : M) (t : DTree M A).

The operations being applied come from a monoid M (the monoid post, written additively here) acting on the leaf values: an action assigns each m : M a function on A, such that the monoid’s identity does nothing and applying two in sequence is applying their product,

0⋅a=a,m⋅(n⋅a)=(m+n)⋅a.0 \cdot a = a, \qquad m \cdot (n \cdot a) = (m + n) \cdot a.

  Context (act : M -> A -> A).
  Context (act_proper : Proper (equ ==> equ ==> equ) act).
  Context (act_unit : forall a : A, act 0 a == a).
  Context (act_compose : forall (m n : M) (a : A),
    act m (act n a) == act (m + n) a).

Only the first two of those are needed to write the code down: an action that respects leaf equality is enough to define the functions and to rewrite under the constructors. The two laws proper — act_unit and act_compose — are needed only to prove things, and that is where the development splits. The datatypes, the five functions and the equations that hold by reflexivity are Impl/DelayedTree.v; everything below is Theory/DelayedFusion.v, which adds the two laws as hypotheses.

The traversing map applies the action at every leaf:

  Fixpoint map_act (m : M) (t : Tree A) : Tree A :=
    match t with
    | Leaf a => Leaf (act m a)
    | Node l r => Node (map_act m l) (map_act m r)
    end.

On the delayed side, three functions. force turns a DTree back into a Tree by pushing the accumulated operation down (its worker force_acc carries the accumulator, composing with each DDelay it passes); lift embeds a plain tree with no pending operation; and delay is the whole point —

  Definition delay (m : M) (t : DTree M A) : DTree M A :=
    match t with
    | DDelay n u => DDelay (m + n) u
    | _ => DDelay m t
    end.

it wraps the root, and if the root is already a pending operation it combines with it instead of nesting. That case is the zero-cost claim, and it is stated with Coq’s structural equality = and proved by reflexivity — one monoid operation happens and no tree is inspected:

  Lemma delay_DDelay : forall (m n : M) (t : DTree M A),
    delay m (DDelay n t) = DDelay (m + n) t.
  Proof.
    intros m n t. reflexivity.
  Qed.

The correctness laws

Trees are compared leafwise up to A’s equality (tree_equiv). The bridge law says a delayed operation means what the traversal means — writing m⋅um \cdot u for map_act m u:

force(delaymt)≡m⋅forcet,\mathrm{force}(\mathrm{delay}\,m\,t) \;\equiv\; m \cdot \mathrm{force}\,t,

which is force_delay, proved from one accumulator induction (force_acc_compose) — the only induction on the delayed side. Everything else chains. The theorem that delaying twice equals delaying the product is four rewriting steps on the blackboard,

force(delaym(delaynt))≡m⋅force(delaynt)≡m⋅(n⋅forcet)≡(m+n)⋅forcet≡force(delay(m+n)t),\mathrm{force}(\mathrm{delay}\,m\,(\mathrm{delay}\,n\,t)) \;\equiv\; m \cdot \mathrm{force}(\mathrm{delay}\,n\,t) \;\equiv\; m \cdot (n \cdot \mathrm{force}\,t) \;\equiv\; (m+n) \cdot \mathrm{force}\,t \;\equiv\; \mathrm{force}(\mathrm{delay}\,(m+n)\,t),

— the bridge, the bridge again, fusion of two traversals, and the bridge backwards. In Coq, as a calc chain (the calc post explains the notation):

  Theorem delay_delay : forall (m n : M) (t : DTree M A),
    tree_equiv (force (delay m (delay n t))) (force (delay (m + n) t)).
  Proof.
    intros m n t.
    calc (force (delay m (delay n t)))
      == (map_act m (force (delay n t)))
           { force_delay }
      == (map_act m (map_act n (force t)))
           { force_delay }
      == (map_act (m + n) (force t))
           { map_act_fuse }
      == (force (delay (m + n) t))
           { force_delay }.
  Qed.

And the dependency can be turned around: the classic fusion law for the traversing map falls out of the delayed apparatus with no induction of its own — round-trip through lift, combine the two delays at the root, and come back:

  Corollary fusion_via_delay : forall (m n : M) (u : Tree A),
    tree_equiv (map_act m (map_act n u)) (map_act (m + n) u).
  Proof.
    intros m n u.
    calc (map_act m (map_act n u))
      == (force (delay m (delay n (lift u))))
           { map_map_delay }
      == (force (delay (m + n) (lift u)))
           { delay_delay }
      == (map_act (m + n) (force (lift u)))
           { force_delay }
      == (map_act (m + n) u)
           { force_lift }.
  Qed.

Running it

At M = A = Z with addition acting on itself, everything computes, and vm_compute checks concrete trees. Delaying 7 and then 5 onto a lifted tree performs one addition and leaves the tree untouched:

  Example zdelay_combines :
    delay 5 (delay 7 (lift ztree))
    = DDelay 12 (DNode (DLeaf 1) (DNode (DLeaf 2) (DLeaf 3))).
  Proof.
    vm_compute. reflexivity.
  Qed.

Forcing performs the single deferred traversal:

  Example zforce :
    force Z.add (delay 5 (delay 7 (lift ztree)))
    = Node (Leaf 13) (Node (Leaf 14) (Leaf 15)).
  Proof.
    vm_compute. reflexivity.
  Qed.

and zfuse checks that the two-traversal program lands on the same tree. The file closes with Print Assumptions on the three main theorems, confirming the action laws entered as hypotheses of the section, not as axioms of the development — the whole soundness of the zero-traversal trick is exactly the two laws a monoid action satisfies, no more.
