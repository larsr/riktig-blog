Fast attention is one associativity away

Three matrices QQ, KK, VV, each with nn rows and dd columns, and one product to compute: (QK𝖳)V(Q\,K^{\mathsf T})\,V. In the neural networks behind current language models this is the arithmetic core of an attention layer — nn is the number of items in a sequence, dd the number of numbers describing each item, and dd is typically far smaller than nn. The middle factor QK𝖳Q\,K^{\mathsf T} is a square of side nn: it scores every pair of items against every other. At a thousand items that square has a million entries, and forming it dominates both the arithmetic and the memory.

But matrix multiplication is associative, and the other bracketing, Q(K𝖳V)Q\,(K^{\mathsf T}V), never builds anything larger than d×dd \times d. The two questions this raises are exactly the two a programmer would ask before rewriting the code. Is the reassociated expression the same matrix — not approximately, exactly? And is it actually cheaper, by how much, under a cost model precise enough to be checked rather than estimated?

Both answers can be made into theorems. The first is one application of associativity. The second is an inequality between two counts of scalar multiplications, and it holds whenever d≤nd \le n.

The two orders

Fix a field F for the entries, the two sizes, and the three matrices. Then the two bracketings are two definitions (Impl/Attention.v):

  (* Left-to-right: materializes the n×n score matrix Q·Kᵀ. *)
  Definition attention_naive : Matrix n d F :=
    mat_mul (mat_mul Q (mat_transpose K)) V.

  (* Right-to-left: materializes only the d×d matrix Kᵀ·V. *)
  Definition attention_fast : Matrix n d F :=
    mat_mul Q (mat_mul (mat_transpose K) V).

mat_transpose is the transpose — mat_transpose K is the d×nd \times n matrix whose entry (i,j)(i,j) is KjiK_{ji} — so the shapes chain as (n×d)⋅(d×n)⋅(n×d)(n{\times}d)\cdot(d{\times}n)\cdot(n{\times}d) and both expressions land in Matrix n d F.

On the blackboard the equality is the associativity law read once:

(QK𝖳)V=Q(K𝖳V){associativity of matrix multiplication}.(Q\,K^{\mathsf T})\,V \;=\; Q\,(K^{\mathsf T} V) \qquad \{\text{associativity of matrix multiplication}\}.

In Coq it is the same single step, with the four size arguments supplied:

  Theorem attention_assoc : attention_naive == attention_fast.
  Proof.
    exact (mat_mul_assoc Q (mat_transpose K) V).
  Qed.

No tactic is named: mat_mul_assoc — proved once in Theory/MatMul.v by exchanging the order of two finite sums — applied to the three factors is the theorem. It takes no shape arguments, because the general statement is about arbitrary index carriers and the two it contracts are read off the factors. The == is pointwise equality of matrices: the two sides agree entry by entry.

Counting the multiplications

Cheapness has to be defined before it can be proved. An m×nm \times n by n×pn \times p product has mpm p entries, each a sum of nn products, so by the definition of mat_mul it performs mnpm\,n\,p scalar multiplications. That is a statement about the algorithm the definition denotes, not a measurement of Coq’s own evaluator:

Definition mulcost (m n p : nat) : nat := (m * n * p)%nat.

Definition cost_naive (n d : nat) : nat :=
  (mulcost n d n + mulcost n n d)%nat.

Definition cost_fast (n d : nat) : nat :=
  (mulcost d n d + mulcost n d d)%nat.

Each order performs two products, so each count is a sum of two terms:

costnaive=ndn+nnd=2n2d,costfast=dnd+ndd=2nd2.\mathrm{cost}_{\mathrm{naive}} = n d n + n n d = 2n^2 d, \qquad \mathrm{cost}_{\mathrm{fast}} = d n d + n d d = 2n d^2 .

Statement. When d≤nd \le n, the reassociated order costs no more.

On the blackboard, compare the two sums term by term rather than multiplying them out — dnd≤ndnd\,n\,d \le n\,d\,n because d≤nd \le n in the last factor after commuting the first two, and ndd≤nndn\,d\,d \le n\,n\,d because d≤nd \le n in the middle factor. Each comparison is one monotonicity step:

Lemma cost_fast_le : forall n d : nat,
  (d <= n)%nat -> (cost_fast n d <= cost_naive n d)%nat.
Proof.
  intros n d Hdn.
  unfold cost_fast, cost_naive, mulcost.
  apply Nat.add_le_mono.
  - rewrite (Nat.mul_comm d n).
    apply Nat.mul_le_mono_l.
    exact Hdn.
  - apply Nat.mul_le_mono_r.
    apply Nat.mul_le_mono_l.
    exact Hdn.
Qed.

Walking it: unfold turns both counts into their sums of products, and Nat.add_le_mono splits the goal into the two term-by-term comparisons — first d*n*d <= n*d*n, then n*d*d <= n*n*d. In the first, Nat.mul_comm rewrites d*n to n*d so that both sides share the prefix n*d, after which Nat.mul_le_mono_l reduces the goal to d <= n. In the second the two sides already share the prefix n, so Nat.mul_le_mono_r peels off the trailing factor d and Nat.mul_le_mono_l the leading n, leaving d <= n again. The inequality is nonlinear in n and d, so it is assembled from these monotonicity lemmas rather than handed to a linear-arithmetic tactic.

The intermediate matrices compare the same way: the fast order’s is d×dd \times d against the naive order’s n×nn \times n.

Lemma intermediate_smaller : forall n d : nat,
  (d <= n)%nat -> (d * d <= n * n)%nat.
Proof.
  intros n d Hdn.
  exact (Nat.mul_le_mono d n d n Hdn Hdn).
Qed.

At a realistic size the ratio is worth seeing as literal numbers. With n=1024n = 1024 and d=64d = 64 the counts are in the hundreds of millions — past what Coq’s unary natural numbers can hold in memory — so the concrete checks are transported into the binary numbers N by a proved transfer lemma first, and there reflexivity settles them:

Example cost_naive_1024_64 : N.of_nat (cost_naive 1024 64) = 134217728%N.
Proof.
  rewrite (cost_naive_toN 1024 64).
  reflexivity.
Qed.

Example cost_fast_1024_64 : N.of_nat (cost_fast 1024 64) = 8388608%N.
Proof.
  rewrite (cost_fast_toN 1024 64).
  reflexivity.
Qed.

134 million multiplications against 8 million: a factor of n/d=16n/d = 16.

For a single vector, no product at all

There is a stronger version of the same idea. If what you want is not the layer’s matrix but its effect on one coordinate vector w, then neither product needs forming. A matrix applied to a coordinate vector is mat_vec, and mat_vec_mul says that applying a product is applying the factors in turn; used twice, it unwinds the whole layer into a pipeline:

  Theorem attention_pipeline : forall w : Fin.t d -> F,
    mat_vec attention_naive w == mat_vec Q (mat_vec (mat_transpose K) (mat_vec V w)).
  Proof.
    intros w i.
    calc (mat_vec attention_naive w i)
      == (mat_vec (mat_mul Q (mat_transpose K)) (mat_vec V w) i)
      == (mat_vec Q (mat_vec (mat_transpose K) (mat_vec V w)) i).
    - exact (mat_vec_mul n n d (mat_mul Q (mat_transpose K)) V w i).
    - exact (mat_vec_mul n d n Q (mat_transpose K) (mat_vec V w) i).
  Qed.

Walking it: intros w i fixes an output index, since two coordinate vectors are equal when they agree everywhere. The first calc step peels V off the outside of attention_naive’s product with mat_vec_mul, leaving the score matrix applied to mat_vec V w; the second peels mat_transpose K off in the same way. What is left is three matrix-vector applications — feed w through V, then K𝖳K^{\mathsf T}, then QQ — and no matrix-matrix product anywhere, not even the d×dd \times d one.

What the theorem does not cover

The layer here is linear attention. A transformer computes softmax(QK𝖳/d)⋅V\mathrm{softmax}(Q\,K^{\mathsf T}/\sqrt{d})\cdot V, with a softmax sitting between the score matrix and VV. Softmax is not linear, and with it in place the reassociation is simply invalid — VV cannot be slid inside it. Dropping the softmax, or replacing it by a linear kernel, is exactly what the linear-attention family of models does, and it is that linear core, and only it, that the equality above applies to. Nothing about softmax is defined or proved here.

Two further boundaries are worth naming. The cost model counts scalar multiplications performed by the algorithm the definitions denote; it says nothing about memory hierarchies, cache behaviour, or what any particular machine will do. And it is a count, not a measurement: cost_naive and cost_fast are separate definitions that a reader has to agree describe mat_mul, which is why the reasoning behind them is spelled out above rather than asserted.
