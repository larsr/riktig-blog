The derivative is a linear map

School calculus presents the derivative as a number: the slope. That reading does not survive contact with functions of several variables, where the answer has to record how the output moves for a push in any input direction. The definition that does survive is older and simpler than the slope, and it says: near a point, ff is a linear map plus an error that vanishes faster than the step.

The definition

LL is the derivative of ff at aa when LL is linear and

∥f(a+h)−(f(a)+L(h))∥≤ε∥h∥\|f(a + h) - \big(f(a) + L(h)\big)\| \leq \varepsilon\,\|h\|

for every ε>0\varepsilon > 0, once hh is small enough. Read the left-hand side as the error: what ff actually does, minus what the linear approximation predicted.

  Definition is_deriv (f : U -> V) (a : U) (L : LinearMap F U V) : Prop :=
    linear_map_bounded L /\
    forall eps : F, 0 < eps ->
      exists delta : F, 0 < delta /\
        forall h : U, ‖ h ‖ < delta ->
          ‖ f (a + h) + - (f a + L h) ‖ <= eps * ‖ h ‖.

Three things about this. The derivative is a LinearMap — the object from the linear-algebra posts, carrying its own proof of linearity — rather than a number. It is required to be bounded, the condition the continuity post introduced, so that the approximation is a well-behaved map and not merely a linear one. And the error is compared to ε∥h∥\varepsilon\|h\| rather than to ε\varepsilon: what makes LL the derivative is not that the error is small, but that it is small relative to the step.

No dimension is mentioned. UU and VV are any normed spaces over the same ordered field, so this covers the school case (U=V=FU = V = F), vector-valued functions, functions on function spaces, and everything between.

What is a derivative of what

Two base cases, and both are as short as they should be. A constant function is approximated by the zero map, with no error at all:

  Theorem deriv_const : forall (v : V) (a : U),
    is_deriv (fun _ : U => v) a linear_map_const0.

and a linear map is its own derivative — the approximation is exact, so again the error is zero:

  Theorem deriv_lm : forall (g : LinearMap F U V) (a : U),
    linear_map_bounded g -> is_deriv (LinearMap.map g) a g.

In both proofs the exists 1 supplies a δ\delta that never has to be small, because the error is identically zero for every hh; the rest is the observation that ε∥h∥≥0\varepsilon \|h\| \geq 0.

The two closure theorems, deriv_add and deriv_scale, say differentiation respects the vector-space operations. Together with the previous post’s Hom_VectorSpace, that is the sentence “differentiable functions form a vector space and differentiation is linear on it”, proved rather than asserted.

The derivative is unique, and forces continuity

Two candidate derivatives at the same point agree — not just as approximations, but as maps:

  Theorem deriv_unique : forall (f : U -> V) (a : U)

which is what makes “the” derivative legitimate and, later, what makes a Jacobian matrix well defined. And differentiability is strictly stronger than continuity:

  Theorem deriv_continuous : forall (f : U -> V) (a : U)

If ff is within ε∥h∥\varepsilon\|h\| of f(a)+L(h)f(a) + L(h), and LL is bounded, then f(a+h)f(a+h) cannot escape far from f(a)f(a) when hh is small. The converse fails — the absolute value is continuous at 00 and has no derivative there — which is why these are two definitions rather than one.

The chain rule

The theorem that makes the linear-map view worth adopting — the chain rule:

  Theorem deriv_comp : forall (f : U -> V) (g : V -> W) (a : U)
      (Lf : LinearMap F U V) (Lg : LinearMap F V W),
    Proper (equ ==> equ) g ->
    is_deriv f a Lf -> is_deriv g (f a) Lg ->
    is_deriv (fun u : U => g (f u)) a (linear_map_comp Lg Lf).

Read the conclusion: the derivative of g∘fg \circ f is linear_map_comp Lg Lf, the composition of the two derivative maps. In one dimension composition of linear maps is multiplication of the numbers representing them, which is why the school rule says “multiply the derivatives”. The general statement is that you compose them, and the school rule is its one-dimensional shadow.

The proof is the longest in the file, and the reason is worth stating. The error of the composite has to be split into a part coming from gg’s error at f(a)f(a) and a part coming from ff’s error at aa pushed through gg’s bound, and each has to be held below half the target — so the ε/2\varepsilon/2 device from the limits post appears again, this time with both a δ\delta and a bound CgC_g to juggle.

Where coordinates finally appear

Everything above is coordinate-free. Partial derivatives are what you get when you choose a basis and feed the derivative one basis vector at a time:

  Definition partial_at {n : nat} {I : Type} {eI : EqRel I}
      {Ieq : EquDec I} {IFin : FinIndex n I} {Vl : HasLincomb I F U}
      (L : LinearMap F U V) (B : Basis n I F U)
      (i : I) : V :=
    L (Basis.vec B i).

That is the entire definition — the ii-th partial derivative is the derivative map applied to the ii-th basis vector. It follows immediately that partials do not depend on which derivative map you picked, since there is only one:

  Lemma partial_at_welldef : forall {n : nat} {I : Type} {eI : EqRel I}
      {Ieq : EquDec I} {IFin : FinIndex n I} {Vl : HasLincomb I F U}
      (f : U -> V) (a : U)
      (L1 L2 : LinearMap F U V) (B : Basis n I F U) (i : I),
    is_deriv f a L1 -> is_deriv f a L2 ->
    partial_at L1 B i == partial_at L2 B i.
  Proof.
    intros n I eI Ieq IFin Vl f a L1 L2 B i HD1 HD2.
    exact (deriv_unique f a L1 L2 HD1 HD2 (Basis.vec B i)).
  Qed.

One line, because uniqueness of the derivative was proved first. The comment above this section in the source reads “Coordinates enter here and nowhere above”, and that ordering is the point of the whole development: the analysis is done without a basis, and a basis is introduced only when someone wants numbers.
