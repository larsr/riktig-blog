A robot arm with no gimbal lock, built from chained rotors

The problem: naming an orientation without a singularity

A robot arm, in its simplest form, is a sequence of straight beams connected end to end by joints, each joint free to steer independently. The everyday question is: given every joint’s steering, where does the tip of the arm end up? Answering it needs, at every joint, a way to combine “how the arm is oriented so far” with “how much this next joint turns it” into a new “oriented so far” — and the same combining rule has to work whichever joint comes next, however far the chain has already turned.

The traditional way to name a three-dimensional orientation is with three numbers: a roll, a pitch, and a yaw, each an angle around one of three fixed axes, applied one after another. This works as a scheme for writing orientations down, but it has a well-known defect. At certain combinations of the three angles, two of the three rotation axes line up, and one whole degree of freedom of the arm’s local motion disappears from the description — a small steering change that should move the arm in some direction produces no local motion at all in that scheme’s numbers. Mechanical engineers call this gimbal lock, after the physical gimbal rings in which the failure was first noticed. It is not only a special-case problem, either: composing two orientations given as roll-pitch-yaw triples is not one uniform formula, but a trigonometric procedure whose shape depends on which angles are involved.

So the sharper question is: is there a representation of “orientation so far” for which combining two orientations is a single operation, defined for every pair, that gives the same accumulated orientation no matter how the combining is grouped? If such a representation exists, chaining any number of joints reduces to repeating one uniform step, with no configuration of steering values that ever needs special handling.

The formalization: a joint is a rotor, a chain is a product

An earlier post built exactly such a representation: the vectors of the plane, or of space, embed into a ring — a geometric algebra — in which a rotor, a unit element of a particular even-graded subring, turns a vector vv into another vector by the sandwich RvR̃R\,v\,\tilde R, with R̃\tilde R a fixed involution called reversal. Composing two turns, first RR then SS, is a single multiplication: S(RvR̃)S̃=(SR)vSR̃S\,(R\,v\,\tilde R)\,\tilde S = (SR)\,v\,\widetilde{SR} — so “orientation so far” is nothing more exotic than an element of the ring, and combining two of them is the ring’s own multiplication.

In the plane, Cl(2,0)\mathrm{Cl}(2,0)’s rotors are rotor c s := c*1 + s*e12 for a pair (c,s)(c,s) with c2+s2=1c^2+s^2=1 — no angle stored, just the pair. A joint of a planar arm records this pair together with the length of the beam that follows it:

Record Joint2 (F : Type) := mkJoint2 {
  joint2_c      : F;
  joint2_s      : F;
  joint2_length : F
}.

and a chain is a base-to-tip list of joints:

Definition Chain2 (F : Type) : Type := list (Joint2 F).

In space, a rotation needs an axis as well as an angle, so a single (c,s)(c,s) pair is not enough. A joint of a spatial arm instead records the four coefficients of a general even element of Cl(3,0)\mathrm{Cl}(3,0):

Record Joint3 (F : Type) := mkJoint3 {
  joint3_c      : F;
  joint3_b12    : F;
  joint3_b13    : F;
  joint3_b23    : F;
  joint3_length : F
}.

Its own rotor is rotor3 c b12 b13 b23 := mkC3 c 0 0 0 b12 b13 b23 0, generalizing rotor c s := mkCl2 c 0 0 s to the eight-coordinate carrier of Cl(3,0)\mathrm{Cl}(3,0):

  Definition rotor3 (c b12 b13 b23 : F) : C3 F := mkC3 c 0 0 0 b12 b13 b23 0.

rotor3’s zero coefficients on the three vector slots and the trivector slot are literal, not merely provable — every Joint3 denotes an even element of Cl(3,0)\mathrm{Cl}(3,0) by construction, and its three free bivector coefficients can point its rotation plane anywhere in space, unlike rotor c s, which is confined to the one plane spanned by e1,e2e_1, e_2.

A chain’s cumulative rotor can be computed two ways. Declaratively, it is the plain algebraic product of every joint’s own rotor, base to tip:

  Definition chain_rotor2 (joints : Chain2 F) : Cl2 F :=
    fold_right (fun j acc => rotor (joint2_c j) (joint2_s j) * acc) 1 joints.

Operationally, it is what a controller walking the chain joint by joint would actually compute — extend a running rotor by the next joint’s own rotor, one at a time:

  Fixpoint chain_orientation_from2 (orientation : Cl2 F) (joints : Chain2 F) : Cl2 F :=
    match joints with
    | [] => orientation
    | j :: rest =>
        chain_orientation_from2 (orientation * rotor (joint2_c j) (joint2_s j)) rest
    end.

These had better agree — that they do is the theorem carrying the “no gimbal lock” claim.

The proof: walking the chain equals multiplying it out

Theorem (chain_rotor_is_product2). Starting from any rotor RR and extending it operationally through a chain, one joint at a time, gives exactly RR multiplied by the chain’s own declarative product.

chain_orientation_from2(R,[j1,…,jn])=R⋅(rotor(j1)⋅rotor(j2)⋯rotor(jn)).\mathrm{chain\_orientation\_from2}(R,\,[j_1,\dots,j_n]) \;=\; R \cdot \big(\mathrm{rotor}(j_1)\cdot\mathrm{rotor}(j_2)\cdots\mathrm{rotor}(j_n)\big).

Theorem chain_rotor_is_product2 : forall (joints : Chain2 F) (orientation : Cl2 F),
  chain_orientation_from2 orientation joints == orientation * chain_rotor2 joints.
Proof.
  induction joints as [| j rest IH]; intros orientation.
  - calc (chain_orientation_from2 orientation [])
      == orientation
      == (orientation * 1)
      == (orientation * chain_rotor2 []).
    + rewrite (chain_orientation_from2_nil orientation). reflexivity.
    + symmetry. exact (right_identity orientation).
    + rewrite chain_rotor2_nil. reflexivity.
  - calc (chain_orientation_from2 orientation (j :: rest))
      == (chain_orientation_from2 (orientation * rotor (joint2_c j) (joint2_s j)) rest)
      == ((orientation * rotor (joint2_c j) (joint2_s j)) * chain_rotor2 rest)
      == (orientation * (rotor (joint2_c j) (joint2_s j) * chain_rotor2 rest))
      == (orientation * chain_rotor2 (j :: rest)).
    + rewrite (chain_orientation_from2_cons orientation j rest). reflexivity.
    + exact (IH (orientation * rotor (joint2_c j) (joint2_s j))).
    + exact (associative orientation (rotor (joint2_c j) (joint2_s j))
               (chain_rotor2 rest)).
    + rewrite chain_rotor2_cons. reflexivity.
Qed.

The proof is an induction on the joint list, matching the two definitions’ own recursion. calc opens the equational chain shown above it, machine-checked: each == line names the next expression, and the justification below (a rewrite, or an exact of the supporting fact) closes that one step. Write RR for the rotor the statement calls orientation. The base case, an empty chain, needs only that multiplying by the ring’s own unit 1 does nothing (right_identity, the generic law that every structure with a unit supplies) — an empty chain’s declarative product is 1, and walking an empty chain leaves RR untouched, so the two sides meet once RR is rewritten as R⋅1R\cdot 1. The inductive step is one application of the equally generic associative law, here at the multiplication of Cl(2,0)\mathrm{Cl}(2,0). The induction hypothesis IH is applied one step further in, at Rrotor(j)R\,\mathrm{rotor}(j) rather than at RR: walking the rest of the chain from there gives (Rrotor(j))P(R\,\mathrm{rotor}(j))\,P, writing PP for the declarative product of rest. Associativity regroups that as R(rotor(j)P)R\,(\mathrm{rotor}(j)\,P), and rotor(j)P\mathrm{rotor}(j)\,P is exactly the declarative product of the whole chain j :: rest. Nothing in this argument inspects what joint2_c j or joint2_s j actually are — the theorem holds for every steering value, because it only ever uses that * is total and associative.

The identical statement, chain_rotor_is_product3, holds for the spatial arm with C3 F’s ring standing in for Cl2 F’s:

  Theorem chain_rotor_is_product3 : forall (joints : Chain3 F) (orientation : C3 F),
    chain_orientation_from3 orientation joints == orientation * chain_rotor3 joints.

and its proof is the same induction, unchanged step for step — Cl(3,0)\mathrm{Cl}(3,0)’s rotors do not commute with each other the way Cl(2,0)\mathrm{Cl}(2,0)’s do, but the argument above never uses commutativity, only associativity and the unit laws, so nothing in it needs to change.

Why there is no gimbal lock

This is the answer to the opening problem. Extending a roll-pitch-yaw orientation by one more rotation behaves differently at different configurations — the formula for “combine these two orientations” is exactly where it breaks down when two axes line up. Extending a rotor chain by one more joint is, by chain_rotor_is_product2/chain_rotor_is_product3, always the same operation: multiply the running rotor by the new joint’s rotor on the right. Multiplication in Cl2 F or C3 F is total — an ordinary function defined on every pair of elements, with no configuration of steering values it fails to handle — and it is associative because that is one of the laws every Ring instance is required to satisfy, checked once for the whole algebra when Cl2_Ring/C3_Ring were built, not re-derived at each joint. A companion fact, chain_rotor2_is_rotor, sharpens the planar case further: the declarative product of any chain’s joints is always again of the exact shape rotor c s for some c, s — the type “orientation accumulated so far” never needs reinterpreting, however many joints came before.

From orientation to position: sandwiching, twice, is one sandwich

Knowing a joint’s cumulative rotor is only half the job — the arm’s geometry needs the direction that rotor points a beam in, which is the sandwich, not the bare rotor. chain_direction2 R := cl2_sandwich R beam_rest_direction2 applies the cumulative rotor R to a fixed local rest direction (beam_rest_direction2, the unit vector along e1e_1 — where a beam points when its own joint applies no steering) to get that beam’s direction in world coordinates.

Positions build up beam by beam: at each joint, extend the cumulative rotor exactly as chain_orientation_from2 does, then advance the running position by that joint’s own beam length along the freshly rotated direction. This only gives the right answer if sandwiching twice in a row is itself a single sandwich by the product of the two rotors — otherwise “accumulate the rotor, then sandwich once at the end” and “sandwich, then sandwich again” could disagree.

Lemma (cl2_sandwich_compose). Sandwiching by BB and then by AA is the same as sandwiching once by the product ABAB:

A(BxB̃)Ã=(AB)xAB̃.A\,(B\,x\,\tilde B)\,\tilde A \;=\; (AB)\,x\,\widetilde{AB}.

Lemma cl2_sandwich_compose : forall A B x : Cl2 F,
  cl2_sandwich A (cl2_sandwich B x) == cl2_sandwich (A * B) x.
Proof.
  intros A B x. unfold cl2_sandwich.
  calc (A * (B * x * cl2_reverse B) * cl2_reverse A)
    == (A * (B * x) * cl2_reverse B * cl2_reverse A)
      { (Cl2.mult_associative A (B * x) (cl2_reverse B)) }
    == (A * B * x * cl2_reverse B * cl2_reverse A)
      { (Cl2.mult_associative A B x) }
    == (A * B * x * (cl2_reverse B * cl2_reverse A))
      { (Cl2.mult_associative (A * B * x) (cl2_reverse B) (cl2_reverse A)) }
    == (A * B * x * cl2_reverse (A * B))
      { (cl2_reverse_anti A B) }.
Qed.

Unfolding cl2_sandwich on both sides turns the goal into a chain of three associativity regroupings (Cl2.mult_associative, sliding the parentheses until cl2_reverse B and cl2_reverse A sit next to each other), followed by one genuinely geometric fact reused from the earlier post: reversal is an anti-automorphism, AB̃=B̃Ã\widetilde{AB} = \tilde B\tilde A (cl2_reverse_anti), which turns the trailing cl2_reverse B * cl2_reverse A into cl2_reverse (A * B) and closes the chain. The spatial version, c3_rotate_compose, is the same four-step argument through c3_reverse_anti.

Using it: two arms, each folded through a full turn, checked by computation

The planar arm below has two joints, both of length 1. The first has rotor (1,0)(1,0) — no steering, the ring’s own unit — so its beam ends at (1,0)(1,0). The second has rotor (0,1)(0,1): since a rotor c+se12c+se_{12} sandwiches a vector at twice the angle it names (the earlier post’s cl2_sandwich_rotor_vec), this is a full 180°180° turn, and the arm folds straight back on itself:

Definition planar_arm_example : Chain2 Q :=
  [ mkJoint2 (1#1)%Q (0#1)%Q (1#1)%Q;
    mkJoint2 (0#1)%Q (1#1)%Q (1#1)%Q ].

Example planar_arm_positions :
  chain_positions2 (0 : Cl2 Q) planar_arm_example
  = [ Cl2.vec (plane_vector (1#1)%Q (0#1)%Q); Cl2.vec (plane_vector (0#1)%Q (0#1)%Q) ].
Proof. vm_compute. reflexivity. Qed.

Q, the rationals, is an ordinary OrderedField, so every definition above specializes to it directly with no extra work; vm_compute fully evaluates both sides — running the fold, the sandwiches, the accumulated positions — down to two literal coordinate pairs, and reflexivity confirms they match: the first beam’s tip at (1,0)(1,0), the second folding all the way back to the origin.

The spatial arm has the same two-joint shape: an unsteered first joint (beam ending at (1,0,0)(1,0,0)), then a second joint steered purely in the e12e_{12} plane — a 180°180° turn about the axis perpendicular to it — again of length 1:

Definition spatial_arm_example : Chain3 Q :=
  [ mkJoint3 (1#1)%Q (0#1)%Q (0#1)%Q (0#1)%Q (1#1)%Q;
    mkJoint3 (0#1)%Q (1#1)%Q (0#1)%Q (0#1)%Q (1#1)%Q ].

Example spatial_arm_positions :
  chain_positions3 (0 : C3 Q) spatial_arm_example
  = [ c3_vec (space_vector (1#1)%Q (0#1)%Q (0#1)%Q);
      c3_vec (space_vector (0#1)%Q (0#1)%Q (0#1)%Q) ].
Proof. vm_compute. reflexivity. Qed.

The result is the three-dimensional analogue of the planar one — the tip returns to the origin — reached by the identical machinery: no Euler angles, no case split on which axis anything happened to align with, only the chain’s rotors multiplied out and sandwiched onto a reference direction.
