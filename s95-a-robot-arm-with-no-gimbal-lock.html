A robot arm with no gimbal lock, built from chained rotors

The problem: naming an orientation without a singularity

A robot arm, in its simplest form, is a sequence of straight beams connected end to end by joints, each joint free to steer independently. The everyday question is: given every joint’s steering, where does the tip of the arm end up? Answering it needs, at every joint, a way to combine “how the arm is oriented so far” with “how much this next joint turns it” into a new “oriented so far” — and the same combining rule has to work whichever joint comes next, however far the chain has already turned.

The traditional way to name a three-dimensional orientation is with three numbers: a roll, a pitch, and a yaw, each an angle around one of three fixed axes, applied one after another. This works as a scheme for writing orientations down, but it has a well-known defect. At certain combinations of the three angles, two of the three rotation axes line up, and one whole degree of freedom of the arm’s local motion disappears from the description — a small steering change that should move the arm in some direction produces no local motion at all in that scheme’s numbers. Mechanical engineers call this gimbal lock, after the physical gimbal rings in which the failure was first noticed. It is not only a special-case problem, either: composing two orientations given as roll-pitch-yaw triples is not one uniform formula, but a trigonometric procedure whose shape depends on which angles are involved.

So the sharper question is: is there a representation of “orientation so far” for which combining two orientations is a single operation, defined for every pair, that gives the same accumulated orientation no matter how the combining is grouped? If such a representation exists, chaining any number of joints reduces to repeating one uniform step, with no configuration of steering values that ever needs special handling.

The formalization: a joint is a rotor, a chain is a product

An earlier post built exactly such a representation: the vectors of the plane, or of space, embed into a ring — a geometric algebra — in which a rotor, a unit element of a particular even-graded subring, turns a vector vv into another vector by the sandwich RvR̃R\,v\,\tilde R, with R̃\tilde R a fixed involution called reversal. Composing two turns, first RR then SS, is a single multiplication: S(RvR̃)S̃=(SR)vSR̃S\,(R\,v\,\tilde R)\,\tilde S = (SR)\,v\,\widetilde{SR} — so “orientation so far” is nothing more exotic than an element of the ring, and combining two of them is the ring’s own multiplication.

That description never said which ring. So the arm below does not either: it is written once, over a carrier A whose only assumed structure is a ring, a scalar action, and — where beams enter — an operation that reverses products. A joint records the element it steers by and the length of the beam that follows it:

Record Joint (F A : Type) := mkJoint {
  joint_rotor  : A;
  joint_length : F
}.

and a chain is a base-to-tip list of joints:

Definition Chain (F A : Type) : Type := list (Joint F A).

The assumptions arrive as section parameters, and there are no others — in particular, no dimension and no basis. For the orientation half of the arm they amount to a ring: an equality, the operations, and the laws relating them.

Section ChainOrientation.
  Context {F A : Type}.
  Context {Ae : EqRel A} {Az : Zero A} {Aa : HasAdd A} {An : HasNeg A}
          {Ao : One A} {Am : HasMult A}.
  Context {AR : Ring A}.

A chain’s cumulative rotor can be computed two ways. Declaratively, it is the plain algebraic product of every joint’s own rotor, base to tip:

  Definition chain_rotor (joints : Chain F A) : A :=
    fold_right (fun j acc => joint_rotor j * acc) 1 joints.

Operationally, it is what a controller walking the chain joint by joint would actually compute — extend a running rotor by the next joint’s own rotor, one at a time:

  Fixpoint chain_orientation_from (orientation : A) (joints : Chain F A) : A :=
    match joints with
    | [] => orientation
    | j :: rest => chain_orientation_from (orientation * joint_rotor j) rest
    end.

These had better agree — that they do is the theorem carrying the “no gimbal lock” claim.

The proof: walking the chain equals multiplying it out

Theorem (chain_rotor_is_product). Starting from any rotor RR and extending it operationally through a chain, one joint at a time, gives exactly RR multiplied by the chain’s own declarative product.

chain_orientation_from(R,[j1,…,jn])=R⋅(rotor(j1)⋅rotor(j2)⋯rotor(jn)).\mathrm{chain\_orientation\_from}(R,\,[j_1,\dots,j_n]) \;=\; R \cdot \big(\mathrm{rotor}(j_1)\cdot\mathrm{rotor}(j_2)\cdots\mathrm{rotor}(j_n)\big).

  Theorem chain_rotor_is_product : forall (joints : Chain F A) (orientation : A),
    chain_orientation_from orientation joints == orientation * chain_rotor joints.
  Proof.
    induction joints as [| j rest IH]; intros orientation.
    - calc (chain_orientation_from orientation [])
        == (orientation : A)
           { chain_orientation_from_nil }
        == (orientation * 1 : A)
           { right_identity }
        == (orientation * chain_rotor [] : A)
           { chain_rotor_nil }.
    - calc (chain_orientation_from orientation (j :: rest))
        == (chain_orientation_from (orientation * joint_rotor j) rest : A)
           { chain_orientation_from_cons }
        == ((orientation * joint_rotor j) * chain_rotor rest : A)
           { IH }
        == (orientation * (joint_rotor j * chain_rotor rest) : A)
           { associative }
        == (orientation * chain_rotor (j :: rest) : A)
           { chain_rotor_cons }.
  Qed.

The proof is an induction on the joint list, matching the two definitions’ own recursion. calc opens the equational chain shown above it, machine-checked: each == line names the next expression, and the justification in braces after it (the equation being rewritten with) closes that one step. Write RR for the rotor the statement calls orientation. The base case, an empty chain, needs only that multiplying by the ring’s own unit 1 does nothing (right_identity, the generic law that every structure with a unit supplies) — an empty chain’s declarative product is 1, and walking an empty chain leaves RR untouched, so the two sides meet once RR is rewritten as R⋅1R\cdot 1. The inductive step is one application of the equally generic associative law. The induction hypothesis IH is applied one step further in, at Rrotor(j)R\,\mathrm{rotor}(j) rather than at RR: walking the rest of the chain from there gives (Rrotor(j))P(R\,\mathrm{rotor}(j))\,P, writing PP for the declarative product of rest. Associativity regroups that as R(rotor(j)P)R\,(\mathrm{rotor}(j)\,P), and rotor(j)P\mathrm{rotor}(j)\,P is exactly the declarative product of the whole chain j :: rest. Nothing in this argument inspects what a joint’s rotor actually is — the theorem holds for every steering value, because it only ever uses that * is total and associative.

There is no second version of this theorem for space. The plane and space arms are the same development at two carriers, and choosing the carrier is all a caller does.

Choosing the carrier: two arms, one development

The plane algebra’s carrier, Cl F 2, stores one coefficient per blade — per subset of the two generators e1,e2e_1,e_2 — so an element has four coordinates: scalar, e1e_1, e2e_2, and the bivector e12e_{12}. A planar arm’s joints are the ones whose rotor is the even element rotor c s — coefficient cc on the scalar, ss on the bivector, zero on both vector slots:

Definition Joint2 (F : Type) : Type := Joint F (Cl F 2).
Definition Chain2 (F : Type) : Type := list (Joint2 F).
  Definition mkJoint2 (c s beam : F) : Joint2 F := mkJoint (rotor c s) beam.

In space, a rotation needs a plane as well as an angle, and one (c,s)(c,s) pair cannot name one. A joint of a spatial arm steers by a general even element of Cl(3,0)\mathrm{Cl}(3,0) instead — scalar plus the three bivectors e12,e13,e23e_{12},e_{13},e_{23}, built by the same recipe as rotor c s:

  Definition spinor (r b12 b13 b23 : F) : Cl F 3 :=
    mk3 r 0 0 0 b12 b13 b23 0.
  Definition mkJoint3 (r b12 b13 b23 beam : F) : Joint3 F :=
    mkJoint (spinor r b12 b13 b23) beam.

spinor’s zero coefficients on the three vector slots and the trivector slot are literal, not merely provable — every joint built this way denotes an even element of Cl(3,0)\mathrm{Cl}(3,0) by construction, and its three free bivector coefficients can point its rotation plane anywhere in space.

Two facts about the plane and space algebras have to be named for this to work at all, rather than re-declared. Impl/Clifford.v keeps one ring per Clifford signature deliberately private, so that a carrier bearing several signatures never leaves instance search a choice between them; Impl/PlaneRotor.v and Impl/SpaceRotor.v each name their own. Naming them again with Existing Instance — as opposed to writing a fresh instance with the same body, which is a different constant and would silently stop matching those files’ lemmas — is what makes the general theorems above apply here:

#[local] Existing Instance Plane_Ring.
#[local] Existing Instance Space_Ring.

Why a joint stores a pair and not an angle

A rotor in the plane of a bivector ee with e2=−1e^2 = -1 is c+sec + s\,e with c2+s2=1c^2+s^2=1, which is the point of the unit circle at some angle — so why does a joint not simply store the angle? The development does define the plane’s rotors from a chosen ee,

  Definition turn (c s : F) : A := c *: 1 + s *: e.

and their composition law is one line, because multiplying two points of that plane is the complex multiplication table:

  Lemma turn_mul : forall c1 s1 c2 s2 : F,
    turn c1 s1 * turn c2 s2 == turn (c1*c2 + - (s1*s2)) (c1*s2 + s1*c2).

and when the scalars carry a cos, a sin and an exponential satisfying Euler’s identity, the pair is an angle:

  Theorem turn_is_cexp : forall t : F,
    turn e (cos t) (sin t) == cexp (t *: e).

Over the rationals there is no such trigonometry, and not for want of searching. Euler’s identity plus cos⁡(−t)=cos⁡t\cos(-t)=\cos t and sin⁡(−t)=−sin⁡t\sin(-t)=-\sin t force t↦(cos⁡t,sin⁡t)t \mapsto (\cos t, \sin t) to be a group homomorphism from (ℚ,+)(\mathbb{Q},+) into the rational points of the unit circle. The source is a divisible group — every element is nn times another one for every nn — so its image is divisible too; the rational circle group is ℤ/4\mathbb{Z}/4 times a free abelian group, whose only divisible subgroup is trivial. So sin\sin would have to vanish identically, which the trigonometry laws forbid. The arm therefore stores the pair, which every field has, and reads it as an angle only over scalars that have one.

From orientation to position: sandwiching, twice, is one sandwich

Knowing a joint’s cumulative rotor is only half the job — the arm’s geometry needs the direction that rotor points a beam in, which is the sandwich, not the bare rotor. Reversal and the beam’s rest direction are parameters of the development, exactly as the algebra is:

  Definition arm_sandwich (R x : A) : A := R * x * reversal R.
  Definition beam_direction (R : A) : A := arm_sandwich R rest_direction.

Positions build up beam by beam: at each joint, extend the cumulative rotor exactly as chain_orientation_from does, then advance the running position by that joint’s own beam length along the freshly rotated direction.

  Fixpoint chain_positions_from (orientation position : A)
           (joints : Chain F A) : list A :=
    match joints with
    | [] => []
    | j :: rest =>
        let orientation' := orientation * joint_rotor j in
        let position' := position + joint_length j *: beam_direction orientation' in
        position' :: chain_positions_from orientation' position' rest
    end.

This only gives the right answer if sandwiching twice in a row is itself a single sandwich by the product of the two rotors — otherwise “accumulate the rotor, then sandwich once at the end” and “sandwich, then sandwich again” could disagree.

Lemma (arm_sandwich_compose). Sandwiching by BB and then by AA is the same as sandwiching once by the product ABAB:

A(BxB̃)Ã=(AB)xAB̃.A\,(B\,x\,\tilde B)\,\tilde A \;=\; (AB)\,x\,\widetilde{AB}.

On the blackboard this is two regroupings and one genuinely geometric fact: associativity slides the parentheses until B̃\tilde B and Ã\tilde A sit next to each other, and reversal being an anti-automorphism — it turns a product around, AB̃=B̃Ã\widetilde{AB} = \tilde B\tilde A — fuses them into AB̃\widetilde{AB}. Nothing in that argument mentions a dimension, a blade or even a vector: it holds in any ring carrying an operation that reverses products. So that is where it is proved, with the reversal as a parameter and its anti-automorphism law as a hypothesis:

  Theorem sandwich_compose_anti : forall R S x : A,
    R * (S * x * rev S) * rev R == (R * S) * x * rev (R * S).
  Proof.
    intros R S x.
    rewrite (rev_anti R S).
    rewrite !associative.
    reflexivity.
  Qed.

rev_anti turns RS̃\widetilde{RS} into S̃R̃\tilde S\tilde R and associative re-brackets both sides until they are the same five factors in the same order. The arm’s own version is that theorem handed the arm’s reversal:

  Theorem arm_sandwich_compose : forall R S x : A,
    arm_sandwich R (arm_sandwich S x) == arm_sandwich (R * S) x.
  Proof.
    intros R S x. unfold arm_sandwich.
    exact (sandwich_compose_anti reversal reversal_anti R S x).
  Qed.

What remains is to hand it a reversal that really does reverse products. Clifford reversal does, in every dimension at once — the sign it attaches to a blade of kk generators is k(k−1)/2k(k-1)/2 transpositions’ worth, and reversing a product of two blades differs from reversing each factor by exactly the swaps that carry one past the other:

  Lemma cl_reverse_mul : forall n (s : Signature F n) (x y : Cl F n),
    cl_reverse (cl_mul s x y) == cl_mul s (cl_reverse y) (cl_reverse x).

That lemma is what makes cl_reverse an instance of Reversal, the structure for an involutive anti-automorphism, and the plane’s and space’s own laws are then projections of it —

  Lemma reverse_anti2 : forall x y : Cl F 2,
    cl_reverse (x * y) == cl_reverse y * cl_reverse x.
  Proof. exact reversal_anti. Qed.

The alternative was to expand both sides coefficient by coefficient. In the plane that works — four blades, and ring closes the four polynomial identities. In space it does not: three unconstrained elements over eight blades means a polynomial in twenty-four unknown coefficients on each side, and expanding it needed nine gigabytes, enough to have the build killed. The version above compiles in a fraction of a second, and it compiles for the same reason — the statement was never about coefficients.

Using it: two arms, each folded through a full turn

Take an arm of two beams of equal length whose first joint does not steer at all and whose second turns the beam direction into its opposite. The first beam runs one length out from the base; the second runs one length back; the tip lands on the base. That argument used no coordinates, so the theorem does not either — the half turn enters as a single equation about the algebra, and which vectors the two positions are is left to the caller:

  Theorem arm_folds_back : forall (base tip back : A) (j1 j2 : Joint F A),
    joint_rotor j1 == 1 ->
    arm_sandwich (joint_rotor j2) rest_direction == - rest_direction ->
    joint_length j1 == joint_length j2 ->
    base + joint_length j1 *: rest_direction == tip ->
    base == back ->
    Forall2 equ (chain_positions base [j1; j2]) [tip; back].

The planar arm below is that arm at Cl Q 2, with both beams of length 1. Its first joint has rotor (1,0)(1,0) — no steering, the ring’s own unit — so its beam ends at (1,0)(1,0). Its second has rotor (0,1)(0,1): since a rotor c+se12c+se_{12} sandwiches a vector at twice the angle it names (an earlier post’s sandwich_rotor_vec), this is a 180°180° turn.

Definition planar_arm_example : Chain2 Q :=
  [ mkJoint2 (1#1)%Q (0#1)%Q (1#1)%Q;
    mkJoint2 (0#1)%Q (1#1)%Q (1#1)%Q ].

Example planar_arm_positions :
  Forall2 equ (chain_positions2 (0 : Cl Q 2) planar_arm_example)
    [ ga_vec (plane_vector (1#1)%Q (0#1)%Q); ga_vec (plane_vector (0#1)%Q (0#1)%Q) ].
Proof.
  apply (arm_folds_back cl_reverse beam_rest_direction2
           (cl_reverse_proper 2) (cl_reverse_one 2)).
  - exact rotor_one.
  - apply cl2_ext; vm_compute; reflexivity.
  - reflexivity.
  - apply cl2_ext; vm_compute; reflexivity.
  - apply cl2_ext; vm_compute; reflexivity.
Qed.

Q, the rationals, is an ordinary OrderedField, so every definition above specializes to it directly. The five bullets are the five hypotheses. The first is rotor_one, that (1,0)(1,0) is the algebra’s unit. The three vm_compute bullets are the only places where a dimension appears: an element of Cl Q 2 is a function from blades to coefficients, cl2_ext reduces an equation between two such functions to its four blade coefficients, and vm_compute evaluates each one down to a literal rational that reflexivity confirms — respectively, that a half turn reverses the rest direction, that one length along that direction from the origin is (1,0)(1,0), and that the origin is (0,0)(0,0). The remaining bullet is that the two beams have equal length.

The spatial arm has the same two-joint shape: an unsteered first joint (beam ending at (1,0,0)(1,0,0)), then a second joint steered purely in the e12e_{12} plane, again of length 1. Its proof is the same five bullets — the same general theorem, at the other carrier:

Definition spatial_arm_example : Chain3 Q :=
  [ mkJoint3 (1#1)%Q (0#1)%Q (0#1)%Q (0#1)%Q (1#1)%Q;
    mkJoint3 (0#1)%Q (1#1)%Q (0#1)%Q (0#1)%Q (1#1)%Q ].

Example spatial_arm_positions :
  Forall2 equ (chain_positions3 (0 : Cl Q 3) spatial_arm_example)
    [ ga_vec (space_vector (1#1)%Q (0#1)%Q (0#1)%Q);
      ga_vec (space_vector (0#1)%Q (0#1)%Q (0#1)%Q) ].
Proof.
  apply (arm_folds_back cl_reverse beam_rest_direction3
           (cl_reverse_proper 3) (cl_reverse_one 3)).
  - apply cl3_ext; vm_compute; reflexivity.
  - apply cl3_ext; vm_compute; reflexivity.
  - reflexivity.
  - apply cl3_ext; vm_compute; reflexivity.
  - apply cl3_ext; vm_compute; reflexivity.
Qed.

The result is the three-dimensional analogue of the planar one — the tip returns to the origin — reached by the identical machinery: no Euler angles, no case split on which axis anything happened to align with, only the chain’s rotors multiplied out and sandwiched onto a reference direction.

Why there is no gimbal lock

This is the answer to the opening problem. Extending a roll-pitch-yaw orientation by one more rotation behaves differently at different configurations — the formula for “combine these two orientations” is exactly where it breaks down when two axes line up. Extending a rotor chain by one more joint is, by chain_rotor_is_product, always the same operation: multiply the running rotor by the new joint’s rotor on the right. Multiplication in Cl F 2 or Cl F 3 is total — an ordinary function defined on every pair of elements, with no configuration of steering values it fails to handle — and it is associative because that is one of the laws every Ring instance is required to satisfy, checked once for the whole family of algebras when Cl_Ring was built, not re-derived at each joint.

Two further facts sharpen this, and both are proved once over the parameter algebra rather than twice over two dimensions. Joints whose rotors are even accumulate to an even rotor — that is the ℤ/2\mathbb Z/2 grading law, folded along the chain (chain_rotor_even); in the plane algebra an even element is again exactly of the shape rotor c s, so the type “orientation accumulated so far” never needs reinterpreting (chain_rotor2_is_rotor). And a chain of rotor joints accumulates to a rotor, whose sandwich preserves the quadratic form, so no chain, however folded, stretches a beam:

  Theorem beam_keeps_its_length : forall (joints : Chain F A) (w : V),
    one_faithful F A ->
    Forall (fun j => Rotor reversal even (joint_rotor j)) joints ->
    ga_vec w == beam_direction reversal (ga_vec rest) (chain_rotor joints) ->
    Q w == Q rest.

Rotor there is not a shape a joint happens to have — it is the definition of one, three equations in Structure/Rotor.v: the element lies in the even part, and its own reversal inverts it from either side. Everything the chain needs is read off those, so chain_is_rotor is four lines and mentions no dimension.
