Audit 2026-08-16: theories/Impl

A read-only pass over all 43 files of theories/Impl/, looking for the defects an implementation file can have that naming a concrete type is not: mathematics welded to one carrier, a general law re-derived by hand, a special case proved where a general theorem already exists, duplicated instances, and code nothing reaches. Thirty-three findings: 5 high (the mathematics is unreusable — a second implementation of the same structure would have to reprove it), 12 medium (duplicated work), 16 low (cosmetic or dead weight). The two largest concentrations are the blade/Clifford stack, where the sign cocycle and the sum over blades are both stated only about Vector.t bool n, and the determinant chain, where Impl/DetMulGeneral.v re-proves at Matrix n n F what Theory/Determinant.v proves for any alternating multilinear form — and is then never imported by anything.

1. Mathematical content trapped in the representation

theories/Impl/Blade.v:297 — bpar_cocycle, the file’s headline theorem, is a statement about a Z/2-valued 2-cochain on the group of finite subsets, but it is reached only through bpar_bxor_l/r, which are inductions on Vector.cons; a bitmask implementation of the same blade algebra would reprove all of it. Severity: high. Fix: state the cocycle over the abstract operations (empty set, symmetric difference, intersection, a Z/2-bilinear pairing) in Structure/+Theory/, and leave Blade.v as one instance of them.

theories/Impl/Blade.v:111,120,129,171,183 — bxor_involutive, bxor_comm, bxor_assoc, bxor_bempty_l, bxor_self are exactly the laws of the elementary abelian 2-group (Z/2)^n, proved by induction on n and never packaged: the file declares no instance of anything, so Theory/Group.v’s vocabulary is unavailable at Blade n and every later use spells the lemma name out. Severity: high. Fix: exhibit AbGroup (Blade n) with bxor/bempty and let the five lemmas become the instance’s fields.

theories/Impl/Blade.v:216,270,284 — bpar with bpar_bxor_l and bpar_bxor_r is a bilinear form over the two-element field, and the tree already has Impl/TwoElementField.v (bool is a Field) and Structure/Bilinear.v; here bi-additivity is two separate boolean case explosions. Severity: medium. Fix: read bpar as a BilinearMap bool (Blade n) (Blade n) bool and take additivity from the structure.

theories/Impl/Clifford.v:18,29,42,49,60,71,82,94,117,261,284 — bsum and its ten laws (bsum_ext, bsum_zero, bsum_add, bsum_mul_l/r, bsum_neg, bsum_swap, bsum_reindex, bsum_delta, bsum_delta_at) are one-for-one the bigopI laws of Theory/BigOp.v (bigopI_ext:683, bigopI_zero:694, bigopI_add:842, bigopI_mul_l:906, bigopI_neg:853, bigopI_swap:875, bigopI_reindex:797, bigopI_delta:1093), re-derived by recursion on n over the 2^n blades. Severity: high. Fix: give Blade n a FinIndex (2^n) (Blade n) instance (the enumeration is a Fixpoint, and Impl/FinIndex.v’s finindex_from_leibniz closes the NoDupA/InA side) and delete bsum in favour of bigopI.

theories/Impl/DetMulGeneral.v:120 — g_swap_antisym (an additive, alternating g : Matrix n n F -> F is antisymmetric under row_swap) is Theory/Determinant.v:445’s mf_swap_neg written out again for the matrix carrier with upd_row in place of upd, 75 lines instead of a citation. Severity: high. Fix: apply mf_swap_neg to the MultilinearForm that Impl/DetInterface.v:70 already builds.

theories/Impl/DetMulGeneral.v:334,375,504,579 — g_row_lincomb, row_expand, basis_rows_g_eq_detM_bound and basis_rows_g_eq_detM are the uniqueness of the determinant among alternating multilinear forms, stated as hypothesis bundles (Proper, additivity, alternation passed as arguments) over Matrix p n F rather than over the MultilinearForm / Alternating / Determinant classes of Structure/Determinant.v, which Impl/DetInterface.v shows detM satisfies. Severity: high. Fix: state uniqueness once in Theory/Determinant.v against those classes and have this file supply the instance.

theories/Impl/QR.v:259 — gram_schmidt_aux_orth_reconstruct is proved purely from the GramSchmidt class equations (gram_schmidt_aux_nil, gram_schmidt_aux_cons) plus inner-product laws, with no Fin and no matrix in sight, yet it lives in the QR file, so the list implementation’s other consumers cannot find it. Severity: medium. Fix: move it, with inner_sub_proj_eq:233, proj_coeffs:247 and neg_proj_coeff_scale:250, into Theory/GramSchmidt.v.

theories/Impl/MatrixNorm.v:15 — mat_norm is the L1 norm of a finite family, written as a nested bigopF at Matrix m n F only; the header’s justification for not using a generic construction (“the generic route would need a NormedSpace F F instance, which the tree deliberately does not have”) is contradicted by Impl/SeriesReals.v:47, which builds exactly that instance locally, and by Theory/MLDerivatives.v:10, which exports it. Severity: low. Fix: either state the L1 norm once over a FinIndex-indexed family of normed components, or correct the comment.

2. A general law re-derived by hand

theories/Impl/Clifford.v:1071 — e1_e2_anticommute cites the general polarization, then spends the surrounding six calc steps (right_identity, right_inverse, associative, zero_scale, left_identity) doing by hand what Theory/Group.v:7’s neg_unique_l already proves. Severity: medium. Fix: derive e1*e2 + e2*e1 == 0 in one chain and finish with neg_unique_l.

theories/Impl/QR.v:502 — solve_for_b : a == b + x -> b == a + - x is a group law proved inline in a Gram–Schmidt file, by the same right_identity/right_inverse/associative chain as neg_unique_l. Severity: medium. Fix: state it once in Theory/Group.v (or derive it from sub_add_cancel) and cite it.

theories/Impl/TrigSeries.v:168,171,174 — scale_mul_left, scale_mul_right and scale_mul_scale repeat Theory/Circular.v:17,21,24 verbatim, proof terms included, because the theory copies are locked behind a full Circular F A instance although they need only a ring with central scalars. Severity: medium. Fix: move the three lemmas to the theory of the weakest structure that states them (rule 13) and have both files cite them.

theories/Impl/DetMul.v:29 — cancel_unit (a unit is not a zero divisor) is a commutative-ring fact with no matrix content, stated inside the determinant-product section. Severity: low. Fix: move it to Theory/Ring.v.

3. A special case proved where a general theorem exists

theories/Impl/DetMul.v:789 — detM_mul_dec proves multiplicativity of detM under an extra EquDec F hypothesis, via Gaussian elimination, while the sibling Impl/DetMulGeneral.v:759 proves the same statement detM_mul with no decidability assumption at all. Severity: medium. Fix: keep the elimination machinery for what it computes (gauss_reduce, det_upper_triangular) and let detM_mul be the theorem.

theories/Impl/DetMul.v:850,856,866 — detM_mul_Q, det_comp_Q and det_basis_indep_Q are the same three statements at F := Q, obtained by feeding Q_EquDec to the weaker theorem; over a field with the general result available they carry no extra content. Severity: low. Fix: discharge Theory/Determinant.v:274’s detM_mul hypothesis with the general theorem and drop the _Q corollaries. FIXED: the hypothesis is discharged and the two endomorphism corollaries are deleted. detM_mul_Q stays as the witness that the elimination route runs at Q.

theories/Impl/Elim.v:633,727 — det_swap_F1_FS2 and det_eq_rows_F1_FS2 handle the rows 0 and 1 only, and their own comments say they are superseded by detM_swap_general (Impl/DetSignGeneral.v:165) and detM_alternating (Impl/DetAlternating.v:116), kept as “the historical first version”. Severity: medium. Fix: delete both, with the ~295 lines that serve only them (see §5).

theories/Impl/CliffordComplex.v:38 — even_mul_closed proves that a product of even elements is even at n = 2 (via rotor_mul), and Theory/SpaceRotor.v:147 proves the same statement again at n = 3 by enumerating eight blades; the general proof for every n and every signature is five lines from bparity_bxor (Impl/Blade.v:257), exactly the argument Impl/CliffordGrade.v:237’s cl_mul_vec_odd already uses. Severity: medium. Fix: prove cl_even x -> cl_even y -> cl_even (x * y) once next to cl_even in Impl/Clifford.v and delete both copies.

theories/Impl/Fin.v:869 — NoDup_map_FS is the Fin.FS instance of Impl/QR.v:307’s NoDup_map_inj_list, which is the general statement (any map injective on the list preserves NoDup) and is itself in the wrong file — a plain list fact inside a QR proof. Severity: low. Fix: put the general lemma in Lib/ListFacts.v and let Fin.v apply it.

theories/Impl/Orders.v:46,84 — the lexicographic order is built twice, once on pairs (Prod_HasOlt … Prod_DecTotalOrder, lines 46–79) and once on lists (list_olt … List_DecTotalOrder, lines 84–152), with structurally identical irreflexivity, transitivity and totality proofs. Severity: low. Fix: factor a lexicographic-step construction that both carriers apply.

theories/Impl/CliffordFin.v:56,175 — SelfDot_Inner and Cliff1_Inner, with their two hand-built InnerProductSpace records (lines 27–64 and 147–183), exist only so the two contraction lemmas can be phrased with norm2; the quadratic forms they duplicate, square_form and neg_form square_form, are already what the two GeometricAlgebra records use as Q. Severity: low. Fix: state trivial_contract and cliff1_ga_contract over square_form / neg_form square_form and delete both inner-product records.

4. Instance duplication

theories/Impl/Clifford.v:1028,1029 — Two_One := cl_one and Two_Mult := cl_mul sig2 at Cl F 2 are re-declared with identical bodies as Plane_One/Plane_Mult in Theory/PlaneRotor.v:14,15, which imports this file; both are #[local], so a goal stated with one set does not match a lemma proved with the other — the hazard Impl/CliffordComplex.v:13,14 documents and works around with #[local] Existing Instance. Severity: medium. Fix: declare the pair once, non-locally enough to be re-exported, and have PlaneRotor.v use Existing Instance on it as CliffordComplex.v does.

theories/Impl/Attention.v:102 — row2 is defined here with exactly the body of Impl/Matrix.v:202’s row2, which this file already has in scope through Theory.MatVec; the local definition silently shadows it, so a row2 from a matrix lemma and a row2 in an attention example are different constants. Severity: medium. Fix: delete the local copy.

theories/Impl/CliffordFin.v:185 — Cliff1_Scale : HasScale F (C F) is the tree’s only scaling on Impl/Complex.v’s carrier, yet it is declared #[export] from a Clifford file, together with the five scale laws (Cliff1_ScaleLaws:231) proved componentwise; Impl/CircleModel.v then has to export Impl.CliffordFin to get the scaling of C F. Severity: low. Fix: move the scaling and its laws next to the carrier in Impl/Complex.v.

What is clean

Impl/ListVS.v is the model for this whole layer: three homomorphism lemmas (nth0_add, nth0_neg, nth0_scale) and then every one of the sixteen laws transported through them in two lines, with not one list induction after line 177. Impl/Matrix.v, Impl/FinVec.v, Impl/GramSchmidt.v, Impl/VectCat.v and Impl/DetInterface.v are the same shape — define the operation, prove the equations, exhibit the instance, stop — and Impl/DetInterface.v in particular is what §1’s DetMulGeneral findings say the determinant work should have been routed through. Impl/Clifford.v parameterizes over the signature, so Cl(2), Cl(3) and Cl(1,3) genuinely are one construction at three values (sig2, sig3, sig13) and not three copies; Impl/CliffordComplex.v and Impl/CircleModel.v both open by re-using an existing instance with #[local] Existing Instance rather than declaring a fresh one, and say why in a comment. Impl/SeriesReals.v is exemplary on rule 5: it states precisely which theorems it does not prove, which axioms that would cost, and stops. No file in theories/Impl/ contains an Admitted, an admit, an Axiom, or a repeat split; simpl wall.
