Design rules

Numbered rules; a violation is a bug. Where prose is unclear, the named exemplar file is the authority. Decisions are stated, not narrated.

Program style

  1. Top level reads in the domain’s language — a pipeline of named stages, readable as a description of what the program does.
  2. Program-as-data. Argument parsing produces one Plan value; a small interpreter executes it. No behavior from scattered ifs.
  3. Errors are values; policy floats to the top. Lower layers never fudge; skip/retry/abort is a Plan field. Parse, don’t validate.
  4. No layer leakage. Lower layers stay parametrically polymorphic in their own vocabulary (a fetcher cannot know upper datatypes).
  5. Most general component wins. Use-case knowledge exists only at the composition point. Boilerplate means a concept is missing — factor the concept, don’t elaborate the handler.
  6. Recursive programs are one plain lambda term — fun, match, Fix, application — with obligations after: one refine, tuple matched once under a single convoy, if dec (..) conditions, all termination holes closed by one abstract lia line (abstract keeps lia’s large proof terms out of transparent definitions). Clause equations are derived via Fix_eq, without functional extensionality. No Program Fixpoint, no Equations plugin. Fuel only for interpreters of possibly-non-terminating input, never for structural recursion. Model: Programs/Merge.v. Grandfathered until their rewrite: Programs/BinarySearch.v, Quicksort.v, MergeSort.v.

Structure and proof style

Each rule keeps its number and one-line statement. Beneath it: the problem the rule prevents, a worked example quoted from the tree, and the decision. Where a decision was measured, the measurement is named.

  1. Four layers plus implementations.

    Problem: a fact filed in the wrong layer is found late or twice — an algorithm’s property buried in its program file cannot be imported without dragging the program’s dependencies along.

    Example — the merge program lives in Programs/Merge.v; its properties live in Theory/Merge.v, which opens by importing the program:

    From Riktig Require Export Lib.Calc Lib.MeasureInd Theory.Sorted.
Require Export Riktig.Programs.Merge.

    Fix: Ops.v: one operational class per symbol. Props.v: one law per class. Structure/: one structure per file, assembled from laws. Theory/: everything proved — and NO function definitions: an operation’s behavior is a class of equations (Theory/Fin.v’s Swap), the function and its instance live in Impl/ (Impl/Fin.v’s swap), and Theory reasons from the equations alone; to compute, import Impl. A Theory file stating lemmas about an Impl-owned concrete type (Fin.t, Matrix) is this rule’s violation in its most common form. Impl/: something to compute with (Z, Q, matrices, records) and every function definition. One file, one job. Programs/, Channel/, Lambda/, Examples/ are self-contained tracks; decidability reaches programs as plain = and stdlib sumbool, nothing from the algebra tower. Properties proved about a program go in Theory/ (Theory/Merge.v), except a track’s own example file (Programs/RobotArm/). Grandfathered pending migration (decided 2026-08-14, enumerated in docs/TODO.md): bigop/bigop_list/ bigopI and lincomb, upd/famEq, Theory/GramSchmidt.v, and the construction definitions (linear_map_comp, basis_transport) whose status awaits a ruling.

  2. Operational classes carry notation.

    Problem: proofs written against structure field projections read as plumbing, and a statement cannot even be written down before a full structure instance exists.

    Example — Ops.v attaches the notation to the operation class itself:

    Class HasAdd T := add : BinOp T.
Infix "+" := add.

    so x + y == y + x is a well-formed statement over any carrier with HasAdd and EqRel, before any structure is assembled.

    Fix: HasAdd/Zero/EqRel give +, 0, ==; proofs read like textbook derivations.

  3. Setoid discipline.

    Problem: without a Proper instance, rewrite refuses to rewrite under an operation, and the tempting escape — unfolding to the representation or the interpreter — welds the proof to one implementation.

    Example — Structure/Group.v makes respect for == a field of the structure, so rewriting under - works for every group:

        neg_proper       :: Proper (equ ==> equ) neg;

    Fix: everything respects == via Equivalence and Proper. Never prove a program property by unfolding an interpreter — the missing piece is an equivalence lemma.

  4. Each lemma is the most general statement of its fact.

    Problem: a side condition discharged inline is unnamed and invisible, so the same fact is re-derived at every use site.

    Example — Lib/NatFacts.v names the division bound once, with the reason it cannot be left to automation:

    (* `lia` treats `d / 2` as an arbitrary natural number, so the division
   bound has to be supplied to it rather than derived by it. *)
Lemma half_le d : d / 2 <= d.
Proof. apply Nat.Div0.div_le_upper_bound. lia. Qed.

    Fix: side conditions become named lemmas, not inline lia.

  5. Honest incompleteness.

    Problem: an undisclosed axiom or a bare Admitted silently weakens every theorem downstream of it.

    Example — Theory/SubspaceBasis.v opens with the disclosure, what forces it, and its limit:

    (* Two Coq.Logic axioms, disclosed: `Classical_Prop.classic` and
   `IndefiniteDescription.constructive_indefinite_description`.  The main
   induction case-splits on `exists v0, P v0 /\ ~ (c1 v0 == 0)`, an arbitrary
   Prop that nothing in Structure/Field.v makes decidable, and the witness
   becomes DATA — a vector of the basis list being built — so a bare
   existential is not enough.  Nothing here uses full choice or proof
   irrelevance. *)

    Fix: no Axiom (the tree has zero). An Admitted carries a proof sketch (the tree has zero). Stdlib axiom imports are disclosed in the file header (Theory/SubspaceBasis.v, Impl/CoqCat.v). Specs owe an equivalence proof to a canonical formulation.

  6. Imports point one way: implementations import theories, theories import interfaces, never the reverse.

    Problem: a Require added for one missing name makes instance visibility depend on who imported what in which order, and the failure appears far from its cause.

    Example — Impl/FinVec.v’s carrier is a function type, so the provider of its instances travels with it:

    From Riktig Require Export Structure.InnerProductSpace Theory.FieldVS
  Theory.BigOp Theory.Pointwise.

    and a require kept for position alone says so, Programs/ABNF/Parser.v:

    (* Structure.Monad/Theory.Monad go LAST so that the monadic [map]
   (Theory.Monad.map) shadows [List.map] at the [map digit_val p_digit]
   call sites below: Impl.Parser and Ast both (re-)export [List], and
   whichever module is imported last wins the bare name [map].  The
   line is a re-require of what Ast already exports, kept for its
   position alone. *)
From Riktig Require Export Structure.Monad Structure.Alternative Theory.Monad.

    Fix: require the deepest name, not the chain — every Structure/ file re-exports its parents. Chains are Require Export; a file whose exported vocabulary needs instances re-exports their provider (Impl/FinVec.v exports Theory.Pointwise). When resolution fails downstream, fix the missing Export, never a locality attribute. A require kept for position or deliberate shadowing carries a comment saying so (Programs/ABNF/Parser.v). A vocabulary dependency of a specification is allowed downward and documented (Structure/Basis.v on lincomb).

  7. Structure classes are assembled from law classes.

    Problem: a monolithic structure record restates its ancestors’ laws and turns its operations into projections that ring, Hint Rewrite and unification cannot see through.

    Example — Structure/Group.v is the exemplar; the whole shape is:

    Module Group.
  Class Group (G : Type) {eq : EqRel G} {zero : Zero G} {add : HasAdd G}
              {neg : HasNeg G} := {
    monoid           :: Monoid G;
    neg_proper       :: Proper (equ ==> equ) neg;
    is_left_inverse  :: LeftInverse G add neg 0;
    is_right_inverse :: RightInverse G add neg 0;
  }.
  Hint Mode Group ! - - - - : typeclass_instances.
  Hint Rewrite @left_inverse @right_inverse : algebra_db.
End Group.

    Fix, point by point:

    • Module-wrapped Class; Export M. after; qualification carries the structure name.
    • Operations are implicit op-class binders ({eq : EqRel G}), not fields. Measured reason: fields make the operations projections, and ring, Hint Rewrite and unification all degrade.
    • Substructure = first :: field (monoid :: Monoid G); law field = a Props.v class; respect law = a Proper field.
    • Hint Mode <C> ! - … : typeclass_instances, ! on the carrier only, written inside the module. ! anywhere else was measured to make instances unreachable.
    • A property is a class; a Record is data. Abstract structure is never a Record; plain records are concrete carriers in implementations (Impl/Complex.v, the C record).
    • Guarded laws take a named domain predicate (nonzero), never an unfolded description.
    • Export, not Notation, out of the module. Documented exception for field shadowing: Structure/Subspace.v.
    • Field lists are column-aligned per class.
    • Instance bodies: := {} when every field is found by search (PW_VectorSpace); a spelled-out literal stays when its fields name plain lemmas (Hom_ScaleLaws) — it carries information.
    • Locality: bare Instance at top level, #[export] inside a Section, #[global] nowhere (see rule 6). #[local] is deliberate and commented where it appears. A Section kept only to hold Context for one instance is hoisted; a Context shared by several declarations earns its keep.
    • Hint Rewrite on a law projection needs a monomorphic wrapper (Theory/Group.v’s grp database: add_left_identity etc.).

  8. Naming: full descriptive words, no abbreviations.

    Problem: an abbreviated name is a private code — grp_invl makes the reader decode what Group.left_inverse simply says.

    Example — a lemma that supplies a law field spells the law out, so both sides of := read alike; Theory/HomVS.v:

                Monoid.is_left_identity  := hom_left_identity;

    Fix: the module path carries the structure name (Group.left_inverse, never grp_invl). Substructure field = weaker structure’s lowercase name. Law field = is_ + the Props class (is_left_inverse); respect law = <op>_proper. Proofs invoke laws by the general Props.v projections (associative, left_identity, …), resolved by search at the structure in scope; a structure-qualified projection in a proof body is a defect unless two instances on one carrier need disambiguation (decided 2026-08-02). A law class instantiated away from its namesake operations is named for what it says there (Exp.add_to_mul, Alternative.fail_left_identity); ScaleLaws is named scaling wherever it appears as a field. A lemma that supplies a law field spells the law out, so both sides of := read alike (Monoid.is_left_identity := hom_left_identity, never hom_idl); _idl _idr _invl _invr _assoc _comm are the banned abbreviations. Names mirroring the Coq standard library keep its spelling (mat_mul_assoc, app_assoc), and _refl _sym _trans stay short for the same reason; _commutes is for two operations commuting with each other.

  9. A class states only the laws it adds.

    Problem: a restated inherited law gives search two instances of one fact, and a second generalizing binder over a shared scalar inserts a second Field F that unification cannot equate with the first.

    Example — Structure/Norm.v: one generalizing binder for the scalar chain, plain binders for everything that shares it:

      Class NormedSpace (F V : Type) `{OrderedField F}
      {Ve : EqRel V} {Vz : Zero V} {Va : HasAdd V} {Vn : HasNeg V}
      {Vs : HasScale F V} {VS : VectorSpace F V} {Vnorm : HasNorm F V} := {

    Fix: the weaker structure is its first :: field; nothing that field implies is restated (Magma 2 fields … Field 5). Structure over a different vocabulary is required ambiently instead: OrderedField takes `{Field F}; NormedSpace takes `{OrderedField F} and a plain {VS : VectorSpace F V} binder — plain, because a second generalizing binder would insert a second Field F. Exactly one bare generalizing binder per shared scalar. In a class definition the instance binders stay named ({aD : HasAdd D}), so a caller can pin one ((aD := …)); in a section Context a single carrier chain is bound by one generalizing binder (`{Basis n F V}), and only an additional carrier over the same scalar is spelled out (decided 2026-08-13). The binder blocks this still leaves are a known cost, kept because both measured alternatives lost — ExperimentalStyle/ holds the carrier-as-class and bundled-operations experiments with their verdicts.

  10. Equational proofs are calc chains (Lib/Calc.v).

    Problem: a raw rewrite script shows the tactics but not the terms, so checking it means replaying it; and in a term with several nested sums a bare rewrite hits the leftmost match, which may be the wrong occurrence.

    Example — Theory/Group.v, neg_unique_l: every intermediate term on the page, one justification per step, bare where the redex is unambiguous:

        calc h
      == (h + 0)          { right_identity  }
      == (h + (g + - g))  { right_inverse }
      == ((h + g) + - g)  { associative }
      == (0 + - g)        { Heq  }
      == (- g)            { left_identity  }.

    and neg_involutive, where one leading argument pins the intended occurrence:

        calc ((- g) + - - g)
      == (0 : G)      { (right_inverse (- g)) }
      == ((- g) + g)  { (left_inverse g)     }.

    Fix: one justification per step, not raw rewrite scripts. A step’s justification is the bare general projection when the rewrite is unambiguous ({ associative }), and otherwise carries the smallest prefix of arguments that selects the intended redex ({ (associative (- x)) }); full application is a last resort, not a default. The braced form stops at seven steps by design: name the intermediate object and split the chain. Step targets carry their carrier ascription ((… : Cl F 2)).

  11. Ring identities go to ring.

    Problem: spending calc steps on a rearrangement any reader would accept without comment buries the one step that carries the idea.

    Example — Theory/Field.v registers the commutative ring of a field once per section:

      Add Ring F_ring : (ring_theory_of_Ring (R := F) commutative).

    Fix: each section that needs it runs Add Ring <name> : (ring_theory_of_Ring (R := F) commutative) — section-local by necessity, and impossible on an abstract (possibly non-commutative) Ring. field likewise via field_theory_of_Field (Impl/Qf.v). Rule 10 never spends a calc step on what ring closes. The boundary: automation where the goal is decidable and the steps carry no insight; written steps where the rearrangement is the content; a recurring shape becomes a named lemma serving both readings.

  12. Comments explain Coq; the mathematics goes in a blog post.

    Problem: a comment that narrates the code or its history goes stale the first time the code moves, and a header essay repeats what the blog already owns.

    Example — Ops.v states the one fact the code cannot show, why the Hint Modes below it exist:

    (* Instance search may only fire once the carrier is known: parametric
   instances (e.g. the pointwise ones on X -> M) match a flexible goal
   like `EqRel ?T` with ?T := ?X -> ?M and recurse forever. *)

    Fix: a comment states the one fact the code cannot show — a Coq-ism, a workaround, a deliberate absence. Never a header essay, never what changed, never a restatement of the next line.

  13. A lemma lives in the theory of the weakest structure that states it.

    Problem: a fact proved about a field when a monoid suffices is invisible to every monoid that is not a field.

    Example — identity uniqueness needs no inverses, so it is stated once in Theory/Monoid.v and never restated for groups, rings or fields:

      Theorem id_unique : forall e f : M,
    (forall a, e + a == a) -> (forall a, a + f == a) -> e == f.

    Fix: before writing it, check ring doesn’t close it.

  14. The source reads like mathematics.

    Problem: an elaborator workaround pasted inline makes the reader parse Coq mechanics in the middle of a mathematical argument.

    Example — Theory/SubspaceBasis.v isolates one conversion behind a named lemma instead of a change in every proof that needs it:

    (* `cons_c_F1`/`cons_c_FS` hold by iota and are stated as `=`; this bridges
   them into `==`-typed goals. *)
Lemma eq_to_equ {T : Type} {e : EqRel T} {Eqv : Equivalence e} (a b : T) :
  a = b -> a == b.
Proof. intros ->. reflexivity. Qed.

    Fix: definitions are equational where an equational form exists; a forced dependent match … in … return appears once, and siblings are defined through it, never by repeating the annotation. Coq idiosyncrasies (convoy pattern, conversions the elaborator cannot see through) are isolated behind small named rewriting lemmas. A proof body needing change … with, cbn beta, or rewrite … at k means a supporting lemma is missing — add the lemma. No component-wise repeat split; simpl walls, no destruct case blowups.

  15. Search retrieves recorded isomorphisms, never constructs one.

    Problem: an isomorphism assembled by instance search is a choice nobody made, and closure instances at flexible carriers let search assemble candidates without terminating.

    Example — Structure/Realizes.v records the choice and pins both carriers rigid:

    (* The recording half of the isomorphism rule (Theory/VSIso.v): the
   Hint Mode demands both carriers rigid and by convention there is
   one instance per carrier pair, so search retrieves recorded
   choices and never constructs one. *)
    Hint Mode Realizes - ! ! - - - - - - - - - - - - - - - - - - - - : typeclass_instances.

    Fix: an isomorphism is a choice; an instance may record a chosen one (Structure/Realizes.v, the exemplar: rigid Hint Mode, one per carrier pair by convention) and search may return it. No reflexivity instance at a flexible carrier, no symmetry or transitivity instances, none mapping an isomorphism along a construction. Measured reason: the vsiso_refl divergence noted in Theory/VSIso.v.

The sandbox

DesignExample.v at the repository root is untracked, hand-compiled (coqc -Q theories Riktig DesignExample.v), and binding on nothing: a place to try structure shapes end to end before proposing them.

Blog contract (pointer)

One post per structure and one per program; the source file is the post’s thread; every identifier in prose links to its coqdoc page; every technical term gets an explanation and a Wikipedia link; friendly computer-science style, no hype register.
