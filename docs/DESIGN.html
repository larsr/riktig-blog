Design rules

Numbered rules; a violation is a bug. Where prose is unclear, the named exemplar file is the authority. Decisions are stated, not narrated.

Program style

  1. Top level reads in the domain’s language — a pipeline of named stages, readable as a description of what the program does.
  2. Program-as-data. Argument parsing produces one Plan value; a small interpreter executes it. No behavior from scattered ifs.
  3. Errors are values; policy floats to the top. Lower layers never fudge; skip/retry/abort is a Plan field. Parse, don’t validate.
  4. No layer leakage. Lower layers stay parametrically polymorphic in their own vocabulary (a fetcher cannot know upper datatypes).
  5. Most general component wins. Use-case knowledge exists only at the composition point. Boilerplate means a concept is missing — factor the concept, don’t elaborate the handler.
  6. Recursive programs are one plain lambda term — fun, match, Fix, application — with obligations after: one refine, tuple matched once under a single convoy, if dec (..) conditions, all termination holes closed by one abstract lia line (abstract keeps lia’s large proof terms out of transparent definitions). Clause equations are derived via Fix_eq, without functional extensionality. No Program Fixpoint, no Equations plugin. Fuel only for interpreters of possibly-non-terminating input, never for structural recursion. Model: Programs/Merge.v. Grandfathered until their rewrite: Programs/BinarySearch.v, Quicksort.v, MergeSort.v.

Structure and proof style

  1. Four layers plus implementations. Ops.v: one operational class per symbol. Props.v: one law per class. Interface/: one structure per file, assembled from laws. Theory/: everything proved, including transfer constructions (Theory/Pointwise.v, Theory/HomVS.v) and canonical generic algorithms (Theory/BigOp.v, Theory/GramSchmidt.v). Impl/: something to compute with (Z, Q, matrices, records). One file, one job. Programs/, Channel/, Lambda/, Examples/ are self-contained tracks; decidability reaches programs as plain = and stdlib sumbool, nothing from the algebra tower. Properties proved about a program go in Theory/ (Theory/Merge.v), except a track’s own example file (Programs/RobotArm/).
  2. Operational classes carry notation. HasAdd/Zero/EqRel give +, 0, ==; proofs read like textbook derivations.
  3. Setoid discipline. Everything respects == via Equivalence and Proper. Never prove a program property by unfolding an interpreter — the missing piece is an equivalence lemma.
  4. Each lemma is the most general statement of its fact. Side conditions become named lemmas, not inline lia.
  5. Honest incompleteness. No Axiom (the tree has zero). An Admitted carries a proof sketch (the tree has zero). Stdlib axiom imports are disclosed in the file header (Theory/SubspaceBasis.v, Impl/CoqCat.v). Specs owe an equivalence proof to a canonical formulation.
  6. Imports point one way: implementations import theories, theories import interfaces, never the reverse. Require the deepest name, not the chain — every Interface/ file re-exports its parents. Chains are Require Export; a file whose exported vocabulary needs instances re-exports their provider (Impl/FinVec.v exports Theory.Pointwise: its carrier is a function type). When resolution fails downstream, fix the missing Export, never a locality attribute. A require kept for position or deliberate shadowing carries a comment saying so (Programs/ABNF/Parser.v). A vocabulary dependency of a specification is allowed downward and documented (Interface/Basis.v on lincomb).
  7. Structure classes are assembled from law classes. The shape, with Interface/Group.v as exemplar:
    • Module-wrapped Class; Export M. after; qualification carries the structure name.
    • Operations are implicit op-class binders ({eq : EqRel G}), not fields. Measured reason: fields make the operations projections, and ring, Hint Rewrite and unification all degrade.
    • Substructure = first :: field (monoid :: Monoid G); law field = a Props.v class; respect law = a Proper field.
    • Hint Mode <C> ! - … : typeclass_instances, ! on the carrier only, written inside the module. ! anywhere else was measured to make instances unreachable.
    • A property is a class; a Record is data. Abstract structure is never a Record; plain records are concrete carriers in implementations (Impl/Complex.v, the C3 record).
    • Guarded laws take a named domain predicate (nonzero), never an unfolded description.
    • Export, not Notation, out of the module. Documented exception for field shadowing: Interface/Subspace.v.
    • Field lists are column-aligned per class.
    • Instance bodies: := {} when every field is found by search (PW_VectorSpace); a spelled-out literal stays when its fields name plain lemmas (Hom_ScaleLaws) — it carries information.
    • Locality: bare Instance at top level, #[export] inside a Section, #[global] nowhere (see rule 6). #[local] is deliberate and commented where it appears. A Section kept only to hold Context for one instance is hoisted; a Context shared by several declarations earns its keep.
    • Hint Rewrite on a law projection needs a monomorphic wrapper (Theory/Group.v’s grp database: add_left_identity etc.).
  8. Naming: full descriptive words, no abbreviations. The module path carries the structure name (Group.left_inverse, never grp_invl). Substructure field = weaker structure’s lowercase name. Law field = is_ + the Props class (is_left_inverse). Respect law = <op>_proper (neg_proper, quad_proper). Props’ own projections (associative, left_identity, …) stay short — they are the vocabulary calc steps use. Exceptions, when a law class is instantiated away from its namesake operations and the class name alone would misstate the law: Exp.add_to_mul, Alternative.fail_left_identity. ScaleLaws is a mixin, named scaling wherever it appears.
  9. A class states only the laws it adds. The weaker structure is its first :: field; nothing that field implies is restated (Magma 2 fields … Field 5). Structure over a different vocabulary is required ambiently instead: OrderedField takes `{Field F}; NormedSpace takes `{OrderedField F} and a plain {VS : VectorSpace F V} binder — plain, because a second generalizing binder would insert a second Field F. Exactly one bare generalizing binder per shared scalar.
  10. Equational proofs are calc chains (Lib/Calc.v), one justification per step, not raw rewrite scripts. The braced form stops at seven steps by design: name the intermediate object and split the chain. Step targets carry their carrier ascription ((… : Cl F 2)).
  11. Ring identities go to ring. Each section that needs it runs Add Ring <name> : (ring_theory_of_Ring (R := F) commutative) — section-local by necessity, and impossible on an abstract (possibly non-commutative) Ring. field likewise via field_theory_of_Field (Impl/Qf.v). Rule 10 never spends a calc step on what ring closes.
  12. Comments explain Coq; the mathematics goes in a blog post. A comment states the one fact the code cannot show — a Coq-ism, a workaround, a deliberate absence. Never a header essay, never what changed, never a restatement of the next line.
  13. A lemma lives in the theory of the weakest structure that states it. Before writing it, check ring doesn’t close it.
  14. The source reads like mathematics. Definitions are equational where an equational form exists; a forced dependent match … in … return appears once, and siblings are defined through it, never by repeating the annotation. Coq idiosyncrasies (convoy pattern, conversions the elaborator cannot see through) are isolated behind small named rewriting lemmas. A proof body needing change … with, cbn beta, or rewrite … at k means a supporting lemma is missing — add the lemma. No component-wise repeat split; simpl walls, no destruct case blowups.

The sandbox

DesignExample.v at the repository root is untracked, hand-compiled (coqc -Q theories Riktig DesignExample.v), and binding on nothing: a place to try structure shapes end to end before proposing them.

Blog contract (pointer)

One post per structure and one per program; the source file is the post’s thread; every identifier in prose links to its coqdoc page; every technical term gets an explanation and a Wikipedia link; friendly computer-science style, no hype register.
