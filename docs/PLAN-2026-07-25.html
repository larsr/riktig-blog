Wave L — blog link coverage and the check tool

Measured state (2026-07-25, on the built public/blog/)

The pipeline today: blog/coqdoc-index.py builds a TSV of unambiguous identifiers from the .glob files; the pandoc filter blog/coqdoc-links.lua turns single-identifier code spans into links to the coqdoc pages; blog/linkcheck.py verifies no link is dead.

What a parse of the generated HTML shows (inline code spans outside <a> and <pre>):

gap count cause
bare unambiguous names 0 already fully linked — the filter works
dotted Module.name spans (Group.left_inverse, …) 37 mentions, 18 distinct, 17 pages filter matches ^[%a_][%w_']*$ — no dots; index has no qualified keys. Grows with every wave below.

L1 — qualified names in the index

blog/coqdoc-index.py: in addition to the bare-name entries, emit a line per qualified name whenever the .glob records an enclosing module scope: Group.left_inverse<TAB>Riktig.Interface.Group.html#Group.left_inverse. Qualified keys collide far less; same ambiguity rule (-) if they do.

L2 — dotted spans in the filter

blog/coqdoc-links.lua: widen the identifier match to ^[%a_][%w_'.]*$ and look the whole dotted string up. Everything else unchanged — the filter still never invents a link.

L3 — ambiguity resolution per post

Change the index format so ambiguous names keep their candidate list instead of collapsing to - (repeat the key, one line per candidate; the lua side collects duplicates into a list). Add optional post front matter:

coqdoc-prefer:
  - Riktig.Programs.Merge
  - Riktig.Theory.Merge

When a bare name is ambiguous, the filter picks the candidate whose module is on the post’s prefer list (first match wins); no match → left plain, as today. A post is normally about one or two files, so one short list per affected post resolves nearly all 144 mentions.

L4 — the checker: blog/linkcov.py

New script, run against public/blog/*.html + the index. Parses the HTML properly (html.parser tracking <a>/<pre> nesting — regexes miss pandoc’s wrapped <a\nhref=…> tags). Three findings, each printed as file: identifier ×count — hint:

  1. unlinked linkable code span — inline code span outside a link whose text is a bare-unambiguous or qualified index key. Catches filter regressions and NOLINK=1 output leaking to publish.
  2. ambiguous code span — inline code span whose text is a known name with several candidates and no coqdoc-prefer match. Hint lists the candidate modules to add to the post’s prefer list.
  3. prose identifier — a token outside code/links that exactly matches an index key and contains _ or a dot with a capitalised module prefix (high-precision heuristics only; plain words like run in prose stay out). Hint: backtick it.

Exit nonzero on any finding. Escape hatch for the rare mention that must not link: `foo`{.nolink} — the filter skips the class, the checker skips it too.

L5 — wire into make, drive to zero

  • Makefile: linkcov target; make the existing linkcheck target depend on it so the one habitual gate covers both dead links and missing links. No baseline/ratchet file: fix all current findings in the same change, then zero is the standing requirement.
  • Fix the current findings: the 37 dotted mentions vanish on rebuild once L1+L2 land; add coqdoc-prefer to the posts the checker lists (33 distinct names); backtick the ≥17 prose mentions.

Acceptance: make blog && make linkcheck green with linkcov at zero findings; temporarily renaming one identifier in a post makes it fail (test once, revert).

Stay as-is:

  • Single-method op/definitional classes: HasLe, HasAbs, HasNorm, HasBind, HasReturn, HasFail, HasAlt, Decidable, EqDec, DecEq — these ARE the ops; nothing to wrap.
  • Records (data carriers, per the Iso precedent): LinearMap, BilinearMap, MultilinearForm, Alternating, Basis, Determinant.

Decision point (Category family): Category bundles its ops (hom, id, comp) as fields by design — it is parameterised over obj, not over op classes, and that architecture stays. Module-wrapping still applies (prefix → module path: category_comp_assoc → Category.comp_assoc), and doing all nine classes keeps the file uniform. It is the widest single item (posts s11–s15, Impl/CoqCat.v and the category instances), so it runs last and can be dropped from scope independently if Lars prefers.

Per-class recipe (proven on Monoid…VectorSpace)

  1. Wrap class in Module X; drop the x_ prefix from field names; Notation X := X.X after End X.
  2. Ops embedded as :: fields move to implicit parameters.
  3. Below the module: membership/bridging instances (X_is_Y, Props instances, Proper instances), Existing Instance for anything that must self-register.
  4. Hint Mode with ! on carrier positions only, - elsewhere; count positions from the error message, never pad blind.
  5. Backtick binders must write the qualified name (`{X.X T} ) — the notation alias breaks implicit generalization.
  6. Constructor renames Build_X → X.Build_X; construction sites become record literals with law fields only.
  7. Known traps: partial Arguments lists reset unlisted implicits; apply X.field can anomaly on pointwise goals → fully-applied exact; abstract lia in anything transparent.
  8. Grep-verify: zero old-prefix names tree-wide (code, blog, docs); then full make -j from the changed file forward.
