Groups: undoing, and the cancellation trick

A monoid is a set with an associative combining operation + and a do-nothing element 0 — for example the integers under addition, or lists under concatenation. What a monoid does not promise is that you can undo a combination. Adding 3 to a number can be reversed by adding -3; concatenating a list cannot be reversed at all. A group is a monoid where every element has an undo.

The group axioms

To “undo” a means to have an element that cancels it back to the do-nothing element 0. The library names the undo operation - (unary negation) and asks for two laws: negating and then adding gives 0, in either order.

(−a)+a=0,a+(−a)=0.(-a) + a \;=\; 0, \qquad a + (-a) \;=\; 0.

Here is the whole structure, from Interface/Group.v:

Module Group.
  Class Group (G : Type) {Ge : EqRel G} {Gz : Zero G} {Ga : HasAdd G} {Gn : HasNeg G} := {
    equivalence    : Equivalence (@equ G _);
    associative    : forall x y w : G, (x + y) + w == x + (y + w);
    left_identity  : forall x     : G, 0 + x == x;
    right_identity : forall x     : G, x + 0 == x;
    left_inverse   : forall x     : G, (- x) + x == 0;
    right_inverse  : forall x     : G, x + (- x) == 0;
    add_proper     : forall x y : G, x == y -> forall u v : G, u == v -> (x + u) == (y + v);
    neg_proper     : forall x y : G, x == y -> (- x) == (- y)
  }.
End Group.
Notation Group := Group.Group.

The operations come in as class parameters — the monoid’s ==, 0, +, and now also a negation Gn from the HasNeg vocabulary class. The first six law fields are the monoid’s laws restated, followed by the two undo laws Group.left_inverse and Group.right_inverse, and the two respect laws (Group.add_proper, Group.neg_proper) that let == be rewritten under + and -. That a group is a monoid is registered once, just below the module, as a derived instance:

#[global] Instance Group_is_Monoid G {Ge : EqRel G} {Gz : Zero G} {Ga : HasAdd G} {Gn : HasNeg G}
  `{H : Group.Group G} : Monoid G := {|
    Monoid.equivalence    := Group.equivalence;
    Monoid.associative    := Group.associative;
    Monoid.left_identity  := Group.left_identity;
    Monoid.right_identity := Group.right_identity;
    Monoid.add_proper     := Group.add_proper
  |}.

It repackages five of the group’s fields as a monoid — no new proofs — and Coq applies it silently, so everything proved about monoids (associativity, the identity laws, id_unique from the previous post) is available for a group with no restatement. The two undo laws are additionally registered under the names invl and invr (their Props.v single-law classes), which is how the proofs below refer to them.

The class and its own laws live inside Module Group rather than carrying a group_ prefix on every field: left_inverse is a name every structure with an inverse operation wants (Field’s own inverse law wants it too), so writing it out fully as Group.left_inverse says exactly the same thing a prefix would, at the one or two places that name it directly, without inventing a new compound word. The final Notation Group := Group.Group means every other use of Group in this tree — `{Group G}, Instance Z_Group : Group Z, and so on — is completely unaffected; only direct references to the law fields change.

Cancellation on the left

The first thing undo buys you is cancellation: if a + b == a + c, then b == c. In ordinary arithmetic this is obvious, but notice the proof uses nothing except the group laws — so it holds in every group, including ones where the elements are not numbers at all (matrices, symmetries, functions under composition). The idea is to add -a on the left of both sides and let the laws collapse it:

b=0+b{left identity}=(−a+a)+b{left undo}=−a+(a+b){associativity}=−a+(a+c){hypothesis a+b=a+c}=(−a+a)+c{associativity}=0+c{left undo}=c{left identity}\begin{aligned} b &= 0 + b &&\{\text{left identity}\}\\ &= (-a + a) + b &&\{\text{left undo}\}\\ &= -a + (a + b) &&\{\text{associativity}\}\\ &= -a + (a + c) &&\{\text{hypothesis } a + b = a + c\}\\ &= (-a + a) + c &&\{\text{associativity}\}\\ &= 0 + c &&\{\text{left undo}\}\\ &= c &&\{\text{left identity}\} \end{aligned}

Here is the proof verbatim from Theory/Group.v:

Theorem cancel_l : forall a b c : G, a + b == a + c -> b == c.
Proof.
  intros a b c Heq.
  calc b
    == (0 + b)          { idl  }
    == ((- a + a) + b)  { invl }
    == (- a + (a + b))  { assoc }
    == (- a + (a + c))  { Heq  }
    == ((- a + a) + c)  { assoc }
    == (0 + c)          { invl }
    == c                { idl  }.
Qed.

The calc block is the blackboard chain above, written out and machine-checked: it reads b == (0 + b) == ... == c, and each { ... } names the single law that turns one line into the next. Walking it step by step, each step matching one equality on the blackboard:

  • == (0 + b) { idl } — insert a 0 on the left, by the left-identity law idl read backwards.
  • == ((- a + a) + b) { invl } — expand that 0 into -a + a, the left-undo law invl.
  • == (- a + (a + b)) { assoc } — reassociate, so a + b appears as a block. This is associativity, assoc.
  • == (- a + (a + c)) { Heq } — replace a + b by a + c, the hypothesis Heq we were given.
  • == ((- a + a) + c) { assoc } — reassociate the other way, so -a + a is a block again.
  • == (0 + c) { invl } — collapse -a + a back to 0.
  • == c { idl } — drop the 0, and the goal b == c is reached.

The whole proof is the blackboard calculation, one law per line, with no appeal to what the elements actually are. Cancelling on the right is the mirror image — from b + a == c + a conclude b == c — and its proof is the same moves reflected, adding -a on the right and using invr/idr where the left version used invl/idl:

b=b+0{right identity}=b+(a+(−a)){right undo}=(b+a)+(−a){associativity}=(c+a)+(−a){hypothesis b+a=c+a}=c+(a+(−a)){associativity}=c+0{right undo}=c{right identity}\begin{aligned} b &= b + 0 &&\{\text{right identity}\}\\ &= b + (a + (-a)) &&\{\text{right undo}\}\\ &= (b + a) + (-a) &&\{\text{associativity}\}\\ &= (c + a) + (-a) &&\{\text{hypothesis } b + a = c + a\}\\ &= c + (a + (-a)) &&\{\text{associativity}\}\\ &= c + 0 &&\{\text{right undo}\}\\ &= c &&\{\text{right identity}\} \end{aligned}

Theorem cancel_r : forall a b c : G, b + a == c + a -> b == c.
Proof.
  intros a b c Heq.
  calc b
    == (b + 0)          { idr  }
    == (b + (a + - a))  { invr }
    == ((b + a) + - a)  { assoc }
    == ((c + a) + - a)  { Heq  }
    == (c + (a + - a))  { assoc }
    == (c + 0)          { invr }
    == c                { idr  }.
Qed.

Double negation

A short one that reuses cancellation. Negating twice returns the original element: - (- g) == g. The reason is that -g has exactly one undo, and both - - g and g qualify, since each adds to -g to give 0. To turn “both undo -g” into “they are equal”, cancel the shared -g:

(−g)+(−(−g))=0{right undo at −g}=(−g)+g{left undo at g}(-g) + (-(-g)) \;=\; 0 \quad\{\text{right undo at } -g\}\quad =\; (-g) + g \quad\{\text{left undo at } g\}

and cancelling -g from the left leaves --g == g. In Coq, from Theory/Group.v:

Theorem neg_involutive : forall g : G, - (- g) == g.
Proof.
  intros g.
  apply (cancel_l (- g)).
  calc ((- g) + - - g)
    == (0 : G)      { (invr (- g)) }
    == ((- g) + g)  { (invl g)     }.
Qed.
  • apply (cancel_l (- g)) uses the theorem just proved: to show - - g == g, it is enough to show (- g) + - - g == (- g) + g. That is the new goal.
  • == (0 : G) { (invr (- g)) } — the left side (- g) + - - g is -g plus its own negation, which is 0 by the right-undo law invr at the element -g.
  • == ((- g) + g) { (invl g) } — and 0 is (- g) + g by the left-undo law invl at g. The two sides meet at 0, so they are equal and cancel_l finishes the job.

Any additive map preserves zero and negation, for free

The last section of Theory/Group.v proves something once that would otherwise be re-proved for every operation in the library. Take any map f between two groups that preserves addition — f (a + b) == f a + f b. Such a map automatically preserves 0 and negation as well, with no extra hypotheses. The setup fixes f and its two properties:

  Context (f : G -> K).
  Context `{fp : Proper _ (equ ==> equ) f}.
  Context (fadd : forall a b : G, f (a + b) == f a + f b).

fp says f respects equality; fadd is the addition-preserving law. The backtick before {fp : ...} marks it as a typeclass-style argument rather than a plain one: whoever calls hom_zero doesn’t have to supply fp by hand, as long as a matching Proper fact is registered as an instance for their particular f. That f 0 == 0 then follows. The argument: f 0 added to itself equals f 0, and the only element that is unchanged by adding f 0 is 0, so cancel one copy of f 0:

f0+f0=f(0+0){f preserves +}=f0{left identity}=f0+0{right identity}f\,0 + f\,0 \;=\; f(0 + 0) \quad\{f \text{ preserves } +\}\quad =\; f\,0 \quad\{\text{left identity}\}\quad =\; f\,0 + 0 \quad\{\text{right identity}\}

  Theorem hom_zero : f 0 == 0.
  Proof.
    apply (cancel_l (f 0)).
    calc (f 0 + f 0)
      == (f (0 + 0)) { (fadd 0 0) }
      == (f 0)       { idl }
      == (f 0 + 0)   { idr }.
  Qed.

Notice this proof reuses cancel_l, proved two sections up: apply (cancel_l (f 0)) reduces the goal f 0 == 0 to f 0 + f 0 == f 0 + 0. Then the chain: f 0 + f 0 == f (0 + 0) by fadd (backwards); f (0 + 0) == f 0 because 0 + 0 == 0 by the left-identity law idl inside f; and f 0 == f 0 + 0 by the right-identity law idr. Cancelling the shared f 0 leaves f 0 == 0. The companion lemma hom_neg, with statement forall a : G, f (- a) == - f a, preserves negation, and it in turn uses hom_zero.

The integers are a group

Every theorem above holds for any type the moment it is shown to satisfy Group. For the integers that takes one instance declaration, from Impl/Zr.v, with each undo law discharged by a standard-library fact:

#[global] Instance Z_Group : Group Z := {|
  Group.equivalence    := eq_equivalence;
  Group.associative    := fun a b c => eq_sym (Z.add_assoc a b c);
  Group.left_identity  := Z.add_0_l;
  Group.right_identity := Z.add_0_r;
  Group.left_inverse   := Z.add_opp_diag_l;
  Group.right_inverse  := Z.add_opp_diag_r;
  Group.add_proper     := ltac:(congruence);
  Group.neg_proper     := ltac:(congruence)
|}.

The monoid laws are discharged exactly as in the previous post (Z.add_0_l, Z.add_0_r, and Z.add_assoc flipped by eq_sym); the negation operation was named by Instance Z_Neg : HasNeg Z := Z.opp alongside the rest of Z’s vocabulary; and Z.add_opp_diag_l and Z.add_opp_diag_r are the standard library’s -a + a = 0 and a + -a = 0. The two respect laws hold for any eq-based equality, which is what the congruence tactic discharges. With this in scope, cancel_l, neg_involutive, hom_zero — all of the above — hold for the integers with no further proof.

For everyday goals the library also packages the group laws as a rewrite database named grp, oriented so that each rule strictly shrinks a term: identity elements disappear, a + -a collapses to 0, double negations cancel. Theory/Group.v checks it on small examples; here is one. The claim, in math, is that (0+(−(−g)))+0=g(0 + (-(-g))) + 0 = g for every group element gg — a left identity, a double negation, and a right identity, all removable:

  Example autorewrite_multi : forall g : G, (0 + - (- g)) + 0 == g.
  Proof. intros g. autorewrite with grp. reflexivity. Qed.

One autorewrite with grp erases all three redundancies in a single step, and reflexivity closes the goal g == g that remains — where a calc chain would have spent three justified lines.
