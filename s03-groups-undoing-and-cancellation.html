Groups: undoing, and the cancellation trick

A monoid is a set with an associative combining operation + and a do-nothing element 0 — for example the integers under addition, or lists under concatenation. What a monoid does not promise is that you can undo a combination. Adding 3 to a number can be reversed by adding -3; concatenating a list cannot be reversed at all. A group is a monoid where every element has an undo.

The group axioms

To “undo” a means to have an element that cancels it back to the do-nothing element 0. The library names the undo operation - (unary negation) and asks for two laws: negating and then adding gives 0, in either order.

(−a)+a=0,a+(−a)=0.(-a) + a \;=\; 0, \qquad a + (-a) \;=\; 0.

Here is the class — all of Interface/Group.v below its one import:

Module Group.
  Class Group (G : Type) {eq : EqRel G} {zero : Zero G} {add : HasAdd G}
              {neg : HasNeg G} := {
    monoid           :: Monoid G;
    neg_proper       :: Proper (equ ==> equ) neg;
    is_left_inverse  :: LeftInverse G add neg 0;
    is_right_inverse :: RightInverse G add neg 0;
  }.
  Hint Mode Group ! - - - - : typeclass_instances.
  Hint Rewrite @left_inverse @right_inverse : algebra_db.
End Group.
Export Group.

The operations come in as class parameters, one tiny vocabulary class per symbol: EqRel for the equality ==, Zero for 0, HasAdd for +, and now also HasNeg for the negation -. So Group G presupposes the operations and contributes only laws.

Of its four fields, only two are new laws. Group.is_left_inverse and Group.is_right_inverse hold the two undo laws, and neither is a freshly written equation: LeftInverse G add neg 0 is a class from Props.v, stating inverse a ⋆ a == unit for the operation, inverse and unit it is given, and its method is called left_inverse — which is the name every proof below cites. (The convention runs through the tree: a field holding a law is named is_ plus the law it holds.)

Everything else a group needs is in its first field. Group.monoid has type Monoid G: the monoid is not restated, it is held. And because the field is declared with :: rather than :, it is a typeclass instance the moment a group is in scope, so a proof about an arbitrary group can use associativity, the two identity laws, and every theorem derived from them — id_unique from the previous post, for one — with nothing said and nothing repackaged. Group.neg_proper plays the part for - that the monoid’s own Magma.op_proper plays for +: it says negation sends equal arguments to equal results, which is what Proper (equ ==> equ) neg spells out, and being an instance it lets rewrite fire underneath a -.

The lines after the class body are bookkeeping. Hint Mode keeps instance search from hunting for a group before the carrier is known; Hint Rewrite files the two new laws in a database, so autorewrite with algebra_db can use them uncited; and Export Group puts the class in scope under its short name, so every other use in the tree — `{Group G}, Instance Z_Group : Group Z — reads exactly as it would without the module wrapper. The wrapper is what lets the fields be called monoid and neg_proper instead of group_monoid and group_neg_proper: the prefix lives in the module path, and Group.monoid says it where it needs saying.

Cancellation on the left

The first thing undo buys you is cancellation: if a + b == a + c, then b == c. In ordinary arithmetic this is obvious, but notice the proof uses nothing except the group laws — so it holds in every group, including ones where the elements are not numbers at all (matrices, symmetries, functions under composition). The idea is to add -a on the left of both sides and let the laws collapse it:

b=0+b{left identity}=(−a+a)+b{left undo}=−a+(a+b){associativity}=−a+(a+c){hypothesis a+b=a+c}=(−a+a)+c{associativity}=0+c{left undo}=c{left identity}\begin{aligned} b &= 0 + b &&\{\text{left identity}\}\\ &= (-a + a) + b &&\{\text{left undo}\}\\ &= -a + (a + b) &&\{\text{associativity}\}\\ &= -a + (a + c) &&\{\text{hypothesis } a + b = a + c\}\\ &= (-a + a) + c &&\{\text{associativity}\}\\ &= 0 + c &&\{\text{left undo}\}\\ &= c &&\{\text{left identity}\} \end{aligned}

Here is the proof verbatim from Theory/Group.v:

Theorem cancel_l : forall a b c : G, a + b == a + c -> b == c.
Proof.
  intros a b c Heq.
  calc b
    == (0 + b)          { left_identity  }
    == ((- a + a) + b)  { left_inverse }
    == (- a + (a + b))  { associative }
    == (- a + (a + c))  { Heq  }
    == ((- a + a) + c)  { associative }
    == (0 + c)          { left_inverse }
    == c                { left_identity  }.
Qed.

The calc block is the blackboard chain above, written out and machine-checked: it reads b == (0 + b) == ... == c, and each { ... } names the single law that turns one line into the next. Walking it step by step, each step matching one equality on the blackboard:

  • == (0 + b) { left_identity } — insert a 0 on the left, by the left-identity law read backwards.
  • == ((- a + a) + b) { left_inverse } — expand that 0 into -a + a, the left-undo law.
  • == (- a + (a + b)) { associative } — reassociate, so a + b appears as a block. This is associativity, inherited through Group.monoid.
  • == (- a + (a + c)) { Heq } — replace a + b by a + c, the hypothesis Heq we were given.
  • == ((- a + a) + c) { associative } — reassociate the other way, so -a + a is a block again.
  • == (0 + c) { left_inverse } — collapse -a + a back to 0.
  • == c { left_identity } — drop the 0, and the goal b == c is reached.

The whole proof is the blackboard calculation, one law per line, with no appeal to what the elements actually are. Cancelling on the right is the mirror image — from b + a == c + a conclude b == c — and its proof is the same moves reflected, adding -a on the right and using the right-hand laws where the left version used the left-hand ones:

b=b+0{right identity}=b+(a+(−a)){right undo}=(b+a)+(−a){associativity}=(c+a)+(−a){hypothesis b+a=c+a}=c+(a+(−a)){associativity}=c+0{right undo}=c{right identity}\begin{aligned} b &= b + 0 &&\{\text{right identity}\}\\ &= b + (a + (-a)) &&\{\text{right undo}\}\\ &= (b + a) + (-a) &&\{\text{associativity}\}\\ &= (c + a) + (-a) &&\{\text{hypothesis } b + a = c + a\}\\ &= c + (a + (-a)) &&\{\text{associativity}\}\\ &= c + 0 &&\{\text{right undo}\}\\ &= c &&\{\text{right identity}\} \end{aligned}

Theorem cancel_r : forall a b c : G, b + a == c + a -> b == c.
Proof.
  intros a b c Heq.
  calc b
    == (b + 0)          { right_identity  }
    == (b + (a + - a))  { right_inverse }
    == ((b + a) + - a)  { associative }
    == ((c + a) + - a)  { Heq  }
    == (c + (a + - a))  { associative }
    == (c + 0)          { right_inverse }
    == c                { right_identity  }.
Qed.

Double negation

A short one that reuses cancellation. Negating twice returns the original element: - (- g) == g. The reason is that -g has exactly one undo, and both - - g and g qualify, since each adds to -g to give 0. To turn “both undo -g” into “they are equal”, cancel the shared -g:

(−g)+(−(−g))=0{right undo at −g}=(−g)+g{left undo at g}(-g) + (-(-g)) \;=\; 0 \quad\{\text{right undo at } -g\}\quad =\; (-g) + g \quad\{\text{left undo at } g\}

and cancelling -g from the left leaves --g == g. In Coq, from Theory/Group.v:

Theorem neg_involutive : forall g : G, - (- g) == g.
Proof.
  intros g.
  apply (cancel_l (- g)).
  calc ((- g) + - - g)
    == (0 : G)      { (right_inverse (- g)) }
    == ((- g) + g)  { (left_inverse g)     }.
Qed.
  • apply (cancel_l (- g)) uses the theorem just proved: to show - - g == g, it is enough to show (- g) + - - g == (- g) + g. That is the new goal.
  • == (0 : G) { (right_inverse (- g)) } — the left side (- g) + - - g is -g plus its own negation, which is 0 by the right-undo law at the element -g.
  • == ((- g) + g) { (left_inverse g) } — and 0 is (- g) + g by the left-undo law at g. The two sides meet at 0, so they are equal and cancel_l finishes the job.

Any additive map preserves zero and negation, for free

A section of Theory/Group.v proves something once that would otherwise be re-proved for every operation in the library. Take any map f between two groups that preserves addition — f (a + b) == f a + f b. Such a map automatically preserves 0 and negation as well, with no extra hypotheses. The setup fixes f and its two properties:

  Context (f : G -> K).
  Context `{fp : Proper _ (equ ==> equ) f}.
  Context (fadd : forall a b : G, f (a + b) == f a + f b).

fp says f respects equality; fadd is the addition-preserving law. The backtick before {fp : ...} marks it as a typeclass-style argument rather than a plain one: whoever calls hom_zero doesn’t have to supply fp by hand, as long as a matching Proper fact is registered as an instance for their particular f. That f 0 == 0 then follows. The argument: f 0 added to itself equals f 0, and the only element that is unchanged by adding f 0 is 0, so cancel one copy of f 0:

f0+f0=f(0+0){f preserves +}=f0{left identity}=f0+0{right identity}f\,0 + f\,0 \;=\; f(0 + 0) \quad\{f \text{ preserves } +\}\quad =\; f\,0 \quad\{\text{left identity}\}\quad =\; f\,0 + 0 \quad\{\text{right identity}\}

  Theorem hom_zero : f 0 == 0.
  Proof.
    apply (cancel_l (f 0)).
    calc (f 0 + f 0)
      == (f (0 + 0)) { (fadd 0 0) }
      == (f 0)       { left_identity }
      == (f 0 + 0)   { right_identity }.
  Qed.

Notice this proof reuses cancel_l, proved two sections up: apply (cancel_l (f 0)) reduces the goal f 0 == 0 to f 0 + f 0 == f 0 + 0. Then the chain: f 0 + f 0 == f (0 + 0) by fadd (backwards); f (0 + 0) == f 0 because 0 + 0 == 0 by the left-identity law inside f; and f 0 == f 0 + 0 by the right-identity law. Cancelling the shared f 0 leaves f 0 == 0. The companion lemma hom_neg, with statement forall a : G, f (- a) == - f a, preserves negation, and it in turn uses hom_zero.

The integers are a group

Every theorem above holds for any type the moment it is shown to satisfy Group. For the integers that takes one instance per law, each discharged by a standard-library fact, from Impl/Zr.v:

#[global] Instance Z_add_associative : Associative Z Z add add :=
  fun a b c => eq_sym (Z.add_assoc a b c).
#[global] Instance Z_add_left_identity : LeftIdentity Z Z add 0 := Z.add_0_l.
#[global] Instance Z_add_right_identity : RightIdentity Z Z add 0 := Z.add_0_r.
#[global] Instance Z_add_left_inverse : LeftInverse Z add neg 0 := Z.add_opp_diag_l.
#[global] Instance Z_add_right_inverse : RightInverse Z add neg 0 := Z.add_opp_diag_r.

The monoid laws are discharged exactly as in the previous post (Z.add_0_l, Z.add_0_r, and Z.add_assoc flipped by eq_sym); the negation operation was named by Instance Z_Neg : HasNeg Z := Z.opp alongside the rest of Z’s vocabulary; and Z.add_opp_diag_l and Z.add_opp_diag_r are the standard library’s -a + a = 0 and a + -a = 0. The structures themselves are then declared with no fields written at all:

#[global] Instance Z_Magma : Magma Z add := { Magma.equivalence := eq_equivalence }.
#[global] Instance Z_Semigroup : Semigroup Z add := {}.
#[global] Instance Z_Monoid : Monoid Z := {}.
#[global] Instance Z_Group : Group Z := {}.

An empty {} asks instance search to supply every field, and it finds the five laws above, the structure one level down, and the two Proper facts registered alongside them — Z_add_proper and Z_neg_proper, both discharged by congruence, since == at Z is Coq’s own equality and every function respects that. With this in scope, cancel_l, neg_involutive, hom_zero — all of the above — hold for the integers with no further proof.

For everyday goals the library also packages the group laws as a rewrite database named grp, oriented so that each rule strictly shrinks a term: identity elements disappear, a + -a collapses to 0, double negations cancel. Theory/Group.v checks it on small examples; here is one. The claim, in math, is that (0+(−(−g)))+0=g(0 + (-(-g))) + 0 = g for every group element gg — a left identity, a double negation, and a right identity, all removable:

  Example autorewrite_multi : forall g : G, (0 + - (- g)) + 0 == g.
  Proof. intros g. autorewrite with grp. reflexivity. Qed.

One autorewrite with grp erases all three redundancies in a single step, and reflexivity closes the goal g == g that remains — where a calc chain would have spent three justified lines.
