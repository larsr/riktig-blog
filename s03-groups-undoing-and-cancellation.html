Groups: undoing, and the cancellation trick

Adding 3 to an integer can be undone: add −3 and you are back where you started. Multiplying an integer by 0 cannot be undone at all. Both operations are associative and both have an identity element, so both give the integers the shape the previous post built — a monoid. What separates them is undoing, and a monoid in which every element can be undone is a group.

The extra guarantee is small and its consequences are not. In the multiplication monoid 0⋅3=0⋅50 \cdot 3 = 0 \cdot 5 while 3≠53 \neq 5, so a shared factor cannot be struck from an equation. In a group it always can. This post gives the structure, then the theorems that follow from it, each first as mathematics and then as the Coq that transcribes it.

The structure

A group is a set GG carrying an operation +:G×G→G+ : G \times G \to G, an element 0∈G0 \in G, and a map −:G→G- : G \to G, such that for all a,b,c∈Ga, b, c \in G

(a+b)+c=a+(b+c),0+a=a=a+0,(a + b) + c = a + (b + c), \qquad 0 + a = a = a + 0,

(−a)+a=0=a+(−a).(-a) + a = 0 = a + (-a).

The last line is the new one — an inverse for every element, on both sides. Here is the transcription, which is the whole of Structure/Group.v:

From Riktig.Structure Require Export Monoid.

Module Group.
  Class Group (G : Type) {eq : EqRel G} {zero : Zero G} {add : HasAdd G}
              {neg : HasNeg G} := {
    monoid           :: Monoid G;
    neg_proper       :: Proper (equ ==> equ) neg;
    is_left_inverse  :: LeftInverse G add neg 0;
    is_right_inverse :: RightInverse G add neg 0;
  }.
  Hint Mode Group ! - - - - : typeclass_instances.
  Hint Rewrite @left_inverse @right_inverse : algebra_db.
End Group.
Export Group.

Reading the transcription against the mathematics: the first two displayed lines are the monoid’s laws, and the class does not restate them — it holds a monoid, in the field monoid. The third line is the two new fields, is_left_inverse and is_right_inverse, filled from the law catalogue as LeftInverse G add neg 0, which unfolds to exactly (−a)+a=0(-a) + a = 0.

The other two lines have no counterpart on the blackboard. neg_proper is the licence to rewrite under −-, needed because == here is a chosen equality rather than Coq’s built-in one; Hint Mode restricts when instance search may go looking for a group. Both devices, and the :: that makes a field an instance, are explained in the Coq underneath; from here on they are plumbing to read past.

Cancellation

If a+b=a+ca + b = a + c then b=cb = c. Add −a-a on the left of both sides and let associativity do the rest:

b=0+b{identity}=((−a)+a)+b{inverse}=(−a)+(a+b){associativity}=(−a)+(a+c){the hypothesis}=((−a)+a)+c{associativity}=0+c{inverse}=c{identity}\begin{aligned} b &= 0 + b && \{\text{identity}\}\\ &= ((-a) + a) + b && \{\text{inverse}\}\\ &= (-a) + (a + b) && \{\text{associativity}\}\\ &= (-a) + (a + c) && \{\text{the hypothesis}\}\\ &= ((-a) + a) + c && \{\text{associativity}\}\\ &= 0 + c && \{\text{inverse}\}\\ &= c && \{\text{identity}\} \end{aligned}

  Theorem cancel_l : forall a b c : G, a + b == a + c -> b == c.
  Proof.
    intros a b c Heq.
    calc b
      == (0 + b)          { left_identity  }
      == ((- a + a) + b)  { left_inverse }
      == (- a + (a + b))  { associative }
      == (- a + (a + c))  { Heq  }
      == ((- a + a) + c)  { associative }
      == (0 + c)          { left_inverse }
      == c                { left_identity  }.
  Qed.

Seven steps on the blackboard, seven in the calc, in the same order; each { } names the law that licenses the step above it. The names cited are the general ones — left_identity, left_inverse, associative — and instance search resolves each at the structure in scope. cancel_r is the mirror image, with right_identity and right_inverse throughout.

An inverse is unique

If h+g=0h + g = 0 then h=−gh = -g. Nothing assumes hh was built by negating anything; combining to zero on one side is already enough.

h=h+0{identity}=h+(g+(−g)){inverse}=(h+g)+(−g){associativity}=0+(−g){the hypothesis}=−g{identity}\begin{aligned} h &= h + 0 && \{\text{identity}\}\\ &= h + (g + (-g)) && \{\text{inverse}\}\\ &= (h + g) + (-g) && \{\text{associativity}\}\\ &= 0 + (-g) && \{\text{the hypothesis}\}\\ &= -g && \{\text{identity}\} \end{aligned}

  Theorem neg_unique_l : forall g h : G, h + g == 0 -> h == - g.
  Proof.
    intros g h Heq.
    calc h
      == (h + 0)          { right_identity  }
      == (h + (g + - g))  { right_inverse }
      == ((h + g) + - g)  { associative }
      == (0 + - g)        { Heq  }
      == (- g)            { left_identity  }.
  Qed.

This is the workhorse for every later “that thing is the negative of this thing” claim: to prove x=−yx = -y, show x+y=0x + y = 0.

Double negation

−(−g)=g-(-g) = g. By cancellation it is enough to add −g-g in front of both sides, and then both sides are 00 read two different ways:

(−g)+(−(−g))=0=(−g)+g.(-g) + (-(-g)) = 0 = (-g) + g.

  Theorem neg_involutive : forall g : G, - (- g) == g.
  Proof.
    intros g.
    apply (cancel_l (- g)).
    calc ((- g) + - - g)
      == (0 : G)      { right_inverse }
      == ((- g) + g)  { left_inverse }.
  Qed.

apply (cancel_l (- g)) is the blackboard sentence “by cancellation it is enough to add −g-g in front”: it turns the goal - - g == g into the two-step chain. neg_zero (- 0 == 0) goes the same way, and neg_inj — negation is injective — is three steps of double negation.

−(a+b)=(−b)+(−a).-(a + b) = (-b) + (-a). The order reverses, because nothing here assumes the operation commutes. By uniqueness it is enough to check that (a+b)(a+b) and (−b)+(−a)(-b) + (-a) combine to zero:

(a+b)+((−b)+(−a))=((a+b)+(−b))+(−a){associativity}=(a+(b+(−b)))+(−a){associativity}=(a+0)+(−a){inverse}=a+(−a){identity}=0{inverse}\begin{aligned} (a + b) + ((-b) + (-a)) &= ((a + b) + (-b)) + (-a) && \{\text{associativity}\}\\ &= (a + (b + (-b))) + (-a) && \{\text{associativity}\}\\ &= (a + 0) + (-a) && \{\text{inverse}\}\\ &= a + (-a) && \{\text{identity}\}\\ &= 0 && \{\text{inverse}\} \end{aligned}

  Theorem neg_add_flip : forall a b : G, - (a + b) == (- b) + (- a).
  Proof.
    intros a b. symmetry. apply neg_unique_r.
    calc ((a + b) + (- b + - a))
      == (((a + b) + - b) + - a)  { associative }
      == ((a + (b + - b)) + - a) { associative }
      == ((a + 0) + - a)          { right_inverse }
      == (a + - a)                { right_identity }
      == (0 : G)                  { right_inverse }.
  Qed.

Every map that preserves addition preserves zero and negation

A map f:G→Kf : G \to K between groups with f(a+b)=f(a)+f(b)f(a + b) = f(a) + f(b) is a group homomorphism. That one equation already forces

f(0)=0andf(−a)=−f(a),f(0) = 0 \qquad\text{and}\qquad f(-a) = -f(a),

with nothing else assumed. The first: f(0)f(0) added to itself is f(0)f(0), so cancel a copy.

f(0)+f(0)=f(0+0)=f(0)=f(0)+0.f(0) + f(0) = f(0 + 0) = f(0) = f(0) + 0.

  Theorem additive_zero : f 0 == 0.
  Proof.
    apply (cancel_l (f 0)).
    calc (f 0 + f 0)
      == (f (0 + 0)) { additive }
      == (f 0)       { left_identity }
      == (f 0 + 0)   { right_identity }.
  Qed.

The second: f(−a)f(-a) combines with f(a)f(a) to zero, so it is the negative of f(a)f(a), by uniqueness.

f(−a)+f(a)=f((−a)+a)=f(0)=0.f(-a) + f(a) = f((-a) + a) = f(0) = 0.

  Theorem additive_negation : forall a : G, f (- a) == - f a.
  Proof.
    intros a.
    apply neg_unique_l.
    calc (f (- a) + f a)
      == (f (- a + a)) { additive }
      == (f 0)         { left_inverse }
      == (0 : K)       { additive_zero }.
  Qed.

The hypothesis “ff preserves addition” is carried by a type class rather than an ordinary argument:

  Context {fa : Additive G K add add f}.

Additive has a single field, and that field is the equation, so “being additive” and “a proof of additivity” are the same term here. That buys both cases at once. When the map is one the library already knows about — a linear map, multiplication by a fixed ring element, scaling by a scalar, an inner product with one argument held fixed — search supplies the proof and the caller writes only the map:

  Theorem mul_0_r : forall a : R, a * 0 == 0.
  Proof.
    intros a.
    exact (additive_zero (mult a)).
  Qed.

When it is a map nothing has been registered about, the caller hands the equation over directly, as additive_zero f (fa := my_proof). So there is one theorem rather than a convenient version and a general version.

Closing routine goals without a chain

Some goals are not worth a seven-step chain: an identity element to throw away, an inverse pair to collapse, a double negation to undo. Theory/Group.v files those laws into a rewrite database named grp and lets autorewrite grind them:

  Example autorewrite_invl_invr : forall g : G,
    ((- g) + g) + (g + - g) == 0.
  Proof. intros g. autorewrite with grp. reflexivity. Qed.

Every rule in grp strictly shrinks the term it matches — an identity disappears, a a+(−a)a + (-a) pair becomes 00, a double negation collapses — so the rewriting always terminates and lands on a normal form.

What the database contains is not the general law projections but monomorphic wrappers around them:

  Definition add_left_identity  : forall x : G, 0 + x == x     := left_identity.
  Definition add_right_identity : forall x : G, x + 0 == x     := right_identity.
  Definition add_left_inverse   : forall x : G, (- x) + x == 0 := left_inverse.
  Definition add_right_inverse  : forall x : G, x + (- x) == 0 := right_inverse.

The reason is a matching problem. left_identity’s left-hand side is op unit a with the operation a variable, and once several LeftIdentity instances are in scope — a field has one for + and another for * — autorewrite cannot reliably tell which is meant. The wrappers pin the head to add and neg, so each rule matches exactly the terms it should.

The integers, concretely

Impl/Zr.v supplies Coq’s Z with the vocabulary and the laws, each law discharged by the corresponding fact from the standard library:

Instance Z_add_left_inverse : LeftInverse Z add neg 0 := Z.add_opp_diag_l.
Instance Z_add_right_inverse : RightInverse Z add neg 0 := Z.add_opp_diag_r.

and then the structure itself is one line, because every field is something search can already find:

Instance Z_Group : Group Z := {}.

With that in scope, cancel_l, neg_involutive, neg_add_flip, additive_zero — everything above — hold for the integers with no further proof.
