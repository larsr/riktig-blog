Groups: undoing, and the cancellation trick

Adding 3 to an integer can be undone: add −3 and you are back where you started. Multiplying an integer by 0 cannot be undone at all. Both operations are associative — the grouping of a chain of combinations never matters — and both have an identity element, an element that combines invisibly on either side, so both give the integers the shape the previous post built: a monoid, a set with an associative operation and an identity element for it. What separates the two examples is undoing. An inverse of an element aa is an element that combines with aa back to the identity, on both sides; adding 3 has the inverse “add −3”, while multiplying by 0 has no inverse. A monoid in which every element has an inverse is a group.

The extra guarantee is small and its consequences are not. In the multiplication monoid, 0⋅3=0⋅50 \cdot 3 = 0 \cdot 5 is true and 3=53 = 5 is false, so a shared factor cannot in general be struck from an equation. In a group it always can, and the proof uses nothing but the group laws — so it holds for numbers, invertible matrices, symmetries, and every other group at once. This post reads the file that defines the group structure from top to bottom, then walks the theorems that follow from it: cancellation, double negation, and a theorem that hands every addition-preserving map its zero and negation laws for free.

Interface/Group.v, top to bottom

Here is the whole file:

From Riktig.Interface Require Export Monoid.

Module Group.
  Class Group (G : Type) {eq : EqRel G} {zero : Zero G} {add : HasAdd G}
              {neg : HasNeg G} := {
    monoid           :: Monoid G;
    neg_proper       :: Proper (equ ==> equ) neg;
    is_left_inverse  :: LeftInverse G add neg 0;
    is_right_inverse :: RightInverse G add neg 0;
  }.
  Hint Mode Group ! - - - - : typeclass_instances.
  Hint Rewrite @left_inverse @right_inverse : algebra_db.
End Group.
Export Group.

Fourteen lines. The rest of this section walks them in order.

The require line. Require Export re-exports: whoever requires Interface/Group.v sees everything Interface/Monoid.v provides. The exports chain — Interface/Monoid.v re-exports Interface/Semigroup.v, which re-exports Interface/Magma.v, which re-exports Props.v, which re-exports Ops.v — so this one line brings in the whole tower below the group. That includes the operation vocabulary of Ops.v, one type class per symbol. A type class declares a family of facts indexed by a type, and an Instance registers one such fact in a database that Coq searches automatically whenever a proof needs one. EqRel provides the equality symbol ==, Zero the constant 0, HasAdd the operation +, and HasNeg the negation -. The line also brings the law catalogue of Props.v — one class per law, more on it below — and the structures already assembled from it: Magma, Semigroup, Monoid.

The module wrapper. Module Group. … End Group. exists so the fields can carry short names. The field written monoid is, in full, Group.monoid; the prefix lives in the module path instead of in the name, which is why the fields are not called group_monoid and group_neg_proper. The closing Export Group. then puts the module’s contents in scope under their short names, so a user writes Group Z, and reaches for the qualified Group.monoid only when the short name would be ambiguous.

The class header. The carrier G arrives together with four operation classes in braces — implicit arguments, filled in by instance search — rather than as fields of the class. The choice is deliberate. Were add a field, the + of a group would be a projection out of the group record: a different term from the + of the underlying monoid, which rewriting and unification would have to be taught to identify. As parameters, every layer of the tower shares literally the same +. So Group G presupposes the four symbols and contributes only laws — four fields, of which just two are new.

The substructure field. monoid :: Monoid G says a group is a monoid with more laws, and the monoid is held, not restated: none of associativity or the identity laws reappear in Group. The :: (where a plain record field has :) additionally declares the field an instance, so the moment a Group G is in scope, a Monoid G is too, and everything provable in monoids — associative, left_identity, right_identity, every theorem of the previous post — applies to G with nothing repeated.

The respect-for-equality field. In this library == is not Coq’s built-in equality but a chosen equivalence relation — a relation that is reflexive, symmetric and transitive, so it can serve wherever equality would. A carrier packaged with such a relation is called a setoid, and the price of the freedom to choose == is that rewriting with it under an operation must be licensed: the operation has to send ==-equal inputs to ==-equal outputs. neg_proper is that license for negation — Proper (equ ==> equ) neg states exactly “equal in, equal out”, with equ the name behind the == notation. The monoid already carries the matching license for +, as op_proper in Magma.

The two inverse laws. is_left_inverse and is_right_inverse hold the undo laws, and neither is a freshly written equation. They instantiate a pair of one-law classes from the catalogue in Props.v:

Section InverseLaws.
  Context (T : Type) {eqT : EqRel T} (op : BinOp T) (inverse : T -> T) (unit : T).
  Local Infix "⋆" := op (at level 40, left associativity).

  Class LeftInverse  := left_inverse  : forall a, inverse a ⋆ a == unit.
  Class RightInverse := right_inverse : forall a, a ⋆ inverse a == unit.
End InverseLaws.

Filling the slots as LeftInverse G add neg 0 yields: for every a,

(−a)+a=0,and symmetricallya+(−a)=0.(-a) + a \;=\; 0, \qquad\text{and symmetrically}\qquad a + (-a) \;=\; 0.

Each law is a class of its own, rather than a bare equation inside Group, for two reasons. Stated over an arbitrary operation, inverse map and unit, the same class serves elsewhere — the same LeftInverse shape recurs wherever something cancels something. And the class’s one projection has a stable name, left_inverse, which is the name every proof below cites. (The field naming is a convention that runs through the whole tree: a field holding a law is called is_ plus the law it holds.)

The Hint Mode line. This line restricts when instance search may look for a group: the ! marks the carrier argument, which must already be a concrete type before the search starts. Without it, a search for Group ?G with the carrier still unknown can drift into parametric instances — the pointwise ones at function types, say — and recurse forever. The four - positions say the operation arguments may remain unknown; finding those is the search’s job.

The Hint Rewrite line. The two new laws are filed into the rewrite database algebra_db, where the layers below already put theirs, so a later autorewrite with algebra_db can apply them without citing them by name.

Cancellation

The first thing inverses buy is the cancellation property: a term appearing on the same side of both sides of an equation can be struck. All the theorems live in Theory/Group.v, inside a section that fixes an arbitrary group once:

Section GroupTheory.
  Context {G : Type} `{Group G}.

The backtick binder `{Group G} quantifies over a group structure on G together with the four operation instances it presupposes, so every theorem in the section is proved for all groups at once.

The theorem: if a + b == a + c, then b == c. The idea of the proof is to add -a on the left of both sides and let the laws collapse it:

b=0+b{left identity}=(−a+a)+b{left inverse}=−a+(a+b){associativity}=−a+(a+c){hypothesis a+b=a+c}=(−a+a)+c{associativity}=0+c{left inverse}=c{left identity}\begin{aligned} b &= 0 + b &&\{\text{left identity}\}\\ &= (-a + a) + b &&\{\text{left inverse}\}\\ &= -a + (a + b) &&\{\text{associativity}\}\\ &= -a + (a + c) &&\{\text{hypothesis } a + b = a + c\}\\ &= (-a + a) + c &&\{\text{associativity}\}\\ &= 0 + c &&\{\text{left inverse}\}\\ &= c &&\{\text{left identity}\} \end{aligned}

Here is the proof verbatim:

Theorem cancel_l : forall a b c : G, a + b == a + c -> b == c.
Proof.
  intros a b c Heq.
  calc b
    == (0 + b)          { left_identity  }
    == ((- a + a) + b)  { left_inverse }
    == (- a + (a + b))  { associative }
    == (- a + (a + c))  { Heq  }
    == ((- a + a) + c)  { associative }
    == (0 + c)          { left_inverse }
    == c                { left_identity  }.
Qed.

The calc block is the blackboard chain above, written out and machine-checked: it reads b == (0 + b) == ... == c, and each { ... } names the single law that turns one line into the next. Step by step:

  • == (0 + b) { left_identity } — insert a 0 on the left, the left-identity law read backwards.
  • == ((- a + a) + b) { left_inverse } — expand that 0 into - a + a, the left inverse law.
  • == (- a + (a + b)) { associative } — regroup, so a + b appears as a block. This is associativity, inherited through the monoid field.
  • == (- a + (a + c)) { Heq } — replace a + b by a + c, the hypothesis we were given.
  • == ((- a + a) + c) { associative } — regroup the other way, so - a + a is a block again.
  • == (0 + c) { left_inverse } — collapse - a + a back to 0.
  • == c { left_identity } — drop the 0, and the goal b == c is reached.

No step appeals to what the elements actually are. Cancelling on the right — from b + a == c + a conclude b == c — is the mirror image, adding -a on the right and citing the right-hand laws where the left version cited the left-hand ones:

b=b+0{right identity}=b+(a+(−a)){right inverse}=(b+a)+(−a){associativity}=(c+a)+(−a){hypothesis b+a=c+a}=c+(a+(−a)){associativity}=c+0{right inverse}=c{right identity}\begin{aligned} b &= b + 0 &&\{\text{right identity}\}\\ &= b + (a + (-a)) &&\{\text{right inverse}\}\\ &= (b + a) + (-a) &&\{\text{associativity}\}\\ &= (c + a) + (-a) &&\{\text{hypothesis } b + a = c + a\}\\ &= c + (a + (-a)) &&\{\text{associativity}\}\\ &= c + 0 &&\{\text{right inverse}\}\\ &= c &&\{\text{right identity}\} \end{aligned}

Theorem cancel_r : forall a b c : G, b + a == c + a -> b == c.
Proof.
  intros a b c Heq.
  calc b
    == (b + 0)          { right_identity  }
    == (b + (a + - a))  { right_inverse }
    == ((b + a) + - a)  { associative }
    == ((c + a) + - a)  { Heq  }
    == (c + (a + - a))  { associative }
    == (c + 0)          { right_inverse }
    == c                { right_identity  }.
Qed.

Double negation

Negating twice returns the original element — negation is an involution, a function that is its own inverse. The reason: both - - g and g undo - g, since each adds with it to 0, and cancellation turns “both undo the same element” into “they are equal”. On the blackboard, both sides are shown equal after - g is prepended,

(−g)+(−(−g))=0=(−g)+g,(-g) + (-(-g)) \;=\; 0 \;=\; (-g) + g,

the left equation by the right inverse law at −g-g, the right one by the left inverse law at gg; cancelling the shared −g-g leaves −(−g)=g-(-g) = g. In Coq:

Theorem neg_involutive : forall g : G, - (- g) == g.
Proof.
  intros g.
  apply (cancel_l (- g)).
  calc ((- g) + - - g)
    == (0 : G)      { (right_inverse (- g)) }
    == ((- g) + g)  { (left_inverse g)     }.
Qed.
  • apply (cancel_l (- g)) uses the theorem just proved: to show - - g == g, it is enough to show (- g) + - - g == (- g) + g.
  • == (0 : G) { (right_inverse (- g)) } — the left side is - g plus its own negation, which is 0 by the right inverse law at the element - g.
  • == ((- g) + g) { (left_inverse g) } — and 0 is (- g) + g by the left inverse law at g. The two sides meet, and cancel_l finishes.

Any map that preserves addition preserves zero and negation

A map between two groups that preserves the operation — f(a+b)=f(a)+f(b)f(a + b) = f(a) + f(b) — is a group homomorphism. The classical fact about them: that one equation already forces f(0)=0f(0) = 0 and f(−a)=−f(a)f(-a) = -f(a), with no extra hypotheses. Theory/Group.v proves this once, for an arbitrary map between two arbitrary groups:

Section GroupHomTheory.
  Context {G K : Type} `{Group G}.
  Context `{Group K}.
  Context (f : G -> K).
  Context `{fp : Proper _ (equ ==> equ) f}.
  Context (fadd : forall a b : G, f (a + b) == f a + f b).

Two groups G and K, a map f between them, the license fp to rewrite under f (the same Proper shape as neg_proper above), and the one substantive hypothesis fadd: f preserves addition.

First the zero law. The argument: f 0 added to itself equals f 0, so cancel one copy —

f(0)+f(0)=f(0+0)=f(0)=f(0)+0,f(0) + f(0) \;=\; f(0 + 0) \;=\; f(0) \;=\; f(0) + 0,

the first step because ff preserves addition (read right to left), the second by the left identity law inside ff, the third by the right identity law; cancelling f(0)f(0) on the left of the outer ends leaves f(0)=0f(0) = 0.

  Theorem hom_zero : f 0 == 0.
  Proof.
    apply (cancel_l (f 0)).
    calc (f 0 + f 0)
      == (f (0 + 0)) { (fadd 0 0) }
      == (f 0)       { left_identity }
      == (f 0 + 0)   { right_identity }.
  Qed.

apply (cancel_l (f 0)) reduces the goal f 0 == 0 to f 0 + f 0 == f 0 + 0, and the calc chain is the displayed equation, one law per step: fadd folds the sum inside f, left_identity collapses 0 + 0, and right_identity re-expands f 0 to meet the goal’s right-hand side.

The negation law leans on a uniqueness fact proved at the top of Theory/Group.v: neg_unique_l says anything that combines with g to 0 from the left is - g — from h + g == 0 follows h == - g. So to show f (- a) == - f a it is enough to show that f (- a) combines with f a to 0:

f(−a)+f(a)=f(−a+a)=f(0)=0,f(-a) + f(a) \;=\; f(-a + a) \;=\; f(0) \;=\; 0,

by additivity, the left inverse law inside ff, and the zero law just proved.

  Theorem hom_neg : forall a : G, f (- a) == - f a.
  Proof.
    intros a.
    apply neg_unique_l.
    calc (f (- a) + f a)
      == (f (- a + a)) { (fadd (- a) a) }
      == (f 0)         { left_inverse }
      == (0 : K)       { hom_zero }.
  Qed.
  • apply neg_unique_l turns the goal f (- a) == - f a into f (- a) + f a == 0.
  • == (f (- a + a)) { (fadd (- a) a) } — additivity folds the sum inside f.
  • == (f 0) { left_inverse } — - a + a collapses to 0 under f, rewriting there being exactly what fp licenses.
  • == (0 : K) { hom_zero } — and f 0 is 0 by the previous theorem.

The same file restates both results with the additivity hypothesis supplied by instance search instead of by hand: additive_zero and additive_negation hold for any map registered as Additive, so a map already known to preserve addition — a linear map, multiplication by a fixed element — gets its zero and negation laws without ever naming its own additivity law.

A rewrite database that only shrinks terms

Routine group goals — a stray 0 in a sum, an a + - a waiting to collapse, a double negation — should not each cost a calc chain. Rewriting automates this: a rewrite rule is an equation applied left to right wherever its left-hand side matches, and a database of rules is applied by autorewrite until nothing matches. Theory/Group.v builds a database named grp from the group laws, each oriented so that applying it strictly shrinks the term — which is why the process terminates. The registered rules are wrappers, one definition per law:

  Definition add_left_identity  : forall x : G, 0 + x == x     := left_identity.
  Definition add_right_identity : forall x : G, x + 0 == x     := right_identity.
  Definition add_left_inverse   : forall x : G, (- x) + x == 0 := left_inverse.
  Definition add_right_inverse  : forall x : G, x + (- x) == 0 := right_inverse.

Each wrapper is the corresponding generic law, restated with +, -, 0 fixed in place. The generic projections themselves (left_identity and friends) are not registered: their left-hand sides start with a variable operation, which autorewrite cannot match reliably once several identity laws are in scope — a field has an additive and a multiplicative identity, and the rule would not know which 0 it is looking at. The wrappers keep a rigid add or neg head, so matching is unambiguous. The database registers the four wrappers plus two derived facts, neg_involutive from above and neg_zero (the identity is its own negation), all as shrinking rules:

Hint Rewrite @add_left_identity @add_right_identity
                       @add_left_inverse @add_right_inverse
                       @neg_involutive @neg_zero using typeclasses eauto : grp.

The file checks the database on small examples. This one claims (0+(−(−g)))+0=g(0 + (-(-g))) + 0 = g — a left identity, a double negation, and a right identity, all removable:

  Example autorewrite_multi : forall g : G, (0 + - (- g)) + 0 == g.
  Proof. intros g. autorewrite with grp. reflexivity. Qed.

One autorewrite with grp erases all three redundancies, and reflexivity closes the g == g that remains — where a calc chain would have spent three justified lines.

The integers are a group

Every theorem above holds for a type the moment it is shown to satisfy Group. For the integers, Impl/Zr.v names the negation operation alongside the rest of Z’s vocabulary,

Instance Z_Neg   : HasNeg Z := Z.opp.

and discharges the two inverse laws, each by the standard-library fact that says exactly that:

Instance Z_add_left_inverse : LeftInverse Z add neg 0 := Z.add_opp_diag_l.
Instance Z_add_right_inverse : RightInverse Z add neg 0 := Z.add_opp_diag_r.

The monoid layers were instantiated in the previous post; on top of them the whole tower is declared with no fields written at all:

Instance Z_Magma : Magma Z add := { Magma.equivalence := eq_equivalence }.
Instance Z_Semigroup : Semigroup Z add := {}.
Instance Z_Monoid : Monoid Z := {}.
Instance Z_Group : Group Z := {}.

An empty {} asks instance search to supply every field, and it finds them: the two inverse laws above, the monoid one level down, and Z_neg_proper — the Proper license for Z.opp, discharged by congruence since == at Z is Coq’s own equality, which every function respects. With this in scope, cancel_l, neg_involutive, hom_zero — all of the above — hold for the integers with no further proof.
