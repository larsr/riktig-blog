A channel behaviour splits wherever the sent list does

A faulty communication channel can be described as a relation: a pair of finite lists — what a sender put in, what a receiver got out — is in the relation exactly when the channel could have turned the one into the other. The class this post works in allows dropping messages and delivering a message more than once, in any interleaving, and its facts always concern whole runs: one sent list, one received list, one yes.

A protocol proof wants something finer. A retransmission protocol lays its wire traffic out in segments — one burst of copies per application message — and its correctness argument goes segment by segment: what the channel did to this burst, then what it did to the rest. So the whole-run fact has to be cut at the segment boundary, and per-segment facts have to be glued back into a whole-run fact. Neither direction is automatic. Cutting is the delicate one: a channel that duplicates does its duplicating on the received side without consuming anything on the sent side, so a run of duplicates sitting exactly at the boundary belongs, on the face of it, to neither half. This post states the two directions as lemmas about the relation alone — no protocol in sight — and walks both proofs, including the boundary case that makes cutting interesting.

The relation being cut

From Channel/Trace.v, the lossy-and-duplicating class is an inductively defined relation between a sent list and a received list — four ways to extend a valid pair:

Inductive lossy_dup : list M -> list M -> Prop :=
  | lossy_dup_nil : lossy_dup [] []
  | lossy_dup_keep : forall x s r,
      lossy_dup s r -> lossy_dup (x :: s) (x :: r)
  | lossy_dup_drop : forall x s r,
      lossy_dup s r -> lossy_dup (x :: s) r
  | lossy_dup_stutter : forall x s r,
      lossy_dup s (x :: r) -> lossy_dup s (x :: x :: r).

lossy_dup_keep delivers the next sent message once; lossy_dup_drop swallows it; lossy_dup_stutter re-emits the message currently at the head of the received list, consuming nothing from the sent side. That last constructor is the one to watch: it is the only one whose action is invisible from the sent list, and it is why splitting a behaviour takes a proof.

Gluing: behaviours compose across a seam

The easy direction first. If the channel could turn s1 into r1 and could turn s2 into r2, it could turn the concatenation s1 ++ s2 into r1 ++ r2 — run the first behaviour, then the second. Writing ld\mathrm{ld} for the relation and +++\!\!+ for concatenation:

ld(s1,r1)∧ld(s2,r2)⇒ld(s1++s2,r1++r2).\mathrm{ld}(s_1, r_1) \;\wedge\; \mathrm{ld}(s_2, r_2) \;\Longrightarrow\; \mathrm{ld}(s_1 \mathbin{+\!\!+} s_2,\; r_1 \mathbin{+\!\!+} r_2).

The proof is an induction on the first behaviour’s derivation: each constructor used to build ld(s1,r1)\mathrm{ld}(s_1, r_1) is replayed at the front of the combined run, and when the first derivation is exhausted, the second behaviour is exactly what remains.

Lemma lossy_dup_app : forall s1 r1 s2 r2 : list M,
  lossy_dup s1 r1 -> lossy_dup s2 r2 -> lossy_dup (s1 ++ s2) (r1 ++ r2).
Proof.
  intros s1 r1 s2 r2 H1.
  induction H1 as [| x s1' r1' H1' IH | x s1' r1' H1' IH | x s1' r1' H1' IH]; intros H2.
  - simpl. exact H2.
  - simpl. apply lossy_dup_keep. apply IH. exact H2.
  - simpl. apply lossy_dup_drop. apply IH. exact H2.
  - simpl. apply lossy_dup_stutter. apply IH. exact H2.
Qed.

Four cases, one per constructor. The base case: s1 and r1 are both empty, the concatenations are s2 and r2, and the hypothesis H2 is the goal. In each of the other three, simpl exposes the head of the concatenation, the same constructor is applied to the combined run, and the induction hypothesis IH finishes — the derivation for the pair (s1, r1) is replayed verbatim with s2 and r2 appended behind it.

Cutting: a behaviour splits at every seam of the sent list

Now the converse. The channel acted once, on the whole list — but if that list happens to be a concatenation l1 ++ l2, the received list must split to match:

ld(l1++l2,r)⇒∃r1r2.r=r1++r2∧ld(l1,r1)∧ld(l2,r2).\mathrm{ld}(l_1 \mathbin{+\!\!+} l_2,\; r) \;\Longrightarrow\; \exists\, r_1\, r_2.\;\; r = r_1 \mathbin{+\!\!+} r_2 \;\wedge\; \mathrm{ld}(l_1, r_1) \;\wedge\; \mathrm{ld}(l_2, r_2).

On the blackboard the argument is an induction on the derivation of the behaviour, not on the lists, and the file’s comment says why in one sentence:

(* Induction on the lossy_dup DERIVATION, not on the lists: stutter
   duplicates the front of the received list without consuming
   anything from the sent side, and can occur arbitrarily deep on
   either side of the split. *)

Consider the last rule used to build ld(s,r)\mathrm{ld}(s, r), with s=l1++l2s = l_1 \mathbin{+\!\!+} l_2.

  • nil: both lists are empty, so l1=l2=[]l_1 = l_2 = [\,], and the empty split works.
  • keep on a message xx: if l1l_1 is empty the whole run belongs to l2l_2 (r1=[]r_1 = [\,]). If l1=x::l1′l_1 = x :: l_1', the sub-derivation splits by the induction hypothesis, and the kept xx is put back at the front of the first fragment.
  • drop: the same two cases, except the dropped message adds nothing to either fragment.
  • stutter — the boundary case. The sub-derivation ends in r=x::r′r = x :: r' and, by the induction hypothesis, splits as r1++r2r_1 \mathbin{+\!\!+} r_2. Where does the duplicate of xx go? It must join whichever fragment contains the xx being duplicated: if r1r_1 is empty, the head xx lives in r2r_2, so the duplicate goes to the second fragment; if r1=x::r1″r_1 = x :: r_1'', it goes to the first. The case split on r1r_1 is exactly the “straddling the boundary” possibility, resolved.

The Coq proof, verbatim:

Lemma lossy_dup_app_split : forall (s r : list M),
  lossy_dup s r -> forall l1 l2 : list M, s = l1 ++ l2 ->
  exists r1 r2, r = r1 ++ r2 /\ lossy_dup l1 r1 /\ lossy_dup l2 r2.
Proof.
  intros s r H.
  induction H as [| x s0 r0 H0 IH0 | x s0 r0 H0 IH0 | x s0 r0 H0 IH0];
    intros l1 l2 Heq.
  - destruct l1 as [| y l1'].
    + destruct l2 as [| z l2'].
      * exists [], []. split.
        -- reflexivity.
        -- split; apply lossy_dup_nil.
      * simpl in Heq. discriminate Heq.
    + simpl in Heq. discriminate Heq.
  - destruct l1 as [| y l1'].
    + simpl in Heq.
      exists [], (x :: r0). split.
      * reflexivity.
      * split.
        -- apply lossy_dup_nil.
        -- rewrite <- Heq. apply lossy_dup_keep. exact H0.
    + simpl in Heq.
      assert (Heqx : x = y). { apply (cons_eq_head x y s0 (l1' ++ l2)). exact Heq. }
      assert (Heqs0 : s0 = l1' ++ l2). { apply (cons_eq_tail x y s0 (l1' ++ l2)). exact Heq. }
      destruct (IH0 l1' l2 Heqs0) as [r1' [r2' [Hr [Hl1 Hl2]]]].
      exists (x :: r1'), r2'. split.
      * simpl. rewrite Hr. reflexivity.
      * split.
        -- rewrite Heqx. apply lossy_dup_keep. exact Hl1.
        -- exact Hl2.
  - destruct l1 as [| y l1'].
    + simpl in Heq.
      exists [], r0. split.
      * reflexivity.
      * split.
        -- apply lossy_dup_nil.
        -- rewrite <- Heq. apply lossy_dup_drop. exact H0.
    + simpl in Heq.
      assert (Heqs0 : s0 = l1' ++ l2). { apply (cons_eq_tail x y s0 (l1' ++ l2)). exact Heq. }
      destruct (IH0 l1' l2 Heqs0) as [r1' [r2' [Hr [Hl1 Hl2]]]].
      exists r1', r2'. split.
      * exact Hr.
      * split.
        -- apply lossy_dup_drop. exact Hl1.
        -- exact Hl2.
  - destruct (IH0 l1 l2 Heq) as [r1' [r2' [Hr [Hl1 Hl2]]]].
    destruct r1' as [| y r1''].
    + simpl in Hr.
      exists [], (x :: x :: r0). split.
      * reflexivity.
      * split.
        -- exact Hl1.
        -- rewrite <- Hr in Hl2.
           apply lossy_dup_stutter. exact Hl2.
    + simpl in Hr.
      assert (Heqxy : x = y). { apply (cons_eq_head x y r0 (r1'' ++ r2')). exact Hr. }
      assert (Heqr0 : r0 = r1'' ++ r2'). { apply (cons_eq_tail x y r0 (r1'' ++ r2')). exact Hr. }
      exists (x :: x :: r1''), r2'. split.
      * simpl. rewrite Heqr0. reflexivity.
      * split.
        -- assert (Hl1' : lossy_dup l1 (x :: r1'')).
           { rewrite Heqxy. exact Hl1. }
           apply lossy_dup_stutter. exact Hl1'.
        -- exact Hl2.
Qed.

Reading it against the blackboard cases. induction H produces the four cases in constructor order; in each, l1 is destructed to decide which side of the seam the constructor’s action lands on. The two helper facts cons_eq_head and cons_eq_tail extract, from an equality of nonempty lists, the equality of heads and of tails — they are how the pattern y :: l1' on the seam side is matched up with the constructor’s own x. The final case is the stutter case: IH0 splits the sub-derivation first, then destruct r1' asks whether the first received fragment is empty, and the duplicate x is prepended to r2' (via lossy_dup_stutter on the second fragment) or to r1'' (via lossy_dup_stutter on the first) — never invented, never lost.

One degenerate companion gets used just as often: a channel given nothing produces nothing,

ld([],r)⇒r=[],\mathrm{ld}([\,],\, r) \;\Longrightarrow\; r = [\,],

because lossy_dup_keep and lossy_dup_drop need a nonempty sent list and lossy_dup_stutter needs something already received to duplicate:

Lemma lossy_dup_nil_l : forall s r, lossy_dup s r -> s = [] -> r = [].
Proof.
  intros s r H.
  induction H as [| x s0 r0 H0 IH0 | x s0 r0 H0 IH0 | x s0 r0 H0 IH0]; intros Hs.
  - reflexivity.
  - discriminate Hs.
  - discriminate Hs.
  - assert (Hcontra : x :: r0 = []). { apply IH0. exact Hs. }
    discriminate Hcontra.
Qed.

The keep and drop cases refute the hypothesis s = [] outright (discriminate); the stutter case asks its sub-derivation for x :: r0 = [], which is equally impossible.

Where the two directions are spent

The consumers live one file over, in the protocol proofs. The safety theorem behind the alternating-bit protocol post inducts over the message list, and its step case opens by cutting the wire at the current burst’s boundary — this line of deliver_subseq in Channel/ARQ.v is the split lemma at work, aimed at the seam between the burst for m and the stream for the remaining messages:

      destruct (lossy_dup_app_split _ _ H
                  (burst t0 m k) (stream (tag_next pro t0) ms' k)
                  eq_refl) as [w1 [w2 [Hwire [H1 H2]]]].

Its base case is lossy_dup_nil_l: no messages sent, so the wire is empty. The gluing direction is spent in the liveness post’s fair_wire_lossy_dup, which reassembles per-burst fragments into one behaviour of the whole sender stream — the inductive step of that proof is a single apply lossy_dup_app. That the lemma never mentions a packet type is why the split above could be written against an abstract tag at all: Channel/ARQ.v proves the delivery argument once, and both the alternating bit of Channel/ABP.v and the sequence numbers of Channel/GoBackN.v cite it. A new retransmission scheme owes an alphabet, not a proof.
