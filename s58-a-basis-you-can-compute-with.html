A basis is a coordinate isomorphism

A vector space over a field FF is a set of vectors you can add and scale by scalars from FF, with the scaling and addition obeying the usual laws: scaling distributes over sums, the scalar 11 leaves a vector alone, and so on. Crucially, that definition mentions no coordinates and no list of numbers — a vector is an abstract thing you can add and scale, nothing more. This post is about the bridge back to numbers: a basis, the structure that lets you write every vector as a finite tuple of scalars and read it back again without loss.

A basis is a coordinate isomorphism

The usual textbook definition of a basis has two clauses — the basis vectors span the space (every vector is some combination of them) and they are linearly independent (that combination is unique). Both clauses are really one statement about a single map. Fix nn basis vectors b0,…,bn−1b_0, \dots, b_{n-1}. They define a coordinate map sending a tuple of scalars cc to the linear combination ∑ici⋅bi\sum_i c_i \cdot b_i, and its would-be inverse sending a vector to its coordinates. Spanning says the first map is onto; independence says it is one-to-one. Together they say: the coordinate map is an isomorphism between the abstract space VV and the concrete space of tuples, which for a finite basis is Fin.t n -> F — functions from the finite index set {0,…,n−1}\{0, \dots, n-1\} to scalars.

So the library defines a basis as exactly that: the data of the basis vectors, a linear coordinate map, and proofs that the two directions undo each other. The vectors are indexed by a finite carrier I — any type with decidable equality and one duplicate-free enumeration of length n; the concrete Fin.t n is one such carrier, not part of the definition. lincomb b c is the linear combination ∑ici⋅bi\sum_i c_i \cdot b_i; the class demands that reconstructing a vector from its coordinates gives the vector back, and that reading the coordinates of a reconstruction gives the coordinates back:

Module Basis.
  Class Basis (n : nat) (I F V : Type)
      {Ieq : EqDec I} {IFin : FinIndex n I}
      {Fe : EqRel F} {Fz : Zero F} {Fa : HasAdd F} {Fn : HasNeg F} {Fo : One F}
      {Fm : HasMult F} {Fi : HasInv F} {FF : Field F}
      {eV : EqRel V} {zV : Zero V} {aV : HasAdd V} {nV : HasNeg V} {sV : HasScale F V}
      {VV : VectorSpace F V} := {
    vec            : I -> V;
    coords         : LinearMap F V (I -> F);
    reconstruction : forall v : V,
      lincomb vec (coords v) == v;
    coords_linear_combination : forall c : I -> F,
      coords (lincomb vec c) == c
  }.
End Basis.

Two round trips, Basis.reconstruction and Basis.coords_linear_combination, are spanning and independence packaged as a single mutual inverse — no separate machinery for “a linearly independent list.” The linear combination it refers to is defined as a finite sum over the index set:

Definition lincomb (b : I -> V) (c : I -> F) : V :=
  bigopI (fun i => c i *: b i).

Here bigopI f sums f over the carrier’s enumeration of all nn indices, and *: is scaling a vector by a scalar. To exhibit an actual basis, we need vectors b and a coordinate map for which those two round trips hold.

The standard basis vector

The cleanest example lives in the coordinate space itself, $V = $ Fin.t n -> F — the vectors are the tuples. Its standard basis is the one every linear-algebra course draws first: eie_i is the tuple that is 11 in position ii and 00 everywhere else. The branch “am I in position ii?” is not special to Fin.t n; the library states it once, for any index type I with decidable equality and any ring R of values, and the standard basis vector is that definition read at I = Fin.t n:

Definition delta (i j : I) : R := if dec (i = j) then 1 else 0.
Definition e {n : nat} (i : Fin.t n) : Fin.t n -> F := delta i.

The if dec (i = j) then 1 else 0 is the decidable-equality idiom: dec (i = j) is not a boolean but a proof-carrying decision that either hands back evidence i = j or evidence i <> j, and the if picks the branch while making that evidence available to whatever needs it (this is the subject of the earlier post on decidable propositions). So e i is 11 on the diagonal i=ji = j and 00 off it — which is precisely the Kronecker delta δij\delta_{ij} written as a computable function.

Two one-line facts read straight off that definition: delta i j is 11 when the indices agree and 00 when they differ.

Lemma delta_at_eq : forall i j : I, i = j -> delta i j == 1.
Proof.
  intros i j Hij.
  unfold delta; destruct (dec (i = j)) as [_ | Hne].
  - reflexivity.
  - destruct (Hne Hij).
Qed.

Each unfolds delta, splits on the decision, and in the impossible branch derives a contradiction from the two conflicting proofs (Hne Hij and Hij Heq are each a proof of False, which destruct turns into anything). One term of the coordinate sum, ci⋅ei(j)c_i \cdot e_i(j), therefore collapses the same way — it is cic_i on the diagonal and 00 off it, because scaling in FF is just multiplication:

Lemma mul_delta_eq : forall (a : R) (i j : I), i = j -> a * delta i j == a.
Proof.
  intros a i j Hij.
  rewrite (delta_at_eq i j Hij).
  exact (right_identity a).
Qed.

On the diagonal, a * 1 = a (right_identity, the right-identity law of the field’s multiplication); off it, a * 0 = 0 (mul_0_r, inside mul_delta_neq). These are the two facts the main argument feeds on.

The delta collapse

Here is the theorem that makes e a genuine basis. Take any coordinate tuple cc and any position jj. The full sum ∑ici⋅ei(j)\sum_i c_i \cdot e_i(j) has one term for every index ii, but ei(j)=δije_i(j) = \delta_{ij} is zero unless i=ji = j, so every term vanishes except the single one at i=ji = j, where it is cj⋅1=cjc_j \cdot 1 = c_j:

∑ici⋅ei(j)=∑ici⋅δij=cj. \sum_{i} c_i \cdot e_i(j) \;=\; \sum_i c_i \cdot \delta_{ij} \;=\; c_j.

That is the whole content of “coordinates read back what a combination put in.” Notice that the blackboard argument never uses what the indices are — only that one term survives and the rest vanish. The library proves it at that level of generality. A finite index type is a type I whose elements one duplicate-free list enumerates:

Class FinIndex (n : nat) (I : Type) {eqdec : EqDec I} := {
  enum          : list I;
  enum_NoDup    : NoDup enum;
  enum_complete : forall i : I, In i enum;
  enum_length   : length enum = n;
}.

and bigopI f sums f over that enumeration:

Definition bigopI (f : I -> M) : M := bigop_list f enum.

The one-survivor argument is then a statement about support: if f vanishes at every index other than p, the whole sum is the term at p.

Lemma bigopI_support_singleton : forall (p : I) (f : I -> M),
  (forall i : I, i <> p -> f i == 0) ->
  bigopI f == f p.
Proof.
  intros p f Hsupp.
  calc (bigopI f)
    == (f p + bigop_list f (remove eq_dec p enum))
         { bigopI_extract }
    == (f p + (0 : M))
         { (bigop_list_zero_on f (remove eq_dec p enum)
             (fun i Hi => Hsupp i (proj2 (in_remove eq_dec enum i p Hi)))) }
    == (f p)
         { right_identity }.
Qed.

Walking the three steps:

  • bigopI_extract pulls the term at p out front: the sum over enum equals f p plus the sum over remove eq_dec p enum, the enumeration with p deleted. enum_NoDup is what makes the deletion lossless — p occurred exactly once, so exactly one term leaves the sum.
  • Every index still in the shortened list is different from p (that is in_remove), so the support hypothesis sends its term to 00, and bigop_list_zero_on collapses the whole tail to 00.
  • right_identity — adding 00 changes nothing — finishes.

Feeding it f i := c i * delta i j and p := j is the delta collapse: off the diagonal mul_delta_neq provides the vanishing, and the surviving term is cj⋅δjj=cjc_j \cdot \delta_{jj} = c_j by mul_delta_eq:

Lemma bigopI_delta : forall (c : I -> R) (j : I),
  bigopI (fun i => c i * delta i j) == c j.
Proof.
  intros c j.
  calc (bigopI (fun i => c i * delta i j))
    == (c j * delta j j)
         { (bigopI_support_singleton j (fun i => c i * delta i j)
             (fun i Hne => mul_delta_neq (c i) i j Hne)) }
    == (c j)
         { mul_delta_eq }.
Qed.

No induction anywhere: the enumeration carries the finiteness, and the support collapse does the rest. Fin.t n is a finite index type — fin_all n, the list 0, 1, ..., n-1, is its enumeration — and on it the enumeration fold agrees with bigopF, the structural fold the matrix implementation computes with:

Lemma bigopF_bigopI : forall (n : nat) (f : Fin.t n -> M),
  bigopF f == bigopI f.

So the concrete collapse is the abstract one, transported:

Lemma lincomb_std_delta : forall (n : nat) (c : Fin.t n -> F)
    (j : Fin.t n),
  bigopF (fun i => c i * e i j) == c j.
Proof.
  intros n c j.
  calc (bigopF (fun i => c i * e i j))
    == (bigopI (fun i => c i * e i j))
      { (bigopF_bigopI n (fun i => c i * e i j)) }
    == (c j)
      { (bigopI_delta c j) }.
Qed.

The sum ends where the blackboard did: the whole sum equals the single surviving coordinate.

From the collapse to a basis

The collapse is stated on a bare sum. Lifting it to lincomb gives the round-trip law itself — for every coordinate tuple cc,

∑ici⋅ei=c,\sum_i c_i \cdot e_i \;=\; c,

and the lift is one short step: evaluating a linear combination lincomb e c at a position j means evaluating the sum at j, and evaluation commutes with the sum (bigopI_app), turning it into ∑i(ci⋅ei)(j)=∑ici⋅ei(j)\sum_i (c_i \cdot e_i)(j) = \sum_i c_i \cdot e_i(j) — the collapse again.

Lemma lincomb_std : forall (n : nat) (c : Fin.t n -> F),
  lincomb e c == c.
Proof.
  intros n c j.
  calc (lincomb e c j)
    == (bigopI (fun i => (c i *: e i) j)) { (bigopI_app (fun i => c i *: e i) j) }
    == (c j)                              { (bigopI_delta c j) }.
Qed.

lincomb e c == c says: build a vector from a tuple of coordinates using the standard basis, and you recover the very tuple you started with. That single equation is both round trips the Basis record asks for — for this space the coordinate map is the identity, so reconstruction and coordinate-reading are the same statement read in the two directions. The basis assembles with lincomb_std supplied for both fields:

  Definition FinVec_Basis (n : nat) : Basis n (Fin.t n) F (Fin.t n -> F) :=
    {| Basis.vec := e;
       Basis.coords                    := linear_map_id;
       Basis.reconstruction            := fun v => lincomb_std n v;
       Basis.coords_linear_combination := fun c => lincomb_std n c |}.

The record literal names all four fields directly. The coordinate map is linear_map_id, the identity linear map; the basis vectors are e; and the two obligations are both discharged by lincomb_std. The delta collapse is the one real computation in the file, and it is what earns e the name “basis”: coordinates become a genuine, checkable round trip rather than a definition asserted by hand.
