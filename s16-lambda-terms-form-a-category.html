riktig — correct, real, propersource

Typed lambda terms form a category, with conversion as arrow equality

A category asks very little: arrows between objects, an identity arrow at each object, a composition, and three laws — identity on either side does nothing, and composition is associative. For functions, the laws hold on the nose: id ∘ f and f return the same value at every input. For programs — pieces of syntax — they do not. The program “apply the identity function to the result of f” is a different piece of text than f; running it takes one step more. If programs are to be the arrows of a category, “equal arrows” cannot mean “identical syntax.” It has to mean “the same after computation,” and the category’s own definition allows exactly this: arrow equality is a field, a chosen equivalence relation per pair of objects, not Coq’s built-in equality. This post cashes that freedom in. The objects are the types of the simply typed lambda calculus, the arrows are closed function-terms, and the three category laws are proved as conversion facts — chains of computation steps under a binder.

Terms that cannot be ill-typed

The whole development is Impl/StlcCat.v, and it opens with the types: one base type and function types over it,

Inductive ty : Type :=
  | Base : ty
  | Arr  : ty -> ty -> ty.

Terms are indexed by a context — the list of types of the free variables in scope — and by their own type, so that only well-typed terms can be written at all. A variable is a position in the context, in de Bruijn style: here is the nearest binder, there skips one.

Inductive var : list ty -> ty -> Type :=
  | here  : forall G T, var (T :: G) T
  | there : forall G U T, var G T -> var (U :: G) T.
Inductive tm : list ty -> ty -> Type :=
  | TVar : forall G T, var G T -> tm G T
  | TAbs : forall G A B, tm (A :: G) B -> tm G (Arr A B)
  | TApp : forall G A B, tm G (Arr A B) -> tm G A -> tm G B.

Read TAbs: the body lives in the context extended by the argument type A, and the abstraction has type Arr A B — the typing rule for λ is the constructor’s type. TApp likewise demands a function and an argument whose types meet. A scope error or a type error is not caught later; it is unwritable.

One operation on terms is needed before any category appears: weakening, which transports a term into a larger context — the term does not use the extra variables, it merely tolerates their presence. The file extends the context at the far end, so every de Bruijn witness is copied unchanged and the recursion stays structural:

Fixpoint wkt {G D T} (t : tm G T) : tm (G ++ D) T :=
  match t in tm G0 T0 return tm (G0 ++ D) T0 with
  | TVar x   => TVar (wkvar x)
  | TAbs b   => TAbs (wkt b)
  | TApp f a => TApp (wkt f) (wkt a)
  end.

(* Type-correct because nil ++ D is definitionally D. *)
Definition wk {D T} (t : tm nil T) : tm D T := wkt t.

wk is the case used below: a closed term dropped into any context.

Arrows: closed function-terms

An arrow from A to B is a closed program of type A → B; the identity arrow is λx. x, and composition builds λx. g (f x), weakening the two closed terms under the new binder:

Definition Hom (A B : ty) : Type := tm nil (Arr A B).

Definition tid (A : ty) : Hom A A := TAbs (TVar here).

Definition tcomp {A B C} (g : Hom B C) (f : Hom A B) : Hom A C :=
  TAbs (TApp (wk g) (TApp (wk f) (TVar here))).

These are ordinary data — tcomp really constructs the composite program, as a computation checked by the kernel shows:

Example tcomp_computes :
  tcomp (tid Base) (tid Base)
  = TAbs (TApp (TAbs (TVar here)) (TApp (TAbs (TVar here)) (TVar here))).
Proof. reflexivity. Qed.

Composing two identities yields λx.(λy.y)((λy.y)x)\lambda x.\,(\lambda y.\,y)\,((\lambda y.\,y)\,x) — visibly not the identity term. The category laws will have to say in what sense it is the identity anyway.

Conversion: exactly the equations the laws force

The equality on arrows is an inductively defined relation conv. Its constructors fall into three groups: the equivalence closure (conv_refl, conv_sym, conv_trans); congruence, so a conversion may happen inside an application, under a binder, or under weakening (conv_app, conv_abs, conv_wk); and three computation rules — the only places anything actually reduces:

  | conv_beta_id : forall G A (v : tm G A),
      conv G A (TApp (TAbs (TVar here)) v) v
  | conv_beta_comp : forall G A B C (g : Hom B C) (f : Hom A B) (v : tm G A),
      conv G C (TApp (wk (tcomp g f)) v) (TApp (wk g) (TApp (wk f) v))
  | conv_eta   : forall A B (f : Hom A B),
      conv nil (Arr A B) (TAbs (TApp (wk f) (TVar here))) f.

conv_beta_id fires the identity redex, conv_beta_comp fires a composite applied to an argument, and conv_eta is the eta rule: a function that only applies f is f. The file’s header discloses the scope cut: these are exactly the β/η instances the four category laws need, not full βη-conversion — the general β rule would need single-variable substitution, whose TAbs case forces the whole renaming tower, machinery the category laws never ask for.

The three laws, as conversion chains

The left identity law says tcomp (tid B) f == f. On the blackboard, writing == for convertibility, it is a two-step chain — one β step under the binder, then η:

id∘f=λx.(λy.y)(fx)=λx.fx{β under the binder}=f{η}\mathrm{id} \circ f \;=\; \lambda x.\,(\lambda y.\,y)\,(f\,x) \;=\; \lambda x.\,f\,x \quad\{\beta \text{ under the binder}\} \;=\; f \quad\{\eta\}

Lemma conv_left_identity : forall A B (f : Hom A B), conv (tcomp (tid B) f) f.
Proof.
  intros A B f.
  apply (conv_trans (t := TAbs (TApp (wk f) (TVar here)))).
  - apply conv_abs. apply conv_beta_id.
  - apply conv_eta.
Qed.

conv_trans names the midpoint of the chain, the term λx.fx\lambda x.\,f\,x. The first leg reaches it by conv_abs — step inside the binder — and conv_beta_id, which fires the identity redex on the body. The second leg is conv_eta verbatim. The right identity law is the same chain with the β step on the argument side of the application (conv_app routes it there).

Associativity is the law with content: f ∘ (g ∘ h) and (f ∘ g) ∘ h are different programs — each contains a composite as a subterm, applied to an argument — and both β-reduce to the same fully spelled-out pipeline:

f∘(g∘h)=λx.f(g(hx))=(f∘g)∘h,f \circ (g \circ h) \;=\; \lambda x.\,f\,(g\,(h\,x)) \;=\; (f \circ g) \circ h,

the first equality by firing the composite g∘hg \circ h inside the left-hand term, the second by firing f∘gf \circ g inside the right-hand term and reading the chain backwards.

Lemma conv_associative :
  forall W X Y Z (f : Hom Y Z) (g : Hom X Y) (h : Hom W X),
    conv (tcomp f (tcomp g h)) (tcomp (tcomp f g) h).
Proof.
  intros W X Y Z f g h.
  apply (conv_trans
    (t := TAbs (TApp (wk f) (TApp (wk g) (TApp (wk h) (TVar here)))))).
  - apply conv_abs. apply conv_app.
    + apply conv_refl.
    + apply conv_beta_comp.
  - apply conv_sym. apply conv_abs. apply conv_beta_comp.
Qed.

Again conv_trans names the meeting point, λx.f(g(hx))\lambda x.\,f\,(g\,(h\,x)). The first leg works under the binder: the outer application keeps its function wk f (conv_refl) while conv_beta_comp fires the composite g ∘ h on the argument. The second leg fires f ∘ g in the other term the same way, and conv_sym turns that reduction around so the two legs chain.

The instance, and what it buys

With the laws proved and a Proper instance saying tcomp respects conversion on both sides (tcomp_proper — congruence, assembled from conv_wk and conv_app), the category is filled in field by field:

Instance Stlc_Category : Category ty := {|
  Category.hom               := Hom;
  Category.hom_equ           := fun A B => @conv nil (Arr A B);
  Category.hom_equiv         := fun A B => @conv_equivalence nil (Arr A B);
  Category.id                := tid;
  Category.comp              := @tcomp;
  Category.comp_proper       := tcomp_proper;
  Category.is_left_identity  := conv_left_identity;
  Category.is_right_identity := conv_right_identity;
  Category.comp_associative  := conv_associative
|}.

The arrow equality field is conv at the empty context — this is the hom-setoid choice the opening paragraph promised, and it is the entire reason the instance exists: with syntactic equality in that field, tcomp_computes above would refute the left identity law outright.

Everything proved about categories in general now applies to programs. The uniqueness of identities from the category post — id_unique_l, any arrow that leaves every arrow unchanged under composition is the identity — holds here word for word: any program that composes invisibly with every program is convertible to λx. x. And the smallest instance is checked directly in the file:

Example conv_idl_base : conv (tcomp (tid Base) (tid Base)) (tid Base).
Proof. exact (conv_left_identity Base Base (tid Base)). Qed.

The composite that tcomp_computes displayed as a genuinely different term is, up to conversion, the identity — which is the whole distinction between programs-as-text and programs-as-arrows, held in one example.
