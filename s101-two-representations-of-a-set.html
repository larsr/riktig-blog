Two representations of a set, and a theorem only one of them satisfies

Fix nn possible generators, numbered 00 through n−1n-1, and consider the subsets of them. There are 2n2^n. Here are two ways to store one.

The first is a row of nn bits, one per generator: bit ii says whether generator ii is in the set. The second is a single natural number, whose binary digits are those same bits — the subset {0,2}\{0, 2\} becomes the number 55.

The two schemes store exactly the same 2n2^n subsets, and both answer “is generator ii in this set?” in one step. But they differ in a way that is easy to overlook. A row of nn bits has exactly nn bits. A natural number has as many binary digits as it likes, and only the first nn are part of the subset. So at n=1n = 1, the numbers 00 and 22 store the same subset — the empty one — because bit 00 is clear in both and bit 11 is not part of the subset at all.

In the row scheme, then, two storage values denote the same subset exactly when they are the same value. In the number scheme they need not be. The question this post answers is whether any mathematical statement about subsets can tell the difference. It can, and the statements that can are a recognizable family: the ones that quantify over all functions out of the subsets.

Saying what a subset is, once

Both schemes should be able to share their theorems, so the theorems must be stated about neither one. What both schemes have is a membership test, and everything else follows from it: the empty subset is the one nothing belongs to, symmetric difference is the subset whose members belong to exactly one of two others, and so on.

That is enough to pin down the notion. A type class — a declaration of a family of facts indexed by a type, with instances registering one such fact for Coq to find by search — collects the membership function together with the equations it satisfies:

  Class Blade (I K B : Type)
      {eK : EqRel K} {zK : Zero K} {aK : HasAdd K} {nK : HasNeg K}
      {oK : One K} {mK : HasMult K} {bits : Boolean K}
      {eB : EqRel B} {zB : Zero B} {aB : HasAdd B} {nB : HasNeg B}
      {oB : One B} {mB : HasMult B} := {
    setoid          :: Equivalence (@equ B eB);
    member          : B -> I -> K;
    member_proper   :: Proper (equ ==> eq ==> equ) member;
    member_faithful : forall x y : B,
                        (forall i : I, member x i == member y i) -> x == y;
    member_empty    : forall i : I, member 0 i == (0 : K);
    member_full     : forall i : I, member 1 i == (1 : K);
    member_symmetric_difference : forall (x y : B) (i : I),
                        member (x + y) i == member x i + member y i;
    member_intersection : forall (x y : B) (i : I),
                        member (x * y) i == member x i * member y i;
    member_complement : forall (x : B) (i : I),
                        member (- x) i == - member x i;
  }.

B is the storage type, I the generator index, and K the type of bits. member x i is the membership test. The subsets carry 00, 11, ++ and ×\times — the empty subset, the full one, symmetric difference and intersection — and the four member_ equations say that membership carries each of them to the bit operation of the same name. member_faithful is the one that does the work below: two subsets with the same members are the same subset.

The equality being written == rather than = is what everything below turns on. A type paired with an equivalence relation standing in for equality is a setoid, and each scheme brings its own. The row scheme compares positions:

  (* Two rows are the same blade when they hold the same generators. *)
  #[export] Instance VectorBlade_EqRel : EqRel (Vector.t K n) :=
    fun v w => forall i : Fin.t n, Vector.nth v i == Vector.nth w i.

The number scheme compares the first nn bits, and says nothing about the rest:

  #[export] Instance MaskBlade_EqRel : EqRel (Mask n) :=
    fun x y => forall i : Fin.t n,
      N.testbit x (mask_bit i) = N.testbit y (mask_bit i).

Mask n is a machine word — the definition is Definition Mask (n : nat) : Type := N, an unbounded binary natural, with n recorded only in the type so that instance search can find the right equality.

The row scheme has no slack

Two rows that agree at every position are the same row. That is not a restatement of the definition: the definition says they agree pointwise, and the conclusion is that they are equal as data. For vectors of a fixed length, Vector.eq_nth_iff closes the gap.

(∀i.vi=wi)⇒v=w\bigl(\forall i.\ v_i = w_i\bigr) \;\Longrightarrow\; v = w

Lemma vector_bool_equ_eq : forall (n : nat) (v w : Vector.t bool n),
  v == w -> v = w.
Proof.
  intros n v w Hvw.
  apply Vector.eq_nth_iff. intros p q Hpq. rewrite <- Hpq. exact (Hvw p).
Qed.

Vector.eq_nth_iff wants agreement at any two indices known to be equal, which is slightly more than agreement at each index; rewrite <- Hpq turns the one into the other, and Hvw p is the hypothesis at that position.

One consequence is worth stating on its own. If subset equality is plain equality, then every function out of the subsets respects subset equality, whatever the function does — because there is nothing for it to fail to respect:

∀f.∀v,w.v≡w⇒f(v)≡f(w)\forall f.\ \forall v, w.\quad v \equiv w \;\Longrightarrow\; f(v) \equiv f(w)

In Coq, a function respecting an equivalence is written Proper (equ ==> equ) f, and the quantifier over f is the outermost one:

Lemma vector_blade_families_proper {F : Type} {eF : EqRel F}
    {RF : Reflexive (@equ F eF)} (n : nat) :
  forall f : Vector.t bool n -> F, Proper (equ ==> equ) f.
Proof.
  intros f v w Hvw. rewrite (vector_bool_equ_eq n v w Hvw). reflexivity.
Qed.

The proof rewrites the two equal rows into each other and appeals to reflexivity. It is quantified over all f, and assumes nothing about it.

The number scheme has slack, and it is visible

At width 11 the numbers 00 and 22 denote the same subset, since bit 00 is clear in both. Now take the function that asks whether its argument is the number zero. It says yes to 00 and no to 22. So it is a function on storage values that is not a function on subsets:

0≡2,f(x)=[x=0],f(0)=𝗍𝗋𝗎𝖾≠𝖿𝖺𝗅𝗌𝖾=f(2)0 \equiv 2, \qquad f(x) = [\,x = 0\,], \qquad f(0) = \mathsf{true} \neq \mathsf{false} = f(2)

That refutes, at this carrier, the statement the row scheme proved for every f:

Example word_families_are_not_all_proper :
  ~ (forall f : Mask 1 -> bool, Proper (equ ==> equ) f).
Proof.
  intros Hproper.
  assert (Hsame : (0%N : Mask 1) == 2%N)
    by (apply mask_agree_after_truncation; vm_compute; reflexivity).
  pose proof (Hproper (fun x : Mask 1 => N.eqb x 0) _ _ Hsame) as Hbit.
  vm_compute in Hbit. discriminate Hbit.
Qed.

The proof assumes the statement, feeds it the offending function, and computes. Hsame is the observation that 00 and 22 agree on bit 00; Hproper applied to N.eqb x 0 then claims N.eqb 0 0 = N.eqb 2 0, which vm_compute reduces to true = false.

Both carriers satisfy the same Blade class, and therefore every theorem proved from the class’s equations holds at both. The statement just refuted is not one of them: it quantifies over functions out of the carrier, so its subject is the storage, not the subsets.

Where it is needed, and what it buys

Here is a theorem that needs it. Sum a quantity over all 2n2^n subsets, then reindex the sum by taking the symmetric difference of every subset with one fixed subset DD. Symmetric difference with DD is its own inverse, so it permutes the subsets, and the sum is unchanged:

∑Af(D△A)=∑Af(A)\sum_{A} f(D \mathbin{\triangle} A) \;=\; \sum_{A} f(A)

The general reindexing lemma for such a sum asks for three things: that the reindexing be an involution, that it respect subset equality, and that the summand f respect subset equality. The first two are facts about symmetric difference. The third is a hypothesis about an arbitrary f — exactly the shape just shown to be carrier-dependent — and at the row carrier it is supplied by the lemma above:

  Lemma bsum_reindex : forall n (D : Blade n) (f : Blade n -> F),
    bsum (fun A => f (bxor D A)) == bsum f.
  Proof.
    intros n D f.
    calc (bsum (fun A => f (bxor D A)))
      == (bigopI (fun A => f (bxor D A))) { bsum_is_bigopI }
      == (bigopI (fun A => f (D + A)))
           { (bigopI_ext (fun A => f (bxor D A)) (fun A => f (D + A))
                (fun A => bsum_summand_at_eq f (bxor_is_add n D A))) }
      == (bigopI f)
           { (bigopI_reindex f (fun A => D + A) (fun A => D + A)
                (vector_blade_families_proper n f)
                (blade_add_left_proper n D) (blade_add_left_proper n D)
                (blade_shift D) (blade_shift D)) }
      == (bsum f) { bsum_is_bigopI }.
  Qed.

Each == line is one step of the displayed chain and the braces name its justification. The first and last convert between two spellings of the same sum. The second reads bxor, the bitwise exclusive-or of the storage, as the subsets’ +. The third is the reindexing lemma, and its middle argument is vector_blade_families_proper n f — the place where the row scheme’s lack of slack is spent.

Note what the statement does not say: it has no hypothesis about f. That is affordable here and only here. The same theorem at the number carrier would have to carry Proper (equ ==> equ) f as a hypothesis, because there it is not derivable, and callers would have to prove it for each summand they use.

Everything stated in terms of membership does hold at both, and both can be used at once. blade_shift is the law that symmetric difference with a fixed subset is its own inverse, proved once from the class’s equations; here it is applied at a row and at a number in the same term, with instance search picking the right equality for each:

Example shift_at_both_carriers (n : nat)
    (v w : Vector.t bool n) (x y : Mask n) :
  (v + (v + w) == w) /\ (x + (x + y) == y) :=
  conj (blade_shift v w) (blade_shift x y).

Neither half mentions rows or bits. The + on the left is Vector.map2 on booleans and the + on the right is N.lxor, and blade_shift knows about neither.

So the two representations are interchangeable for every theorem stated in terms of membership, and part company exactly when a statement quantifies over functions out of the carrier. That is a useful thing to be able to see in a statement before choosing a representation to prove it at.
