A finite index type is a duplicate-free enumeration, and a transposition is three equations

A sum over coordinates, a basis of nn vectors, a determinant of an n×nn \times n matrix — each needs a type of exactly nn indices to range over. What should “exactly nn elements” mean? For a type compared by Coq’s built-in equality the answer is folklore, but the types in this library are compared by a chosen equality: a setoid pairs the carrier with an equivalence relation ==, and two elements may be equal for every provable purpose while being distinct terms — the calc post sets this machinery up, with 1/2==2/41/2 == 2/4 in ℚ\mathbb{Q} as the standing example. Counting must respect that: a carrier with the three terms 1/21/2, 2/42/4, 3/63/6 has one element, not three.

The operational answer: a type has nn elements when some list enumerates it — every element occurs, none occurs twice, both up to == — and that list has length nn. Two questions follow immediately. Is nn well defined, or could one carrier own both a 3-element and a 4-element enumeration? And what do functions on such an index type look like, when every definition must respect an equality it did not choose? This post answers the first with a theorem and the second with a class of three equations.

The structure

Writing e=[i1,…,in]e = [i_1, \dots, i_n] for the enumeration, the three laws are

j≠k⇒¬(ij==ik),∀i.∃j.i==ij,|e|=n,j \neq k \;\Rightarrow\; \neg(i_j == i_k), \qquad \forall i.\; \exists j.\; i == i_j, \qquad |e| = n,

no duplicates, completeness, and the length. From Structure/Fin.v:

  Class FinIndex (n : nat) (I : Type) {eI : EqRel I} {Ieq : EquDec I} := {
    enum_equivalence :: Equivalence (@equ I eI);
    enum             : list I;
    enum_NoDup       : NoDupA equ enum;
    enum_complete    : forall i : I, InA equ i enum;
    enum_length      : length enum = n;
  }.

The vocabulary is the standard library’s SetoidList: InA equ i l is membership in l up to ==, and NoDupA equ l says no two positions of l hold ==-equal elements — precisely the two italicized “up to” clauses above. The two binders are the carrier’s equality EqRel and its decision procedure EquDec, the setoid form of decidable equality from the decidable-propositions post: dec (a == b) answers every equality question with a proof either way. One asymmetry is deliberate. Equivalence is a field: an index carrier has no algebra whose structure would already own the proof that == is reflexive, symmetric and transitive, so the enumeration structure carries it. Decidability stays a binder, because dec is an operation that definitions over the index type use — making it a field would turn an operation into a projection of a proof bundle.

The count is well defined

Suppose one carrier had two enumerations, e1e_1 of length nn and e2e_2 of length mm. Each is complete, so each element of e1e_1 occurs in e2e_2 and conversely: the two lists have the same elements up to ==. Two duplicate-free lists with the same elements are permutations of one another, and permuting a list does not change its length:

n=|e1|=|e2|=m.n \;=\; |e_1| \;=\; |e_2| \;=\; m.

The middle step is the content, and the standard library proves it: NoDupA_equivlistA_PermutationA turns “duplicate-free, same elements” into a PermutationA, the up-to-== permutation relation. From Theory/Fin.v:

Lemma finindex_cardinality_unique : forall (n m : nat) (I : Type)
    {eI : EqRel I} {Ieq : EquDec I}
    (F1 : FinIndex n I) (F2 : FinIndex m I),
  n = m.
Proof.
  intros n m I eI Ieq F1 F2.
  rewrite <- (@enum_length n I eI Ieq F1), <- (@enum_length m I eI Ieq F2).
  apply (PermutationA_length (eqA := @equ I eI)).
  apply NoDupA_equivlistA_PermutationA.
  - exact (@enum_equivalence n I eI Ieq F1).
  - exact (@enum_NoDup n I eI Ieq F1).
  - exact (@enum_NoDup m I eI Ieq F2).
  - intros x.
    split; intros _.
    + exact (@enum_complete m I eI Ieq F2 x).
    + exact (@enum_complete n I eI Ieq F1 x).
Qed.

Walking it: the two rewrite <- enum_length steps replace n and m by the two list lengths; PermutationA_length (from Lib/ListFacts.v) reduces equal lengths to a permutation; the standard library lemma asks for the equivalence proof, the two NoDupA facts, and elementwise mutual membership — and completeness of each enumeration answers the membership question in both directions without even looking at x. So the parameter n is a property of the carrier, not a choice: FinIndex 3 I and FinIndex 4 I cannot coexist.

A transposition is three equations

Functions on a setoid index type must respect ==, and there is a way to get that respect for free: define the function by equations whose hypotheses are ==-tests rather than by pattern matching on syntax. The exemplar is the transposition σij\sigma_{ij}, the permutation that exchanges ii and jj and fixes everything else:

σij(x)={jx==iix==j,i≠jxotherwise.\sigma_{ij}(x) = \begin{cases} j & x == i \\ i & x == j,\; i \neq j \\ x & \text{otherwise.} \end{cases}

From Theory/Fin.v, those three cases as a class over the operation:

  Class Swap {I : Type} {eI : EqRel I} (swap : I -> I -> I -> I) := {
    swap_at_i : forall i j x : I, x == i -> swap i j x == j;
    swap_at_j : forall i j x : I, ~ (i == j) -> x == j -> swap i j x == i;
    swap_ne   : forall i j x : I, ~ (x == i) -> ~ (x == j) -> swap i j x == x;
  }.

Note what is not a field: respect for ==. The three equations already pin the value of swap i j on every ==-class of the carrier, so respect is derivable — decide where the argument sits with dec, and in each of the three cases both sides reduce by the matching equation. That derivation is swap_proper in the same file, and it is the pattern’s selling point: state the equations with == hypotheses, and congruence comes out instead of going in.

Every further law of transpositions is a consequence of the three equations, with no access to any implementation: swap_invol (σij(σij(x))==x\sigma_{ij}(\sigma_{ij}(x)) == x), swap_symmetric (σij==σji\sigma_{ij} == \sigma_{ji} pointwise), swap_conj (conjugation by a transposition), and injectivity. Injectivity is the shortest and shows the style — on the blackboard it is one chain from the involution,

x==σ(σ(x))==σ(σ(y))==y,x \;==\; \sigma(\sigma(x)) \;==\; \sigma(\sigma(y)) \;==\; y,

by the involution law, the hypothesis σ(x)==σ(y)\sigma(x) == \sigma(y) under σ\sigma’s congruence, and the involution law again. In Coq, as a calc chain:

  Lemma swap_inj : forall i j x y : I, swap i j x == swap i j y -> x == y.
  Proof.
    intros i j x y Heq.
    calc x
      == (swap i j (swap i j x))  { (symmetry (swap_invol i j x)) }
      == (swap i j (swap i j y))  { (swap_proper i j _ _ Heq) }
      == y                        { (swap_invol i j y) }.
  Qed.

The three steps are the three blackboard steps, in order — and the middle one uses the derived swap_proper, the congruence the class never had to assume.

The instance: Coq’s Fin.t

Fin.t n, the standard library’s type of numbers below n, is the canonical carrier. Its equality is Coq’s built-in one, and a carrier whose == is built-in equality enters the setoid interface through one constructor, finindex_from_leibniz in Impl/FinIndex.v, which lifts ordinary In/NoDup facts to their InA/NoDupA forms. The enumeration is structural recursion, from Impl/Fin.v:

Fixpoint fin_all (n : nat) : list (Fin.t n) :=
  match n with
  | O => nil
  | S m => cons Fin.F1 (map Fin.FS (fin_all m))
  end.

with fin_all_complete, fin_all_NoDup and fin_all_length proved by induction, and the instance is their assembly:

Instance FinIndex_Fin (n : nat) : FinIndex n (Fin.t n) :=
  finindex_from_leibniz (fin_all n) (fin_all_NoDup n)
    (fin_all_complete n) (fin_all_length n).

The computing transposition decides against each endpoint — the three class equations, read as a program:

Definition swap {I : Type} {eqdec : EqDec I} (i j r : I) : I :=
  if dec (r = i) then j
  else if dec (r = j) then i
  else r.

Its Swap instance (swap_Swap, same file) is the only place this definition is ever unfolded; everything downstream — the determinant chain permutes matrix rows with it — uses the three equations alone.

What the enumeration is for is summation: bigopI f sums f over enum, and the Kronecker delta delta — from Theory/BigOp.v, over any finite index type —

  Definition delta (i j : I) : R := if dec (i == j) then 1 else 0.

collapses such sums: ∑iciδij=cj\sum_i c_i\, \delta_{ij} = c_j, which is bigopI_delta, proved once from the enumeration laws. The check that instance search assembles the whole chain unaided at the concrete carrier is an Example in Impl/FinIndex.v:

Example finindex_delta_check (F : Type) `{FF : Field F} (n : nat)
    (c : Fin.t n -> F) (j : Fin.t n) :
  bigopI (fun i => c i * delta i j) == c j :=
  bigopI_delta c j (leibniz_proper c).

The basis post is this collapse at work: coordinates of a vector against a basis are read off by exactly this sum.
