What real numbers need: least-upper-bound completeness

A field is a set with +, *, a zero, a one, negation, and inverses of everything except zero, obeying the ordinary arithmetic laws — the rationals Q are the standard example. An ordered field adds a total order <= that is compatible with the arithmetic: adding the same thing to both sides preserves the order, and the product of two nonnegative elements is nonnegative. The rationals are an ordered field too. So what separates the real numbers from the rationals is not any of the algebra and not the order — it is one further property, which this post is about.

The property Q is missing

Take the set of rationals whose square is at most two:

P={q∣q⋅q≤2}.P = \{\, q \mid q \cdot q \le 2 \,\}.

This set is inhabited (it contains 1) and it is bounded above (by 2, say — nothing in it exceeds 2). Ask for its least upper bound, the smallest rational that sits above every element of P. There isn’t one. Any rational upper bound can be nudged down a little and still be an upper bound, closing in on 2\sqrt 2 from above without ever reaching it, because 2\sqrt 2 is not rational. The candidate boundary falls outside the number system. That single failure — a bounded, inhabited set with no least upper bound — is the one thing that makes Q “gappy” and the reals “complete”.

Least-upper-bound completeness is the axiom that closes the gap: every inhabited, bounded-above set does have a least upper bound (a supremum) inside the system. That, plus the ordered-field structure, is the whole specification of the real numbers.

The ordered field comes first, and separately

Everything in the first paragraph — the arithmetic, the order, the two compatibility conditions — is already a structure of its own, OrderedField in Structure/Order.v. It takes a type F that is already a Field, an order le and an absolute value abs on it, and states the laws all three must jointly satisfy:

Module OrderedField.
  Class OrderedField (F : Type) `{Field F}
                     {le : HasLe F} {abs : HasAbs F} := {
    le_proper  :: Proper (equ ==> equ ==> iff) le;
    abs_proper :: Proper (equ ==> equ) abs;

    le_reflexive         :: Reflexive le;
    le_transitive        :: Transitive le;
    le_antisymmetric     :: Antisymmetric F equ le;
    le_total             : forall a b : F, a <= b \/ b <= a;
    le_stable            : forall a b : F, ~ ~ a <= b -> a <= b;
    add_le_monotone_left : forall a b c : F, a <= b -> c + a <= c + b;
    mul_nonneg_closed    : forall a b : F, 0 <= a -> 0 <= b -> 0 <= a * b;
    abs_nonneg           : forall a : F, 0 <= abs a;
    abs_zero_iff         : forall a : F, abs a == 0 <-> a == 0;
    abs_mul              : forall a b : F, abs (a * b) == abs a * abs b;
    abs_neg              : forall a : F, abs (- a) == abs a;
    abs_triangle         : forall a b : F, abs (a + b) <= abs a + abs b;
    abs_nonneg_identity  : forall a : F, 0 <= a -> abs a == a;
  }.
End OrderedField.

The order half is the five laws after the two properness fields: <= is reflexive, transitive, antisymmetric and total — a total order, not merely a partial one — and le_stable says a doubly-negated inequality is an inequality, which is what lets a proof argue by contradiction about <= without assuming excluded middle everywhere. Then add_le_monotone_left and mul_nonneg_closed are the two compatibility conditions that make the order an order of a field: you may add the same c to both sides, and a product of two nonnegative elements is nonnegative. The last six laws pin down abs. It is carried as its own operation rather than defined as “if 0 <= a then a else - a,” because that definition would have to decide the order, and for a general model of the reals no such decision procedure exists.

Two fields are declared with :: rather than :. That makes the field itself a typeclass instance whenever an OrderedField F is in scope, so rewrite can replace an argument of <= or of abs by anything == to it without the law ever being named.

The rationals satisfy every line of that class. So does every model of the reals. The class does not distinguish them.

The specification, in full

Here is Structure/Reals.v, the entire file:

From Riktig.Structure Require Export Order.

Module Reals.
  Class Reals (R : Type) `{OrderedField R} := {
    complete : forall P : Pred R,
      (exists x : R, P x) ->
      (exists b : R, forall x : R, P x -> x <= b) ->
      exists s : R,
        (forall x : R, P x -> x <= s) /\
        (forall b : R, (forall x : R, P x -> x <= b) -> s <= b);
  }.
  Hint Mode Reals ! - - - - - - - - - - - : typeclass_instances.
End Reals.
Export Reals.

One field. The backtick binder `{OrderedField R} says: before you may even state this, R must already be an ordered field, and the <= appearing below is that order — not a fresh relation with its own copy of the order laws. Everything the first two sections described is inherited, and what is left is the single thing the rationals lack.

Read complete as a sentence about an arbitrary set P : Pred R, where Pred T abbreviates T -> Prop — a set is the property of belonging to it. If P is inhabited (exists x, P x) and bounded above (exists b above every element), then there exists an s that is (i) an upper bound — forall x, P x -> x <= s — and (ii) the least one: any other upper bound b satisfies s <= b, so s sits below every competitor. Those two conjuncts are the definition of “least upper bound”, written out with no appeal to anything outside the class.

The Hint Mode line tells Coq’s instance search to wait until it knows the carrier type R — the position marked ! — before trying to solve a Reals goal. Without it, search asked for Reals ?R would try to invent the carrier, which does not terminate.

No instance — on purpose

Nowhere does the file exhibit a concrete type and prove it satisfies Reals. The specification says what a real-number system must satisfy and stops there.

That is deliberate, and it is worth being clear about why it is a reasonable choice rather than an unfinished one.

Building an actual model of Reals means constructing the reals — as Dedekind cuts, or as equivalence classes of Cauchy sequences of rationals, or by importing Coq’s standard-library R — and then discharging every field of the class for that construction. Each of these is a substantial, self-contained development in its own right, and they have essentially nothing to do with the things one proves using completeness. The intermediate value theorem, the mean value theorem, the existence of suprema in any argument that needs them — these are statements about any type satisfying Reals, and their proofs quote complete and the order laws by name, never the internal machinery of cuts or sequences.

The reward for the split is concrete. Anything proved generically against the Reals class — with a Context {R : Type} `{Reals R} at the top, the way Theory/Exp.v proves things against Exp — holds automatically for every model the class will ever have. Prove the intermediate value theorem once from complete, and it is simultaneously a theorem about the classical stdlib reals and about the constructive Cauchy reals, the moment either instance is supplied. The construction is a plug fitted later into a socket whose shape is already fixed; the theorems are wired to the socket, not the plug.

The split also explains why the file is fourteen lines. A first draft might reasonably have restated the order and its eight laws inside Reals, and the class would then carry two orders that happen to coincide — its own le and the ordered field’s — with every downstream lemma having to be told which one it meant. Requiring OrderedField as a superclass instead means there is exactly one <= in play, and the file has nothing left to say except the one axiom that distinguishes the reals from the rationals.
