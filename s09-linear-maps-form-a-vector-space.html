Linear algebra without coordinates

A first linear algebra course usually reaches matrices within a week, and from then on a “linear map” means a grid of numbers. But the two defining equations of a linear map mention no grid, and neither do most of its theorems. This post does a piece of the course the other way: the maps themselves, no coordinates anywhere, with each proof shown twice — once as you would write it on a blackboard, once as Coq checks it — so you can compare them line by line.

The cast: linear maps

A linear map between vector spaces is a function that respects the structure: it carries sums to sums and scalings to scalings,

f(u+v)=f(u)+f(v)f(au)=af(u),f(u + v) = f(u) + f(v) \qquad f(a\,u) = a\,f(u),

and it respects the chosen equality == on each space — throughout, == is a setoid equality, an equivalence relation picked for the carrier, not Coq’s equality of terms. Those three demands are stated as a class about a plain function, so a lambda written anywhere can be shown linear without first being packaged (Interface/Linear.v):

Class Linear (F U V : Type)
    {eU : EqRel U} {aU : HasAdd U} {sU : HasScale F U}
    {eV : EqRel V} {aV : HasAdd V} {sV : HasScale F V}
    (f : U -> V) := {
  proper         :: Proper (equ ==> equ) f;
  is_additive    :: Additive U V add add f;
  is_homogeneous :: Homogeneous F U V scale (fun a => a) f;
}.

Additive and Homogeneous are two one-line classes that take the operations they talk about as arguments, so the same class serves several situations. Additive U V add add f unfolds to f (x + y) == f x + f y — carry + on U to + on V. Homogeneous F U V scale (fun a => a) f unfolds to f (a *: x) == a *: f x, where the fun a => a is the weight applied to the scalar on the way through: the identity here, but a squaring for a quadratic form, which is why the class takes it as a parameter rather than fixing it. The :: in front of each field registers it for instance search, so anything already known to be additive — a linear map, multiplication by a ring element — is found by search rather than named by hand.

A linear map is then the data: the function, plus a proof that it is linear (Interface/LinearMap.v):

Record LinearMap (F U V : Type)
    {eU : EqRel U} {aU : HasAdd U} {sU : HasScale F U}
    {eV : EqRel V} {aV : HasAdd V} {sV : HasScale F V} := {
  lm_fun :> U -> V;
  lm_linear :: Linear F U V lm_fun;
}.

lm_fun is declared a coercion (:>), so a map is applied as f u and never as lm_fun f u. The three laws are reachable under the names linear_map_proper, linear_map_additive and linear_map_scale, which is how the proofs below name them.

Theorem 1: a linear map sends zero to zero

Every course proves this first, and the proof is a small gem because it doesn’t use what you’d expect — no scaling by 0, just additivity and cancellation.

Blackboard. f(0)=f(0+0)=f(0)+f(0)f(0) = f(0+0) = f(0) + f(0). Now cancel one f(0)f(0) from both sides of f(0)+f(0)=f(0)+0f(0) + f(0) = f(0) + 0… wait, that’s the trick: rewrite the goal f(0)=0f(0) = 0 as f(0)+f(0)=f(0)+0f(0) + f(0) = f(0) + 0 and cancel on the left. ∎

In Coq (Theory/Group.v — note it’s proved for any additive map between groups; vector spaces inherit it):

Theorem hom_zero : f 0 == 0.
Proof.
  apply (cancel_l (f 0)).
  calc (f 0 + f 0)
    == (f (0 + 0)) { (fadd 0 0) }
    == (f 0)       { left_identity }
    == (f 0 + 0)   { right_identity }.
Qed.

To check the Coq proof against the blackboard, you need the types of the pieces:

name statement
cancel_l forall a b c, a + b == a + c -> b == c
fadd forall a b, f (a + b) == f a + f b (the map’s additivity)
left_identity, right_identity 0 + a == a, a + 0 == a

Read it backwards, the way apply works: to show f 0 == 0, by cancel_l it suffices to show f 0 + f 0 == f 0 + 0. The calc block is that chain written out, each step naming the law that licenses it: fadd read right to left folds f 0 + f 0 into f (0 + 0); left_identity collapses the inner 0 + 0 to 0; right_identity expands f 0 into f 0 + 0, the right-hand side wanted. Each { ... } holds the justification for the step above it, and the block elaborates to a chain of transitivity steps — so the displayed proof and the term Coq checks are the same sequence of equalities.

The twist: the maps themselves form a vector space

Here is where the course usually gets interesting. Define, for linear maps f,g:U→Vf, g : U \to V,

(f+g)(u)=f(u)+g(u),(af)(u)=af(u).(f + g)(u) = f(u) + g(u), \qquad (a\,f)(u) = a\,f(u).

Claim: with these operations, Hom(U,V)\mathrm{Hom}(U,V) — the set of all linear maps U→VU \to V — is itself a vector space.

There are two things to prove, and they are different in kind:

Closure (the interesting part): f+gf + g must again be linear. Blackboard, for additivity:

(f+g)(u+v)=f(u+v)+g(u+v)=(f(u)+f(v))+(g(u)+g(v))=!(f(u)+g(u))+(f(v)+g(v))(f+g)(u+v) = f(u+v) + g(u+v) = \big(f(u)+f(v)\big) + \big(g(u)+g(v)\big) \stackrel{!}{=} \big(f(u)+g(u)\big) + \big(f(v)+g(v)\big)

The marked step is the interchange law — swapping the middle two summands — which holds in any abelian group. In Theory/HomVS.v:

Lemma hom_plus_add : forall u v : U,
  f (u + v) + g (u + v) == (f u + g u) + (f v + g v).
Proof.
  intros u v.
  rewrite (linear_map_additive f u v), (linear_map_additive g u v).
  apply add_interchange.
Qed.

with add_interchange : (a + b) + (c + d) == (a + c) + (b + d) doing exactly the marked step. Closure of afa\,f under the scale law is the one place a commutativity of scalars is used: af(bu)=abf(u)=baf(u)=b(af(u))a\,f(b\,u) = ab\,f(u) = ba\,f(u) = b\,(a\,f(u)) — that step is the lemma scale_swap, and it is why Hom over a noncommutative ring would be a subtler story.

Laws (the routine part, and that’s the point): associativity, identities, inverses for + on maps all hold because they hold at every point u. Take the left identity: the zero of Hom(U,V)\mathrm{Hom}(U,V) is the map sending everything to 00, so

(0+f)(u)=0(u)+f(u)=0+f(u)=f(u),(0 + f)(u) = 0(u) + f(u) = 0 + f(u) = f(u),

the middle step being nothing but VV’s own left-identity law at the point uu. In Coq:

Lemma hom_idl : forall f : Hom, 0 + f == f.
Proof.
  intros f u.
  exact (left_identity _).
Qed.

intros f u fixes the map and a single argument u, because equality of linear maps is agreement at every argument; what remains is V’s own identity law at that point. The scaling laws bundle into a ScaleLaws F Hom instance and the additive ones into an AbGroup Hom, and a vector space is exactly those two put side by side:

#[export] Instance Hom_VectorSpace : VectorSpace F Hom := {}.

VectorSpace has precisely those two fields — an abelian group of vectors and the laws relating scalars to it — so building the instance means naming the two proofs already in hand, with nothing further to prove.

Dual space: measurements are vectors too

A special case with a famous name (Theory/Hom.v):

V*=Hom(V,F)V^* \;=\; \mathrm{Hom}(V, F)

the dual space — linear “measurements” of vectors. Since scalars form a (one-dimensional) vector space over themselves, V*V^* is a vector space by the theorem above, with nothing new to prove: the instance resolves automatically:

Example dual_vs_check (F V : Type) `{FF : Field F} `{VV : VectorSpace F V} :
  VectorSpace F (Dual F V) := _.

That underscore is Coq assembling the whole proof by instance search.

And now the most elegant map in this post. Every vector vv is a measurement of measurements: feed it a functional, it returns the functional’s value on it:

ι:V→V**,ι(v)(φ)=φ(v).\iota : V \to V^{**}, \qquad \iota(v)(\varphi) = \varphi(v).

Note what is not in that definition: no basis, no coordinates, no choices. This map is into_double_dual. Its underlying function is written bilinear_map_appr eval_pair: eval_pair is the two-slot map (φ,v)↦φ(v)(\varphi, v) \mapsto \varphi(v), and bilinear_map_appr fixes its right slot, leaving a linear map in the remaining one — that is exactly v↦(φ↦φ(v))v \mapsto (\varphi \mapsto \varphi(v)). Its linearity is each φ\varphi’s own linearity read backwards — ι(u+v)(φ)=φ(u+v)=φ(u)+φ(v)=(ι(u)+ι(v))(φ)\iota(u+v)(\varphi) = \varphi(u+v) = \varphi(u)+\varphi(v) = \big(\iota(u)+\iota(v)\big)(\varphi) — so its additivity proof has nothing left to do but fix a functional and hand over that functional’s own law:

Lemma dd_add : forall u v : V,
  bilinear_map_appr eval_pair (u + v) == bilinear_map_appr eval_pair u + bilinear_map_appr eval_pair v.
Proof.
  intros u v f.
  exact (linear_map_additive f u v).
Qed.

intros u v f fixes the two vectors and then a functional f, since equality in the double dual is agreement on every functional; exact (linear_map_additive f u v) is φ\varphi testifying for the map. (That ι\iota is an isomorphism when VV is finite-dimensional is a later theorem; it needs bases, which is exactly why it’s later.)

What the space of maps is for

Once Hom(U,V)\mathrm{Hom}(U,V) is a vector space, it is the place representations of operations live. Choosing bases for UU and VV gives an isomorphism

Hom(U,V)≅Fm×n\mathrm{Hom}(U,V) \;\cong\; F^{m \times n}

and with it the theorem [[g∘f]]=[[g]][[f]][\![g \circ f]\!] = [\![g]\!]\,[\![f]\!]: matrix multiplication is function composition, transported along that isomorphism. Every matrix identity is then a rewrite along a representation change rather than a fresh calculation with indices. The blackboard and the machine agree; bring your own coordinates, or don’t.
