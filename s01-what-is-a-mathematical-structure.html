Mathematical structures, and how this library encodes them

Programmers already know half of what a mathematical structure is. An interface says which operations exist: this thing can be compared, that thing can be concatenated. What an interface does not say is what the operations mean. A sort function that returns its input unsorted satisfies the interface list → list perfectly. A mathematical structure is the missing half — this post is about that missing half, and about a handful of structures built from it, each one a little richer than the last.

Structures are interfaces with laws

The missing half is a vocabulary of operations plus the laws those operations must obey. Not “there is a +”, but “there is a +, and it never matters how you parenthesize it”. The laws are the meaning. Two structures with the same operations but different laws are different worlds.

The classic first example. Lots of things can be combined: numbers add, strings concatenate, program fragments sequence, rotations compose. Superficially unrelated — but in each case, combining is associative

(a⋅b)⋅c=a⋅(b⋅c)(a \cdot b) \cdot c \;=\; a \cdot (b \cdot c)

and there is a do-nothing element (zero, the empty string, the no-op, the identity rotation) that combines invisibly. That pair of laws has a name: a monoid. The payoff of naming it: anything you prove from the two laws alone is instantly true for numbers, strings, programs, and rotations — and for every combinable thing anyone invents later. Prove once, hold everywhere. That is the entire business model of algebra.

Structures then stack, each adding vocabulary and laws to the last:

Structure Adds New laws (typeset the way we state them)
Magma + none yet — only that == is an equivalence and + respects it
Semigroup — (a + b) + c == a + (b + c) — parenthesisation is irrelevant
Monoid 0 0 + a == a, a + 0 == a
Group - a (- a) + a == 0, a + (- a) == 0 — every combination can be undone
Abelian group — a + b == b + a — order of combination is irrelevant
Ring *, 1 * is an (associative, unital) second operation, tied to the first by distributivity: a * (b + c) == a * b + a * c
Field inv nonzero elements can be divided: inv a * a == 1 (for a =/= 0)
Vector space *: vectors form an abelian group, scalars from a field act on them: (a + b) *: u == a *: u + b *: u, 1 *: u == u
Inner product ⟨u, v⟩ a symmetric, bilinear pairing: ⟨u, v⟩ == ⟨v, u⟩, ⟨u + v, w⟩ == ⟨u, w⟩ + ⟨v, w⟩
Geometric algebra ga_vec vectors become multipliable: embed V in a ring where v * v == Q v *: 1 — a vector squared is its length²

Read the table top to bottom and you can watch capability accumulate: combine → regroup → do nothing → undo → reorder → multiply → divide → scale → measure → multiply geometry itself. Each row inherits every law above it. (Topology does the same trick with a different vocabulary — instead of + and its laws, it is “open sets” and laws about how they union and intersect. Same idea: vocabulary plus laws; only the subject changes.)

How this looks in Coq

The encoding keeps four things in four kinds of files, and the separation is the point.

1. The vocabulary (theories/Ops.v) — one tiny typeclass per symbol, no laws at all:

Class HasAdd T := add : BinOp T.
Infix "+" := add.

Class Zero T := zero : T.
Notation "'0'" := zero.

This is what lets every later law be written in notation: once a structure provides HasAdd, the literal symbol + works for it.

2. The single laws (theories/Props.v) — one class per law, so a law is a first-class, nameable thing. The laws about combining are stated over an action: a function A -> B -> B letting an element of one type act on an element of another.

Section ActionLaws.
  Context (A B : Type) {eqB : EqRel B} (action : A -> B -> B) (op : BinOp A).
  Local Infix "·" := action (at level 40, left associativity).
  Local Infix "⋆" := op (at level 40, left associativity).

  Class Associative := associative : forall (a b : A) (x : B), (a ⋆ b) · x == a · (b · x).
End ActionLaws.

Take B to be A and the action to be the operation itself, and this is ordinary associativity, (a + b) + c == a + (b + c). Take A to be a type of scalars, B a type of vectors, op scalar multiplication and the action scaling, and the very same class says (a * b) *: u == a *: (b *: u). One class, two laws that would otherwise have to be stated twice. LeftIdentity and RightIdentity are shaped the same way — a monoid’s 0 and a scaling’s 1 are the same law at different actions — while Commutative, LeftInverse and RightInverse mention one type only.

3. The structures (theories/Interface/) — classes stating laws over that vocabulary, axioms only, no theorems. The operations arrive as class parameters (the {eq : EqRel M} binders below), so a structure assumes the vocabulary rather than owning it, and each class holds the structure one step below it plus the laws it adds. At the bottom sits a carrier with one operation and one obligation:

Module Magma.
  Class Magma (M : Type) {eq : EqRel M} (op : BinOp M) := {
    equivalence :: Equivalence eq;
    op_proper   :: Proper (equ ==> equ ==> equ) op;
  }.
  Hint Mode Magma ! - - : typeclass_instances.
End Magma.
Export Magma.

Magma.equivalence says == really is an equivalence relation, and Magma.op_proper says the operation respects it, in the standard library’s spelling Proper (equ ==> equ ==> equ) op: replacing either argument by an equal one gives an equal result. Both are declared with :: rather than :, which makes the field an instance in its own right, so a rewrite under + finds it without the magma being named. The Hint Mode line stops instance search from hunting for a magma before it knows the carrier. The Module wrapper is a namespace, so the fields carry plain English names inside and are read qualified from outside — Magma.equivalence, Magma.op_proper — while the closing Export puts the class itself in scope under its short name.

Two more files, three more laws, and the monoid is reached:

Module Semigroup.
  Class Semigroup (S : Type) {eq : EqRel S} (op : BinOp S) := {
    magma       :: Magma S op;
    is_associative :: Associative S S op op;
  }.
  Hint Mode Semigroup ! - - : typeclass_instances.
  Hint Rewrite @associative : algebra_db.
End Semigroup.
Export Semigroup.
Module Monoid.
  Class Monoid (M : Type) {eq : EqRel M} {zero : Zero M} {add : HasAdd M} := {
    semigroup         :: Semigroup M add;
    is_left_identity  :: LeftIdentity M M add 0;
    is_right_identity :: RightIdentity M M add 0;
  }.
  Hint Mode Monoid ! - - - : typeclass_instances.
  Hint Rewrite @left_identity @right_identity : algebra_db.
End Monoid.
Export Monoid.

Look at what those fields hold. Semigroup.is_associative does not restate associativity: it is an Associative, the law class above, at A = B = S with both the operation and the action taken to be op. And Monoid.semigroup is not a copy of the semigroup’s laws but a semigroup itself, held as a field. The Hint Rewrite lines file each new law in a database, so autorewrite with algebra_db can simplify a goal without any law being cited by hand.

A group is a monoid with a negation and its two undo laws:

Module Group.
  Class Group (G : Type) {eq : EqRel G} {zero : Zero G} {add : HasAdd G}
              {neg : HasNeg G} := {
    monoid           :: Monoid G;
    neg_proper       :: Proper (equ ==> equ) neg;
    is_left_inverse  :: LeftInverse G add neg 0;
    is_right_inverse :: RightInverse G add neg 0;
  }.
  Hint Mode Group ! - - - - : typeclass_instances.
  Hint Rewrite @left_inverse @right_inverse : algebra_db.
End Group.
Export Group.

The table’s “each row inherits every law above it” is therefore nothing anyone has to register: Group.monoid is the inheritance, and because it is declared with ::, instance search projects it out on its own. Anything that knows “G is a group” thereby knows “G is a monoid” — and, one hop further down, a semigroup and a magma — so every theorem proved from the monoid laws alone applies to a group unchanged.

4. The consequences (theories/Theory/) — theorems derived from the laws alone, valid for every instance forever. Here is a real one, exactly as it appears in theories/Theory/Group.v. In a group, cancelling on the left is legitimate:

Theorem cancel_l : forall a b c : G, a + b == a + c -> b == c.
Proof.
  intros a b c Heq.
  calc b
    == (0 + b)          { left_identity  }
    == ((- a + a) + b)  { left_inverse }
    == (- a + (a + b))  { associative }
    == (- a + (a + c))  { Heq  }
    == ((- a + a) + c)  { associative }
    == (0 + c)          { left_inverse }
    == c                { left_identity  }.
Qed.

The calc block is the calculation, written the way you would on paper:

b=0+b=(−a+a)+b=−a+(a+b)=Heq−a+(a+c)=(−a+a)+c=0+c=cb \;=\; 0+b \;=\; (-a+a)+b \;=\; -a+(a+b) \;\overset{\text{Heq}}{=}\; -a+(a+c) \;=\; (-a+a)+c \;=\; 0+c \;=\; c

— each == line one step, each { … } naming the single law that justifies it (left_identity, left_inverse and associative are the methods of the law classes of Props.v, which the group’s fields supply). That is the proof style throughout: every proof is a chain of equalities, each step justified by a named law — the same equational reasoning you did in school algebra, machine-checked. No proof scripts full of tactic incantations; if a step doesn’t have a name, it is factored out as a lemma and given one.

What is proved so far

So that “consequences derived from the laws alone” is not left abstract, here is the actual inventory of the first three theory files — small enough to read in one sitting. Theory/Monoid.v proves the identity element is unique (id_unique, and the specializations zero_unique_l, zero_unique_r). Theory/Group.v proves inverses are unique (neg_unique_l, neg_unique_r), that negation is an involution and injective (neg_involutive, neg_inj), - 0 == 0 (neg_zero), - (a + b) == - b + - a (neg_add_flip), both cancellation laws (cancel_l, cancel_r), and two telescoping facts (add_neg_telescope, sub_eq_zero); a section of it shows that any map f preserving + between groups automatically preserves 0 and - (hom_zero, hom_neg), and it ends by packaging the identity and inverse laws as a rewrite database named grp that closes routine goals in one autorewrite. Theory/AbGroup.v adds the reshuffling kit that commutativity makes available: moving a summand past a sum (add_swap_l, add_swap_r), the interchange law (a + b) + (c + d) == (a + c) + (b + d) (add_interchange, with add_rotate as a variant), - (a + b) == - a + - b (neg_add), and a family of cancellation-in-context lemmas (add_sub_cancel, sub_pair, add_neg_cancel_l, and friends) — each stated because some later proof needs exactly that shape of shuffle, and naming it keeps that proof a one-line rewrite.

The payoff at the top of the tower

The chain culminates (for now) in geometric algebra, where the axiom “a vector squares to its length” makes the whole preceding tower earn its keep. Length arrives as a quadratic form: a function Q : V -> F sending a vector to its squared length, required to scale by the square of the scalar, Q(au)=a2Q(u)Q(a\,u) = a^2\,Q(u), and to have a cross term

polar⁡Q(u,v)=Q(u+v)−Q(u)−Q(v)\operatorname{polar}_Q(u,v) \;=\; Q(u+v) - Q(u) - Q(v)

that is linear in uu for each fixed vv. For the squared length of ordinary geometry the cross term works out to twice the inner product. It is a plain definition, from Interface/QuadraticForm.v:

Definition polar {F V : Type} `{VectorSpace F V} (Q : V -> F) (u v : V) : F :=
  Q (u + v) + - Q u + - Q v.

The geometric-algebra interface (Interface/GeometricAlgebra.v) embeds a vector space V into a ring A by a linear map ga_vec, and asks for one law beyond linearity:

Module GeometricAlgebra.
  Class GeometricAlgebra (F V A : Type) `{QuadraticForm F V}
      {Ae : EqRel A} {Az : Zero A} {Aa : HasAdd A} {An : HasNeg A}
      {Ao : One A} {Am : HasMult A} {As : HasScale F A} := {
    ring    :: Ring A;
    scaling :: ScaleLaws F A;

    mul_linear_l :: forall y : A, Linear F A A (fun x => x * y);
    mul_linear_r :: forall x : A, Linear F A A (fun y => x * y);

    ga_vec     : V -> A;
    vec_linear :: Linear F V A ga_vec;

    contraction : forall u : V, ga_vec u * ga_vec u == Q u *: 1;
  }.
  Hint Mode GeometricAlgebra - - ! - - - - - - - - - - - - - - - - - - - - - - - : typeclass_instances.
End GeometricAlgebra.
Export GeometricAlgebra.

The first two fields are the tower again, held rather than restated: A is a ring, and the scalars of V scale it too. The next two say multiplication is linear in each argument separately. ga_vec is the embedding, vec_linear says it is linear, and GeometricAlgebra.contraction is the axiom — a vector squared is its length². (The long Hint Mode line is the same annotation the magma carried, one dash per parameter, with ! on the one that must be known before search may start.) From just that, Theory/GeometricAlgebra.v derives the polarization identity

uv+vu=polar⁡Q(u,v)1uv + vu \;=\; \operatorname{polar}_Q(u,v)\,1

— the symmetric part of the geometric product is the form’s cross term, which is the seed of everything geometric algebra is good for (rotations and reflections). It deserves the same slow walk as cancel_l.

On paper. Square the sum u+vu + v two ways. Expanding the product, (u+v)2=u2+uv+vu+v2(u+v)^2 = u^2 + uv + vu + v^2, and contraction turns the two squares into (Q(u)+Q(v))1(Q(u) + Q(v))\,1. Contracting directly, (u+v)2=Q(u+v)1(u+v)^2 = Q(u+v)\,1. So, adding (Q(u)+Q(v))1(Q(u)+Q(v))\,1 to the identity we want:

(Q(u)1+Q(v)1)+(uv+vu)=Q(u+v)1{the two squarings equated}=((Q(u)+Q(v))+polar⁡Q(u,v))1{definition of the cross term}=(Q(u)+Q(v))1+polar⁡Q(u,v)1{scaling distributes over scalar sums}=(Q(u)1+Q(v)1)+polar⁡Q(u,v)1{the same law again}\begin{aligned} (Q(u)\,1 + Q(v)\,1) + (uv + vu) &= Q(u+v)\,1 &&\{\text{the two squarings equated}\}\\ &= \big((Q(u) + Q(v)) + \operatorname{polar}_Q(u,v)\big)\,1 &&\{\text{definition of the cross term}\}\\ &= (Q(u) + Q(v))\,1 + \operatorname{polar}_Q(u,v)\,1 &&\{\text{scaling distributes over scalar sums}\}\\ &= (Q(u)\,1 + Q(v)\,1) + \operatorname{polar}_Q(u,v)\,1 &&\{\text{the same law again}\} \end{aligned}

Both ends now begin with the summand Q(u)1+Q(v)1Q(u)\,1 + Q(v)\,1; cancelling it on the left — with exactly the cancel_l proved above — leaves the identity.

In the repository, exactly as it appears (a helper lemma contract_add packages the first step, and polar_recovers the second):

Theorem polarization : forall u v : V,
  ga_vec u * ga_vec v + ga_vec v * ga_vec u == polar Q u v *: (1 : A).
Proof.
  intros u v.
  apply (cancel_l (Q u *: (1 : A) + Q v *: 1)).
  calc (((Q u *: (1 : A) + Q v *: 1)
          + (ga_vec u * ga_vec v + ga_vec v * ga_vec u)) : A)
    == ((Q (u + v) *: (1 : A)) : A)
      { (contract_add u v) }
    == ((((Q u + Q v) + polar Q u v) *: (1 : A)) : A)
      { (polar_recovers u v) }
    == (((Q u + Q v) *: (1 : A) + polar Q u v *: (1 : A)) : A)
      { (right_distributive (Q u + Q v) (polar Q u v) (1 : A)) }
    == (((Q u *: (1 : A) + Q v *: (1 : A)) + polar Q u v *: (1 : A)) : A)
      { (right_distributive (Q u) (Q v) (1 : A)) }.
Qed.

Read it step by step. apply (cancel_l …) is the “cancel from both sides” move — this post’s own first theorem, already earning reuse — and it leaves exactly the four-line chain above as the goal, one transitivity per line. contract_add closes the first line: it contracts both squares and collects the cross terms (itself a calc chain through add_rotate and mul_add_expand, the abelian-group and ring inventories at work). polar_recovers is the definition of the cross term read as (Q u + Q v) + polar Q u v == Q (u + v), used backwards; it is wrapped in ScaleLaws.scale_proper because the replacement happens inside a *: 1, and that is the field saying scaling respects ==. The last two steps are the same distributive law twice, splitting (x+y)*:1(x+y) \mathbin{*:} 1 into x*:1+y*:1x \mathbin{*:} 1 + y \mathbin{*:} 1; the second is wrapped in Magma.op_proper because it rewrites only the left summand of a sum. One axiom in the interface, four steps in the theory file, true in every model anyone ever builds.
